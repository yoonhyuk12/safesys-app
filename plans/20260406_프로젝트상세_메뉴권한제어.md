# 프로젝트 상세 페이지 메뉴 버튼 역할 기반 권한 제어

## 날짜
2026-04-06

## 배경
프로젝트 상세 페이지(`/project/[id]`)의 점점점(⋯) 메뉴에 수정, 인계, 공유, 삭제 버튼이 **모든 역할**에게 노출되고 있음. 시공사 계정으로 로그인해도 삭제 버튼이 보이는 문제가 확인됨.

현재 `handleDelete()`에서 `발주청`이 아닌 경우 alert로 차단하고 있지만, 버튼 자체가 보이는 것은 UX상 부적절함.

## 현재 코드 분석

### 파일: `safesys-app/src/app/project/[id]/page.tsx`

**메뉴 구조 (line 481~507)**:
```
점점점 메뉴
├── 수정 (handleEdit) — 항상 노출
├── 인계 (handleHandover) — 항상 노출
├── 공유 (handleShare) — 항상 노출
└── 삭제 (handleDelete) — 항상 노출 (클릭 시 role 체크)
```

**기존 권한 함수들**:
- `canDelete()` (line 340): `project.created_by === user.id` — UI에서 미사용
- `canShare()` (line 345): `project.created_by === user.id` — UI에서 미사용
- `handleDelete()` (line 195): `role !== '발주청'`이면 alert 후 return

**역할 체계**:
| 역할 | 설명 |
|------|------|
| 발주청 | 클라이언트 — 전사 관리 권한 |
| 감리단 | 감독 — 소속 지사 데이터만 |
| 시공사 | 계약업체 — 소속 지사 데이터만 |

## 구현 계획

### Phase 1: 메뉴 버튼 역할별 표시/숨김

**변경 파일**: `safesys-app/src/app/project/[id]/page.tsx`

#### 1-1. 권한 함수 정리

기존 `canDelete()`, `canShare()` 함수를 활용하고, 삭제 권한 로직을 통일:

```typescript
// 삭제 가능 여부: 발주청만 가능
const canDelete = () => {
  return user && project && userProfile?.role === '발주청'
}

// 수정 가능 여부: 프로젝트 생성자 또는 발주청
const canEdit = () => {
  if (!user || !project) return false
  if (userProfile?.role === '발주청') return true
  return project.created_by === user.id
}

// 인계 가능 여부: 프로젝트 생성자만
const canHandover = () => {
  return user && project && project.created_by === user.id
}

// 공유 가능 여부: 프로젝트 생성자만
const canShare = () => {
  return user && project && project.created_by === user.id
}
```

#### 1-2. 메뉴 UI에 조건부 렌더링 적용

```tsx
{isMenuOpen && (
  <div className="absolute right-0 mt-1 bg-white border ...">
    {canEdit() && (
      <button onClick={handleEdit}>수정</button>
    )}
    {canHandover() && (
      <button onClick={handleHandover}>인계</button>
    )}
    {canShare() && (
      <button onClick={handleShare}>공유</button>
    )}
    {canDelete() && (
      <button onClick={handleDelete}>삭제</button>
    )}
  </div>
)}
```

#### 1-3. 메뉴 버튼(⋯) 자체도 조건부 렌더링

모든 메뉴 항목이 숨겨진 경우, 점점점 버튼 자체도 숨김:

```tsx
const hasAnyMenuAction = canEdit() || canHandover() || canShare() || canDelete()

{hasAnyMenuAction && (
  <div className="absolute top-4 right-4" ref={menuRef}>
    <button onClick={() => setIsMenuOpen(!isMenuOpen)}>
      <MoreVertical />
    </button>
    {/* 드롭다운 메뉴 */}
  </div>
)}
```

#### 1-4. handleDelete()에서 중복 role 체크 제거

버튼 자체가 `canDelete()`로 숨겨지므로, `handleDelete()` 내부의 role 체크는 **보안 방어 목적으로 유지**하되 alert 메시지는 제거 가능.

### Phase 2: 역할별 메뉴 표시 매트릭스

구현 후 최종 동작:

| 메뉴 항목 | 발주청 | 감리단 (생성자) | 감리단 (비생성자) | 시공사 (생성자) | 시공사 (비생성자) |
|-----------|--------|----------------|------------------|----------------|------------------|
| 수정 | ✅ | ✅ | ❌ | ✅ | ❌ |
| 인계 | ❌* | ✅ | ❌ | ✅ | ❌ |
| 공유 | ❌* | ✅ | ❌ | ✅ | ❌ |
| 삭제 | ✅ | ❌ | ❌ | ❌ | ❌ |
| ⋯ 버튼 | ✅ | ✅ | ❌ | ✅ | ❌ |

> *발주청은 프로젝트 생성자가 아닌 경우가 대부분이므로 인계/공유 불가

## 변경 영향 범위

- **변경 파일 1개**: `safesys-app/src/app/project/[id]/page.tsx`
- **신규 파일 없음**
- **DB 변경 없음**
- **API 변경 없음**
- 기존 `handleDelete()` 내부 방어 로직은 그대로 유지 (이중 안전장치)

## 검증 방법

1. **발주청 계정** 로그인 → 수정/삭제 버튼 보임, 인계/공유는 본인 생성 프로젝트만
2. **시공사 계정** 로그인 → 본인이 만든 프로젝트: 수정/인계/공유 보임, 삭제 안 보임
3. **시공사 계정** 로그인 → 공유받은 프로젝트: 점점점 메뉴 자체 안 보임
4. **감리단 계정** 로그인 → 시공사와 동일한 동작 확인
