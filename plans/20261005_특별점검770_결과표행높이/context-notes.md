# 결과표 행 높이 검증 결과

최종 행 높이는 1700 → 2500 HWPUNIT이며 헤더 높이는 그대로다. 표 선언 높이는 21695 → 30495다. 소스 상수·관련 주석과 기존 테스트 높이 기대값만 변경했다.

| 표본 | 기준/최종 쪽 수 | 기준 표 하단 | 최종 표 하단 |
|---|---|---|---|
| 굴착기 1대·지적 1건 | 3/3 | 649.33pt | 737.31pt |
| 굴착기 1대·지적 없음 | 3/3 | 649.33pt | 737.31pt |
| 기존 2대·지적 6건 | 9/9 | 668.15pt | 748.10pt |

2700은 다중 지적 결과표를 다음 쪽으로 밀어 10쪽이 되어 제외했다. 2500은 제목·현황표·결과표를 한 쪽에 유지하며 1대 표본의 아래 여백을 약 67.6mm에서 36.6mm로 줄인다. 임의 장문의 동적 페이지 분할은 범위 밖이다.

숨긴 한글 2022 COM에서 모든 Open(HWPX)·SaveAs(PDF) 성공, 사용자 프로세스 종료 없음. 9개 PDF 모든 쪽 contact sheet와 최종 결과표 확대 PNG를 육안 확인했다. 기준과 최종 모든 쪽 텍스트가 동일하고 결과표 외 점검표·사진대지의 PDF 벡터 도형 경계가 전부 일치한다. 사진은 기존 테스트의 합성 PNG이며 미등록 사진 칸은 의도한 빈칸이다. 사진 페이지 렌더 픽셀 완전 동일 검사는 불일치가 있어 주장하지 않으며 육안 배치와 도형 경계로 보존을 확인했다.

npm run lint 종료 0(기존 경고), npx tsc --noEmit 종료 0, npm run test:special-770 39/39 통과. RED는 기존 1700에서 새 2500 기대값 실패를 확인했다. 빌드·커밋·스테이징 없음.

산출물 루트는 safesys-app/test-files/770-row-height/다. height-1700은 기준, height-2500은 최종, height-2700은 탈락 후보이며 각각 single/clean/multiple.hwpx 및 .pdf, *-page-N.png, *.contact.png가 있다. 대표 최종 이미지는 height-2500/single-page-2.png 및 multiple-page-3.png다. measurements.json은 쪽별 실측, scoped.diff는 작업 전 임시 백업 대비 변경이다. generate.mjs·convert.ps1·render.py로 재현할 수 있다.
