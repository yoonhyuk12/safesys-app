# 폭염 점검 카드 3단계 드릴다운 (본부별 → 지사별 → 프로젝트)

2026-07-31. 사용자 피드백: /safe/heatwave 진입 시 바로 프로젝트 테이블이 나온다. 다른 안전카드(TBM 등)처럼 본부별 집계 → 지사별 집계 → 프로젝트 테이블로 드릴다운되게 한다. 구현은 Codex 워커에게 Orca 오케스트레이션으로 위임.

## 현황 분석

- `SafetyHeatwaveView.tsx`는 `heatWaveChecks`를 평평한 프로젝트 테이블로만 렌더.
- 참조 구현은 `SafetyTBMView.tsx` — 렌더 분기 3단계.
  - `selectedSafetyBranch` 있음 → 프로젝트 테이블 (705행~)
  - `selectedSafetyHq`만 있음 → 지사별 집계 (869행~)
  - 둘 다 없음 → 본부별 집계 (982행~)
- Dashboard의 TBM wiring(3384-3434행)이 콜백 패턴 원본. `onSelectSafetyHq`는 상태만 변경(URL 무변화), `onSelectSafetyBranch`는 `/safe/branch/<지사>/heatwave`로 push — 이 라우트는 이미 존재(Dashboard 래퍼).
- `HeatWaveCheck` 타입에 `managing_hq`·`managing_branch`가 이미 있어 클라이언트 집계 가능 (`lib/projects.ts:127`).
- 지사 소속 사용자는 Dashboard 792행에서 `selectedSafetyBranch` 자동 세팅 → 바로 레벨3 진입(기존 동작 유지).

## 결정 사항 (컨텍스트 노트)

- 신규 라우트·파일 생성 없음. 수정 파일은 `SafetyHeatwaveView.tsx`, `Dashboard.tsx` 2개뿐.
- 본부 클릭은 TBM과 동일하게 URL 변경 없이 상태만 변경. 지사 클릭만 URL push.
- 집계 컬럼 세부(점검 건수·최고 체감온도 등)는 TBM 양식을 따르되 폭염 데이터 특성에 맞게 워커 재량. 최종 컬럼: 점검 프로젝트 수 | 점검 건수 | 최고 체감온도 | 항목 이행 현황(O개수/전체).
- 사용자 추가 요구(작업 중 수신): 폭염 현황은 일 단위 확인이 핵심 — 모든 레벨 집계는 selectedDate 하루 기준, 날짜 변경 시 전 레벨 갱신. heatWaveChecks가 원래 날짜 단위 조회라 집계도 자동으로 일 단위다.
- 본부/지사 정렬은 lib/constants의 HEADQUARTERS_OPTIONS·BRANCH_OPTIONS 순서를 따름(워커 판단, 승인).
- 사용자 2차 피드백(같은 날): 점검 없는 본부·지사·프로젝트도 목록에 나와야 함 → 행 생성을 점검 데이터가 아닌 projects 목록 기반으로 전환(TBM 방식 미러). 집계 컬럼에 "대상 프로젝트 수" 추가, 점검 없는 행은 0·'-' 표시. 프로젝트 단계는 지사 전체 프로젝트를 display_order→이름 순으로 표시하고 무점검 행 클릭도 onRowClickProject로 프로젝트 폭염 페이지 이동. 프로젝트가 하나도 없는 조직은 TBM과 동일하게 미표시.
