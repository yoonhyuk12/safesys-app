# CSI 품질검사 성적서 연동 — 컨텍스트 노트

- **키 저장 방식 결정.** 사용자가 "키 입력 자리"를 요청했으나 선택지 제시 후 **환경변수(Vercel) 방식**으로 확정.
  G2B `DATA_GO_KR_API_KEY`와 동일 패턴. UI 키 입력란은 만들지 않는다.
- **데이터 활용 방식 결정.** 조회 + 대장 행으로 가져오기(프리필). 직접 DB 삽입은 하지 않는다 —
  실시대장 저장 검증이 사진·서명·공종 등을 필수로 요구하므로, 등록 폼을 열어 프리필하고
  사용자가 나머지를 채워 저장하는 기존 '이전 기록 복사' UX와 동일한 흐름을 쓴다.
- **그룹핑 단위.** API 응답은 성적서×시험항목×결과 단위 평탄화 행. `issueNo`(성적서번호)로 묶어
  성적서 1건 = 대장 제출건(일련번호) 1건 = 시험항목 N건으로 대응시킨다.
- **연결성 실측(2026-07-16).** 더미 키로 호출 시 401 + `resultCode:"30"` 구조화 JSON 수신 — 서비스 도달 확인.
- **IP 화이트리스트 실측(2026-07-16).** 실제 키로 호출 시 "유효하지 않는 IP 주소로 API 인증을
  시도하였습니다" — **CSI는 신청기관 IP를 실제로 검증한다.** 신청 시 기재한 IP는 64.29.17.65
  (krcsafesys.com 인바운드)라 로컬 개발 PC(58.232.131.219)도, Vercel 동적 이그레스 IP도 차단됨.
  → 로컬 개발: CSI 'API 인증키 정보'에서 신청기관 IP를 개발 PC 공인 IP로 수정/추가 필요.
  → 운영(Vercel): 고정 이그레스 IP가 없어 근본 해결 필요 — CSI에 IP 검증 예외·대역 등록 문의
  (1588-8788 / csi@kalis.or.kr) 또는 고정 IP 프록시(QuotaGuard 등) 경유. 미해결 과제.
- **IP 일치 재신청 후에도 실패(2026-07-16~17 실측).** 기관 IP를 개발 PC 공인 IP(58.232.131.219)로
  새로 신청·자동승인(23:02, 키 249E7AFB...)했고 발신 IP 일치·IPv6 아님·IPv4 강제까지 확인했으나,
  승인 +0분/+10분/+58분/익일 재시도 모두 "유효하지 않는 IP 주소" 동일 오류.
  → 클라이언트 측 원인 소진. **CSI 기술지원 문의 필요** — 게이트웨이 로그의 실제 수신 IP와
  화이트리스트 반영 상태 확인 요청. `.env.local` 키는 249E... 키로 교체 완료.
- **성적서 발급일자 기준 조회.** 필수 파라미터가 발급일자 범위라 기본값 최근 3개월로 설정.
  1회 최대 100건 제한 — 초과 시 기간을 좁히라는 안내만 표시(페이지네이션 비범위).
- **schInstType 미전송.** 기본값 R(의뢰기관/시공사 기준). 발주기관 키로 조회 결과가 비면
  Q(대행기관) 전환이나 파라미터 노출을 재검토한다.
- **주의.** 기술문서 PDF가 `safesys-app/public/`에 있어 배포 시 공개 경로로 노출된다.
  비밀정보는 없으나 이동 여부는 사용자 판단 대기. → 이후 `docs/`로 이동됨(확인).

## 2026-07-20 — 조회 0건 원인 규명 (실측)

**결론. 인증·파라미터는 정상이고 데이터만 0건이다. 코드 문제가 아니라 계정 데이터 범위 문제다.**

대조군으로 원인을 분리했다.
- 더미 키 → `401 / resultCode 30`(인증 실패). 필수 날짜 누락 → `400 / resultCode 10`(필드별 사유).
- 실제 키 + 정상 파라미터 → 항상 `204 / resultCode 22`("요청하신 데이터가 존재하지 않습니다").
→ 키 유효·IP 화이트리스트 통과·파라미터명 인식 모두 정상임이 확정됐다.

0건이 나온 조건(전부).
- 공사명 비움(기관 전체), 2021~2026 5년 범위, 연도별·월별 세분화
- `schInstType` 미전송 / R / Q / O / C
- `schCompanyNm` = `(주)신성건설` / `신성건설` (R·Q 양쪽)
- `schConstNm` = 정식 전체 공사명 / `점동지구` / `다목적 농촌용수`

**필터로는 해결 불가 — 논리적으로 확정.** 필터를 모두 비운 기관 전체 조회가 이미 0건이므로
공사명·시공사명 추가는 결과를 늘릴 수 없고 좁히기만 한다.

**응답 시간이 스코프를 드러낸다.** Q(대행기관) 조회는 0~4초에 즉시 빈 응답(해당 스코프 자체가 없음),
R(의뢰기관) 조회는 20~27초간 실제 검색 후 0건. 즉 검색은 수행되나 키 기관 소유 성적서가 없다.

**구조적 원인.** 기술문서상 `schInstType`은 **R:의뢰기관(시공사) / Q:품질검사 대행기관** 둘뿐이다.
이 API는 키 등록기관이 시공사이거나 품질검사 대행기관일 때만 데이터를 준다.
발주청·감리 성격 기관 키로는 어느 쪽에도 걸리지 않아 구조적으로 0건이다.
→ 실데이터를 보려면 시공사 명의 키를 쓰거나, CSI에 발주청·감리 기관의 조회 가능 여부를 문의해야 한다.

**부수 수정(커밋 99429a4).** `resultCode 22`를 502 오류로 오분류하던 것을 빈 성공 결과로 변경.
모달의 "조회된 성적서가 없습니다" 빈 상태가 표시되지 않아 데이터 없음과 장애가 구분 불가였다.

**데이터는 CSI에 실재한다(2026-07-20 사용자 확인).** 사용자가 로그인 상태에서
`https://gcloud.csi.go.kr/cmq/qti/qltRptReadng/qltRptReadngList.do`(품질검사 성적서 열람)로
해당 성적서를 직접 조회했다 — 시공자 (주)신성건설 / 점동지구다목적농촌용수개발사업토목공사 / 2025-11-25.
그 정확한 조건(정확일자·공백없는 공사명·해당 월 전체·필터 없음)으로 API를 호출해도 전부 `resultCode 22`.

→ **웹 열람 권한 ≠ API 조회 스코프.** API의 조회 기준은 R(의뢰기관=시공사)·Q(품질검사 대행기관)뿐이라,
발주청·감리 기관은 웹에서는 관할 공사 성적서를 볼 수 있어도 API에는 대응 스코프가 없다.
키가 시공사·대행기관 명의가 아니면 구조적으로 0건이다.

**호스트 확인.** `api.csi.go.kr`이 현행이다(인증·파라미터 검증 정상 동작). 웹 화면만
`gcloud.csi.go.kr`로 이전됐고(www→gcloud 301) API 주소 변경 공지는 없다.
`gcloud.csi.go.kr`의 `/api/service/...`·`/openapi/...`는 404 — 새 API 호스트는 존재하지 않는 것으로 보인다.

**다음 확인 사항(사용자·CSI 측에서만 가능).**
1. CSI 마이페이지 > API 인증키 정보에서 **키를 어느 기관 명의로 신청했는지**.
2. 성적서 열람 화면의 **의뢰기관**이 (주)신성건설인지, 표시된 2025-11-25가 **발급일자**인지.
3. CSI(1588-8788 내선 2/7)에 발주청·감리 기관 키로 관할 공사 성적서를 API 조회할 수 있는지 문의.

**미해결.** `CSI_API_KEY`가 Vercel production/preview에 미등록(`vercel env ls` 확인) — 운영에선 500.
