# 프로젝트 사고보고 구현 계획

**목표.** 각 프로젝트 안전캐비넷의 A(조치)에 사고보고 서류철을 추가한다.

**구조.** 기존 `project_accidents`, 사고 입력 모달 및 CRUD를 재사용한다. 프로젝트 전용 목록/상세 화면은 현재 프로젝트만 조회하고 입력 프로젝트를 고정한다. 같은 데이터를 사용하는 안전대시보드 집계를 유지한다.

**범위.** `safesys-app/src/app/project/[id]/page.tsx`, 신규 `accident-report/page.tsx`, `src/components/dashboard/AccidentEntryModal.tsx`, `src/lib/accident-analysis.ts` 및 관련 테스트와 문서.

1. 프로젝트 고정 입력/조회와 기존 모달 회귀를 검증하는 테스트를 먼저 작성하고 실패를 확인한다.
2. 안전캐비넷 A에 `DocumentFolder`를 추가하고 `/project/${projectId}/accident-report`로 연결한다.
3. 프로젝트별 사고 조회 함수를 추가한다. 목록은 최신순이며 다른 프로젝트와 미등록 현장 사고를 포함하지 않는다. 오류를 빈 목록으로 숨기지 않는다.
4. 기존 모달에 선택적 고정 프로젝트 입력을 추가한다. 고정 모드에서는 프로젝트 변경 및 미등록 현장 입력을 차단한다. 기존 대시보드의 일반 모드는 유지한다.
5. 업무형 화면에 목록, 상세, 입력/수정, 삭제 확인을 구현한다. 기존 중대도·피해·원인·예방조치 필드를 모두 보존한다. 세션 복원 전 로그인 리다이렉트를 하지 않는다.
6. 권한은 현장 작성으로 확정했다(2026-09-16 사용자 응답). 등록은 그 현장을 열 수 있는 로그인 사용자 전원이며, 수정·삭제는 본인 작성 건이거나 본부급 이상 관할일 때만 허용한다. 미등록 현장 사고는 기존 본부급 정책 그대로 둔다. DB 정책·SQL 회귀 테스트는 별도 작업이 맡는다.
7. 관련 테스트, 린트, 타입체크 및 독립 리뷰를 수행한다. 프로덕션 빌드/배포 없이 검증된 변경을 커밋한다.

**검증 시나리오.** 프로젝트 간 조회 격리, 고정 입력 프로젝트 유지, 기존 모달의 미등록 현장 모드 유지, 조회/저장 실패 표시, 작성권한 없는 사용자의 변경 차단, 기존 사고 집계 테스트 통과.

**제약.** 새 테이블·파일 출력·서명·첨부는 요구하지 않았으므로 추가하지 않는다. 디자인 시스템을 따르고 무관한 코드는 수정하지 않는다.
