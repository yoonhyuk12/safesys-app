# 품질시험 결과 관리대장 기능 계획

작성일: 2026-07-02
근거 양식 (PDF 원본 3종)

1. 품질검사 성과 총괄표 — 별지 2호 (지침 제14조 1항 관련)
2. 품질검사 실시대장 — 건설기술 진흥법 시행규칙 별지 제42호서식 (개정 2024. 7. 10.)
3. 확인시험 의뢰서 — 公社시험업무지침 별지 제4호서식 (지침 제17조, 제18조 관련)

## 목표

프로젝트 상세 페이지의 **품질 캐비넷**에 "품질시험 결과 관리대장" 서류철 1개를 추가하고, 위 3종 양식의 작성·조회·엑셀 출력 기능을 탭으로 묶어 구현한다.

## 양식 분석

### 1) 품질검사 실시대장 (별지 제42호서식) — 핵심 원장

행 단위 기록. 열 구성.

- 일련번호 / 연월일 / 시험·검사구분 / 품질검사 대상 재료 / 건설자재·부재를 공급받은 공장 / 시험·검사 장소 / 시험·검사 종목 / 시험 기준 / 시험 결과 / 시험 결과 판정 / 품질관리기술인(성명·서명) / 건설사업관리기술인 확인(성명·서명) / 비고

### 2) 품질검사 성과 총괄표 (별지 2호) — 집계 보고서

- 헤더: 공사명, 공사기간, 공정(%)
- ③ 기성 또는 정산량: 공종 / 연도 계획량(㎥) / 전회까지 시공량 / 금회 시공량 / 누계 / 비고
- ④ 품질검사 종류 및 실적: 공종 / 시험·검사 종류(재료) / 횟수(계획·실시·합격·불합격·재시험) / 비고
- ⑤ 확인시험 종류 및 실적: ④와 동일 + 확인시험구분 열
- 작성일시 + 작성자(건설업자)·검토자(품질시험업무담당자)·확인자(감독소장) — 각 소속/직위/성명/(인)

### 3) 확인시험 의뢰서 (별지 제4호서식) — 단건 문서

- 의뢰번호, 의뢰일자, 받음, 보냄(인 또는 서명), 참조
- 공사명 / 발주자 / 시공자 / 대상공종·물량 / 확인시험 항목 / 확인시험예정일 / 시험목적 / 기타사항

## 설계 결정

1. **서류철 위치**: 품질 캐비넷에 `C (점검)` 그룹을 신설하고 배치. 시공 캐비넷의 검사/검측 대장이 C(점검)에 있는 것과 동일한 분류 논리 (기존 월례보고서 계획서와도 일치). `pdcaCategory="C"`, `bottomLabel="품질"`, docCount는 실시대장 건수.
2. **라우트**: `/project/[id]/quality-test-ledger` — 상단 탭 3개 (실시대장 / 성과총괄표 / 확인시험 의뢰서). 각 탭은 독립 컴포넌트로 분리해 파일 크기를 제한한다.
3. **데이터 모델** (3개 테이블, 모두 `project_id UUID REFERENCES projects(id) ON DELETE CASCADE` + RLS)
   - `quality_test_records` — 실시대장 1행 = 1레코드. 일련번호는 저장하지 않고 (시험일, 생성일) 순 정렬로 표시·출력 시 부여. 총괄표 자동집계를 위해 `work_type`(공종) 필드를 둔다 (양식엔 없지만 집계 필수). 서명은 base64 TEXT (DB행과 함께 cascade 삭제 — Storage 수집 불필요).
   - `quality_verification_requests` — 확인시험 의뢰서 1건 = 1레코드.
   - `quality_summary_reports` — 총괄표 1건 = 1레코드. 표 행들은 JSONB 배열(`settlement_rows`, `quality_rows`, `verification_rows`), 누계(전회+금회)는 저장하지 않고 계산. 서명자 3인은 평면 컬럼(소속/직위/성명/서명 × 3).
   - RLS는 `inspection_requests`와 동일 패턴: SELECT는 전체 허용, INSERT/UPDATE/DELETE는 `auth.uid() = created_by`.
4. **자동화 포인트**
   - 총괄표 "실적 자동집계" 버튼: 실시대장 레코드를 (공종, 시험·검사 종목) 기준으로 그룹핑해 실시/합격/불합격/재시험 횟수를 채움. `시험·검사구분 = '확인시험'`인 레코드는 ⑤ 확인시험 실적으로, 나머지는 ④ 품질검사 실적으로 분류. 계획 횟수·기성량은 수동 입력.
   - 확인시험 의뢰서: 공사명(프로젝트명)·시공자(프로젝트 소유자 회사명) 프리필, 의뢰번호는 `지구명의뢰-순번` 자동 제안 (검측요청서와 동일 규칙).
   - 실시대장 판정은 합격/불합격/재시험 선택형.
5. **출력**: 3종 모두 ExcelJS 엑셀 출력 (검사/검측 대장과 동일 패턴 — setCell/mergeSet/서명이미지 삽입 유틸 재사용 구조).
   - 실시대장: A4 가로, 전체 목록 1시트.
   - 총괄표: A4 세로, 1건 1시트.
   - 확인시험 의뢰서: A4 세로, 1건 1시트.
6. **권한**: 기존 서류철과 동일 — 프로젝트 접근 가능자 모두 사용, 수정·삭제는 작성자 본인만 (RLS + UI 안내).

## 추가 기능 (2026-07-02 페이지 피드백 반영)

1. **일련번호 표시**: 실시대장 작성/수정 폼 공통 항목 그리드에 읽기 전용 "일련번호" 필드 추가 (신규 등록 시 다음 번호 미리보기, 수정 시 해당 번호 표시).
2. **일련번호별 사진 첨부**: 참고 양식(품질검사 사진대지, 공사명·일련번호·타설(시공)일자·시험일자 + 사진 1장 레이아웃)에 맞춰 `quality_test_records`에 `photo_url` 컬럼 추가. 일련번호(제출건) 1건당 사진 1장 업로드 — 공통 항목 그리드에 배치, 같은 제출건의 여러 시험 항목 행에는 동일 URL이 공통 필드처럼 중복 저장됨. Storage 버킷 `quality-test-photos` 사용 (서명과 달리 사진은 용량이 커서 base64 대신 URL 컬럼 방식, 기존 heat_wave_checks 등과 동일 관례).
3. **사진대지 PDF 출력**: 사진이 첨부된 항목만 모아 A4 세로 PDF로 출력 (jsPDF+html2canvas, 페이지당 2건). 타설(시공)일자는 현재 데이터 모델에 없어 공란으로 출력(사용자 확인 완료 — 최소 구현 우선).

## 구현 단계

1. `database/add_quality_test_ledger_tables.sql` 작성 → Supabase MCP `apply_migration` 적용 (실패 시 콘솔 실행 안내)
2. `src/lib/quality/quality-test-types.ts` — 타입·빈 값 생성자·집계 함수
3. 엑셀 출력 3종 — `src/lib/excel/quality-test-ledger-export.ts`(실시대장), `quality-summary-export.ts`(총괄표), `quality-verification-request-export.ts`(의뢰서)
4. 탭 컴포넌트 3종 — `src/components/project/quality/QualityTestRecordsTab.tsx`, `QualitySummaryTab.tsx`, `QualityVerificationRequestsTab.tsx`
5. 페이지 `src/app/project/[id]/quality-test-ledger/page.tsx` — 헤더 + 탭 전환 + 프로젝트 로드
6. 품질 캐비넷 C(점검) 그룹 신설 + 서류철 추가 (`project/[id]/page.tsx`)
7. lint + 수동 검증 → 시맨틱 커밋

## 추가 피드백 계획 (2026-07-15 감독 서명 분리)

1. 건설사업관리기술인 이름·서명 입력과 필수 검증을 실시대장 등록·수정 폼에서 제거한다.
2. 발주청 사용자에게만 HWP 양식 오른쪽의 `감독서명` 버튼을 표시한다.
3. 감독 서명 모드에서 미서명 목록 행을 개별 또는 전체 선택하고 공용 일괄서명 API로 저장한다.
4. 기존 서명은 선택·덮어쓰기를 막고, 신규·이전 기록 복사 시 감독 서명을 승계하지 않는다.
5. 타입 검사·린트·로컬 경로 응답과 실제 선택 모달 진입을 검증한다.

## 추가 피드백 계획 (2026-07-15 감독 서명 대체)

1. 감독 서명 모드에서 미서명 여부와 관계없이 실시대장 전체 행을 개별 또는 전체 선택할 수 있게 한다.
2. 이미 감독 서명된 행을 선택해 저장하면 기존 서명을 새 서명으로 대체한다.
3. 화면 요청은 `replace_existing=true`를 명시하고, 서버의 덮어쓰기 허용 범위는 레지스트리에서 허용한 `signer=supervisor`의 `quality_test_record` 대상으로만 제한한다.
4. 다른 일괄서명 대상의 기존 서명 보호 로직은 그대로 유지한다.
5. 타입 검사·대상 린트·diff 검사를 실행한다.
