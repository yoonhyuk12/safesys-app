# 기상특보 JSON 응답 수정 컨텍스트

- 실측한 `disp=1` 응답은 HTTP 200 JSON 배열 19건이며 모두 해상 특보다. 기존 파서 결과는 sourceRows=0이다. 경계 서비스 두 곳은 정상이다.
- 서버 GET과 POST 모두 `기상청 특보 응답에 유효한 데이터가 없습니다.`로 502를 기록한다.
- 기상청 공식 명세의 필드 REG_UP, REG_UP_KO, REG_ID, REG_KO, TM_FC, TM_EF, WRN, LVL, CMD와 실측 ED_TM을 사용한다. https://apihub.kma.go.kr/apiList.do?seqApi=10
- GitHub 코드 검색으로 동일 endpoint 사용례를 확인했다. 이번 변경은 기존 파서에 JSON.parse와 필드 매핑을 추가하는 범위이므로 새 패키지는 필요 없다.
- feature-workflow가 참조하는 superpowers 스킬과 Opus 전용 에이전트는 세션에서 제공되지 않는다. 사용 가능한 작업 에이전트와 직접 검토로 계획·TDD·리뷰 절차를 수행한다.
- 빈 JSON 배열은 정상 0건으로 처리하되 오류 객체·HTML·손상 JSON·유효하지 않은 비어 있지 않은 배열은 실패시킨다.
- 과거 실응답도 확인했다. `tm=202608201200`은 139건, `tm=202609040900`은 47건이며 LVL은 공백이 붙은 `경보`와 `주의`다. 기존 특보 수준 변환을 유지할 수 있다.
- 사용자 지정 브라우저 탭이 후속 수정 시점에 사라져 Orca의 동일 워크스페이스에 `/map` 검증 탭을 생성했다.

## 결과

- JSON 필드 배열을 직접 정규화하여 CSV와 공통 병합 로직으로 전달한다. ED_TM의 쉼표와 문구는 보존한다. 정상 빈 배열만 0건을 허용하며 라우트의 일괄 0행 오류 판정을 제거했다.
- 회귀 테스트 6개 중 기존 코드에서 5개 실패, 수정 후 6개 모두 통과. 쉼표가 많은 HTML이 CSV로 오인되는 사례도 실패 재현 후 차단했다. Advisor가 diff와 테스트 실행 결과를 직접 확인했다.
- `npm run lint` 종료 코드 0(기존 경고 있음), `npx tsc --noEmit` 종료 코드 0, `git diff --check` 통과.
- V8 precise coverage로 새 `readKmaWarningFields` 함수 범위 11개 중 11개 실행을 확인했다. 100%는 해당 함수의 V8 실행 범위 기준이며 프로젝트 전체 커버리지 수치가 아니다.
- 실제 현재 데이터 19행→sourceRows 19·육상 0, 과거 데이터 47행→육상 26·지역 22, 139행→육상 139·지역 113. 과거 두 사례 모두 주의보·경보 정상 변환.
- 로컬 지도 GET·위치 GET·일괄 POST 모두 HTTP 200. 브라우저 `/map` 버튼 `기상특보 (0개)`, 메뉴 `현재 발효 중인 특보가 없습니다.`를 확인했다.
- 코드 검토에서 요청과 무관한 UI·인증키·경계 서비스 변경이 없음을 확인했다. 배포·프로덕션 빌드는 실행하지 않았다.
