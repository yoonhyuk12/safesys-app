# 품질시험 월례보고서 — 컨텍스트 노트

계획서: `plans/20260702_품질시험월례보고서.md`

## 2026-07-02

- 사용자가 원본 PDF(`3-3. 품질시험 월례보고서.pdf`)를 제공하고 품질 캐비넷에 서류철 추가 + 기능 구현을 요청. "허락 맞지 말고 진행" 지시로 설계 결정을 에이전트가 단독 수행.
- **서류철 분류 = C(점검)**: 월례 "실적 보고" 성격이므로 PDCA상 점검 문서로 판단. 시공 캐비넷의 검사/검측대장(C)과 동일 논리. 품질 캐비넷에 C 그룹이 없어 신설.
- **rows JSONB 단일 테이블**: 행 수가 가변(공종×시험항목)이고 행 단위 조회·집계 요구가 없어 정규화(별도 rows 테이블) 대신 JSONB 채택. 단순성 우선.
- **파생값 비저장**: 계(①+②), 확인시험 소계, 시공잔량은 입력값에서 항상 계산 가능하므로 저장하지 않음 — 불일치 원천 차단.
- **누계 자동 제안**: 직전 월 보고서의 누계 + 이번 달 입력값으로 자동 계산하되 수정 가능하게. 시스템 도입 전 데이터가 없는 프로젝트는 첫 달에 누계를 직접 입력해야 하기 때문.
- **누계 데이터 모델 확정**: 행에 "전월까지 누계"(prevCumul*)를 명시적 입력 필드로 저장하고, 화면·PDF의 누계 = 전월누계 + 이번달 입력으로 항상 계산. 숨은 상태 없이 투명하고, 첫 달 수동 입력도 자연스럽게 지원.
- **입력값은 TEXT**: 시공물량에 단위("1,200㎥")가 붙을 수 있어 자유 텍스트로 받고, `parseNum()`이 앞쪽 숫자만 추출해 계산. 숫자가 전혀 없으면 파생값은 빈 칸.
- **RLS는 work_daily_reports 패턴**: 조회 전체 허용, 등록 본인, 수정/삭제 로그인 사용자 — 작성자(시공사)·확인자(감독) 공동 작성 워크플로우 지원.
- **MCP 마이그레이션 차단**: `apply_migration`이 auto mode 권한 분류기에서 거부됨(프로덕션 DDL). CLAUDE.md 방침대로 `database/add_quality_monthly_reports_table.sql`을 사용자가 Supabase 웹 콘솔에서 직접 실행해야 기능이 동작한다. 테이블 없이도 앱은 깨지지 않음(건수 미표시, 목록 빈 화면, 저장 시 오류 알림).
- **`rows` 컬럼명 회피**: PostgreSQL 예약어 충돌 가능성이 있어 `report_rows`로 명명.
- **커밋은 로컬만**: main 푸시 = Vercel 자동 배포라서, 마이그레이션 미적용 상태로 푸시하지 않음. 코드 자체는 테이블 부재에 안전하지만 사용자 판단에 맡김.
- **HWP 양식 버튼**: 보고서 페이지 헤더 우측에 구글 드라이브 직접 다운로드 링크(`uc?export=download`) 추가 — 신규근로자 둘러보기 페이지의 기존 패턴 재사용.
- **사업현황(/business) 제출현황 카드**: 기존 카드(자급자재·검사/검측)는 지사→프로젝트 2단이지만, 사용자가 "본부별 > 지사별"을 명시해 본부→지사→프로젝트 3단 드릴다운으로 구현(`BusinessQualityReportView`). "제출" 판정 = 해당 월 `quality_monthly_reports` 행 존재. 이번 달 기준 제출/미제출 집계이며, 데이터 로딩은 발주청 + business 뷰 게이팅(기존 검사/검측 useEffect 패턴 복제).
