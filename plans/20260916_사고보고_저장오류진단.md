# 사고보고 저장 오류 진단

실제 저장 실패의 원인은 미확정이다. 부모의 읽기 전용 확인에서 `report_details` 컬럼과 예상 일수 14의 검증함수 통과를 확인했으므로 SQL 누락으로 단정하지 않는다.

공통 오류 분류기를 추가해 create/update 응답 오류와 예외를 안전한 한국어 문구·코드로 변환한다. 네트워크, 권한 42501, CHECK 23514, 컬럼 42703/PGRST204, FK 23503을 구분한다. 보고서 CHECK와 작성자 FK는 알려진 제약 이름만 식별하고 원문 message/details/hint는 출력하지 않는다. 알 수 없는 코드는 일반 안내로 처리하며 코드 형식이 안전하지 않으면 UNKNOWN으로 대체한다.

입력 객체·사진·보고서 내용을 변경하지 않고 요청은 한 번만 보낸다. 통신 오류는 저장 성공 여부가 불확실하므로 목록 확인을 먼저 안내한다. 필드를 버리는 재시도, 권한·RLS 변경, 원격 SQL은 범위 밖이다.

1. 기존 오류 분기와 Supabase/PostgREST 오류 형태를 확인하고 실패 회귀를 추가한다.
2. `accident-mutation-error.ts`와 create/update 네 오류 분기에 적용한다.
3. 분류·개인정보 비노출·단일 요청·입력 보존 회귀, tsc, 대상 lint를 검증한다.

참고한 1차 문서는 [PostgREST 오류 구조와 코드](https://docs.postgrest.org/en/stable/references/errors.html)다. 문서상 details에는 실패 행이 포함될 수 있어 로깅 대상에서 제외한다.

## 구현과 표시 정책

`src/lib/accident-mutation-error.ts`의 순수 분류기가 `{ code, message }`만 반환한다. `accident-analysis.ts`의 create/update 응답 오류·catch 네 분기에서 이 객체만 로그에 남기고 message를 기존 `AccidentMutationResult.error`에 전달한다. 등록/수정 요청과 페이로드 생성은 그대로다.

| 코드 | 안내 |
|---|---|
| NETWORK | 통신 문제로 저장 결과 미확인, 연결 확인 후 목록에서 저장 여부 먼저 확인 |
| 42501 | 로그인 상태와 프로젝트 접근 권한 확인 |
| 23514 + 보고서 CHECK 이름 | 보고서 항목·사진 입력 확인 |
| 기타 23514 | 사고 입력값과 저장 조건 확인 |
| 42703 / PGRST204 | 서버 저장 항목 확인 실패, 코드로 담당자 문의 |
| 23503 + 작성자 FK 이름 | 작성자 정보·로그인 상태 확인 |
| 기타 23503 | 연결된 프로젝트·사용자 정보 확인 |
| 기타 정상 형식 코드 | 일반 저장 실패 문구 + 해당 코드 |
| 코드 부재·잘못된 코드 | 일반 저장 실패 문구 + UNKNOWN |

PostgreSQL 5자리 또는 PGRST 8자리 대문자 영숫자 코드만 표시하며 개행·개인정보가 섞인 코드는 UNKNOWN으로 바꾼다. 통신 오류는 알려진 fetch 오류 문구와 네트워크 코드만 식별한다. 임의 TypeError를 네트워크 문제로 단정하지 않는다. 원문 details/hint는 읽지 않으며 원문 message는 알려진 오류 식별에만 사용한다.

## 검증 결과

- RED — 기존 generic 문구가 권한 안내를 내지 않아 새 통합 회귀 실패 확인.
- `node --test --test-name-pattern='사고 저장 오류' tests/project-accident-report.test.mjs` — 2 PASS. 13개 오류 형태를 create/update × 응답 오류/catch 4경로(52조합)로 검사하고 단일 요청·입력/사진 보존·안전 로그를 확인했다. details/hint getter를 읽지 않는지, 예상 밖 예외·개행 코드를 일반 처리하는지도 확인했다.
- `node --test tests/accident-report-details.test.mjs` — 기존 저장 회귀 24 PASS, 해당 파일은 변경하지 않았다.
- `npx tsc --noEmit --incremental false` — PASS.
- `npx eslint src/lib/accident-analysis.ts src/lib/accident-mutation-error.ts` — 경고·오류 없이 PASS.
- 두 테스트 파일 전체 실행은 45 PASS / 3 FAIL. 실패 3개는 병행 PDF 변경의 `pdfjs-dist/build/pdf.mjs`가 Node에서 `DOMMatrix is not defined`를 발생시킨 기존 모달 렌더 테스트다. 부모에게 전달했고 PDF 담당 파일은 수정하지 않았다.
- 작업 대상 `git diff --check` — PASS.

실제 사용자 저장 오류 코드는 아직 전달받지 못했으며 이번 구현만으로 저장 원인을 해결했다고 주장하지 않는다. 부모의 실제 오류 수집·독립 리뷰 및 PDF 테스트 로딩 문제 처리가 남는다. 빌드·커밋·푸시·원격 SQL은 실행하지 않았다.
