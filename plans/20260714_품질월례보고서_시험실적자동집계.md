# 품질시험 월례보고서 시험실적 자동집계 계획

## 목표

품질시험 실시대장의 기록을 월례보고서 시험실적 칸에 일련번호 기준으로 자동 반영한다.

## 계획

1. 실시대장 레코드를 보고 연월 이전 범위로 조회한다.
2. 공종·시험항목·시험구분별 고유 일련번호를 금월과 전월까지 누계로 나누어 집계한다.
3. 월례보고서 행과 집계 결과를 병합하고 없는 공종·시험항목 행은 자동 추가한다.
4. 자동 집계 필드는 읽기 전용으로 표시하고 집계 기준을 화면에 안내한다.
5. 타입체크와 린트로 검증한다.

## 완료 기준

- 자체시험 등 일반 시험은 `품질시험①`에 반영된다.
- `의뢰(수탁)시험`은 `전문기관`, `확인시험`은 `기타확인`에 반영된다.
- 한 일련번호에 같은 시험항목이 여러 행이어도 1건으로 집계된다.
- 보고 월 변경과 기존 보고서 수정 시에도 해당 연월 기준으로 다시 계산된다.

## 컨텍스트 노트

- 건수 단위는 DB 행 수가 아니라 `serial_no` 고유 개수다. `serial_no`가 없는 레거시 행만 레코드 ID를 대체 키로 쓴다.
- 집계 분류는 `의뢰(수탁)시험`을 전문기관, `확인시험`을 기타확인(감독시험), 그 외 시험구분을 품질시험으로 본다.
- 월 실적은 보고 연월과 같은 `test_date`, 전월까지 누계는 보고 월 1일 이전 `test_date`를 사용한다.
- 행 키는 공종과 시험항목의 공백·줄바꿈을 정규화해 비교한다.
- 기존 행의 시공계획·물량·다음월 계획은 보존하고 시험실적 필드만 실시대장 값으로 덮어쓴다.
- 월례보고서와 실시대장을 함께 조회하고, 정상 조회된 실시대장 값은 목록 PDF와 작성·수정 폼에 모두 다시 집계한다.
- 실시대장 조회가 실패하면 저장된 보고서 행을 보존하고 오류를 안내하며, 잘못된 자동값이 저장되지 않도록 저장 버튼과 저장 처리를 막는다.
- 자동 추가 행은 실시대장 최초 등장 순서를 따르고 공종·시험항목의 공백을 정규화한 값을 표시한다.
- 자동집계로 채워진 행이 하나라도 있으면 초기 선두 빈 행만 제거하고, 집계 결과가 없으면 수기 입력을 위해 빈 행 하나를 유지한다.
- `npx tsc --noEmit`과 `npm run lint`는 종료 코드 0으로 통과했고, 이번 변경 파일에서 새 린트 경고는 발생하지 않았다.
- 다른 작업이 수정 중인 `checklist.md`, `context-notes.md`와 품질 관련 기존 파일은 요청 범위 밖에서 건드리지 않는다.
