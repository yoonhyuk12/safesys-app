# 비밀번호 찾기 — Edge Function을 Next.js API 라우트로 전환

## 배경 (2026-07-15)

로그인 화면 "비밀번호 찾기" 모달의 비밀번호 변경이 400으로 실패.

진단 결과 (근본 원인 확정).
1. Supabase Edge Function `update-user-password`에 자동 주입되는 `SUPABASE_SERVICE_ROLE_KEY`가 레거시 JWT 키인데, 2026-07-13 키 회전 때 레거시 JWT를 비활성화하면서 함수 내부 admin 클라이언트가 죽음. `getUserById`가 항상 실패 → 함수가 에러를 삼키고 "User not found" 400 반환.
   - 판별 증거. 실존 userId + 틀린 email 호출 시 'Email mismatch'가 아니라 'User not found' → 이메일 비교 단계(getUserById 성공 후)에 도달 못함.
2. 클라이언트 fallback은 존재하지 않는 `user_profiles.temp_password` 컬럼에 UPDATE(42703) → 항상 400. 컬럼이 있어도 로그인 시 읽는 코드가 없는 죽은 설계 + 평문 비밀번호 저장이라는 보안 문제.
3. 부수 발견. Edge Function은 anon 키만으로 호출 가능해 userId+email만 알면 누구든 타인 비밀번호 초기화 가능한 구조였음.

## 결정

Edge Function을 버리고 Next.js API 라우트 `/api/auth/update-password`로 대체한다.

- 소스가 리포에 들어옴 (Edge Function 소스는 리포 밖에 있었음).
- 이미 회전 완료·검증된 `sb_secret_` 키(`supabase-admin.ts`, Vercel env)를 재사용.
- 본인확인(email+이름+전화번호)을 서버에서 재검증 — anon 호출 보안 구멍 해소.

## 구현

1. 신규 `safesys-app/src/app/api/auth/update-password/route.ts`
   - POST { email, name, phone, newPassword }
   - 입력 검증(필수값, 비밀번호 6~72자)
   - `user_profiles`에서 email(소문자)+full_name+phone_number 3요소 일치 조회(service role)
   - 일치 시 `auth.admin.updateUserById(id, { password })`
   - 기존 라우트 패턴(`quality-summary/reject/route.ts`) 준수
2. `FindPasswordModal.tsx` 수정
   - `handlePasswordSubmit`에서 Edge Function invoke + temp_password fallback 제거
   - 새 API 라우트 fetch 호출, 서버 에러 메시지 그대로 표시
3. 검증. `npm run lint` + `npx tsc --noEmit` 통과 후 커밋

## 남기는 것 (범위 밖)

- 모달 1단계의 클라이언트 직접 `user_profiles` 조회(본인확인 UX)는 유지 — 외과적 변경 원칙.
- 레이트 리밋 없음(프로젝트 전반에 인프라 부재) — context-notes 참조.
- Supabase Edge Function `update-user-password` 삭제는 사용자 확인 후 별도 처리.
