# 품질시험 결과 관리대장 — 컨텍스트 노트

작업 중 내린 결정과 근거를 기록한다. (2026-07-02)

## 요청 배경

- 사용자 페이지 피드백: `/project/{id}` 품질 캐비넷에 "품질시험 결과 관리대장" 서류철 추가 + 3종 양식(성과총괄표·실시대장·확인시험 의뢰서) 기능 구현 요청.
- 사용자가 자율 진행을 명시 승인 ("허락맞지 말고 진행해") — 승인 게이트 없이 설계~구현 진행.

## 결정 사항

1. **기존 월례보고서 계획과의 관계**: `plans/20260702_품질시험월례보고서.md`(별지 제3호서식, 미구현)는 별도 기능. 이번 작업과 무관하므로 건드리지 않음. 다만 서류철 위치(품질 캐비넷 C그룹 신설)와 출력 방식 등 설계 언어는 일치시킴.
2. **참조 구현체**: 시공 캐비넷의 검사/검측 대장 (`inspection-request`) — 페이지 구조(목록+폼), 타입 파일 분리, ExcelJS 출력, SignatureModal 서명, RLS 정책까지 이 패턴을 그대로 따름. 새 패턴 발명 없음.
3. **일련번호 미저장**: 실시대장 일련번호는 (test_date, created_at) 정렬 순서로 표시 시 부여. 중간 삭제 시 번호 재정렬이 자연스럽고, 동시성 문제 없음.
4. **work_type(공종) 필드 추가**: 별지 제42호서식에는 공종 열이 없지만, 성과총괄표 ④⑤가 공종 단위 집계라서 실시대장 레코드에 공종을 입력받아야 자동집계가 가능. 폼에서는 선택 입력으로 배치.
5. **확인시험 구분 방법**: 실시대장의 `시험·검사구분`(test_category)이 '확인시험'인 레코드를 총괄표 ⑤로 분류. 별도 boolean 플래그를 두지 않음 (단일 출처).
6. **총괄표 행 데이터는 JSONB**: 검사/검측 대장의 checklist_items JSONB 전례를 따름. 행 스키마 변경에 유연하고 테이블 정규화 불필요 (문서 스냅샷 성격).
7. **누계 미저장**: 총괄표 기성량 누계 = 전회까지 + 금회 — 화면·엑셀에서 계산 (기존 월례보고서 계획의 계산 규칙과 동일 철학).
8. **서명은 base64 TEXT 컬럼**: CLAUDE.md 프로젝트 종속 테이블 규칙에 따라 Storage 대신 DB 저장 → cascade 삭제로 고아 파일 없음. 삭제 라우트 URL 수집 로직 추가 불필요.
9. **출력은 Excel (PDF 아님)**: 3종 모두 표 중심 양식이고, 가장 가까운 기존 기능(검사/검측 대장)이 Excel 출력. html2canvas 텍스트 버그 회피 측면에서도 유리.
10. **RLS**: inspection_requests와 동일 — 조회 전체 허용 / 삽입·수정·삭제는 작성자 본인. 프로젝트 접근 제어는 앱 레벨(기존 서류철들과 동일 수준).

## 구현 후 검증 메모

1. **동시 작업 감지**: 구현 도중 다른 세션이 월례보고서 기능을 커밋함 (d51d6a5, 품질 캐비넷 C그룹 신설 포함). 이 작업의 서류철은 그 C그룹에 나란히 추가하는 것으로 조정 — 계획의 "C그룹 신설" 항목은 불필요해짐.
2. **마이그레이션 미적용**: supabase-safesys MCP는 읽기 전용(문서화된 제약), 플러그인 Supabase MCP는 다른 계정(AIalertapp만 보유), supabase CLI 미설치. → `database/add_quality_test_ledger_tables.sql`을 사용자가 Supabase SQL Editor에서 직접 실행해야 기능이 동작한다. 테이블 없더라도 페이지·캐비넷은 안전하게 동작 (count 조회 에러 시 건수 미표시, 목록 빈 상태).
3. **검증 결과**: `npx tsc --noEmit` 신규 파일 오류 0건. ESLint의 `no-explicit-any` 지적은 기존 코드 전반의 `(supabase as any)` 패턴과 동일 — 프로젝트가 수용 중인 현상이라 그대로 둠 (외과적 변경 원칙).
4. **Write 도구로 생성한 파일에 NUL(0x00) 문자가 섞인 사고 1회**: quality-test-types.ts 초판에서 발견, 전체 재작성으로 해결. 신규 파일 9개 전부 제어문자 스캔으로 클린 확인.
5. **프로덕션 빌드는 실행하지 않음**: CLAUDE.md 규칙(동의 없이 빌드 금지) + 동시 세션 작업 중 간섭 위험. 타입 검사로 대체.

## 추가 기능: 일련번호 표시 + 사진대지 (2026-07-02 페이지 피드백)

- 배경: `/project/{id}/quality-test-ledger` 실시대장 탭 페이지 피드백 2건 — (1) 작성 폼에 일련번호가 안 보임, (2) 시험 항목별 사진 첨부 필요 (참고 파일: `3.품질검사 사진대지.pdf`, 별지 형식 — 공사명·일련번호 / 타설(시공)일자·시험일자 + 사진 1장).
- **사진 저장 방식 — Storage vs base64**: 서명(quality_engineer_signature 등)은 CLAUDE.md 규칙대로 base64 TEXT로 저장했지만, 사진은 서명보다 훨씬 크고 대장 목록 조회가 `select('*')`라 모든 행에 사진까지 실려 성능 저하 위험 → Storage(`quality-test-photos` 버킷) + URL 컬럼 방식 채택. 프로젝트 삭제 라우트에 정리 블록 추가 완료.
- **사진 개수 — 일련번호(제출건)당 1장**: 처음엔 "항목(시험·검사 종목)당 1장"으로 구현했으나 사용자가 즉시 "사진은 일련번호당 1건씩"이라고 정정 → `photo_url`을 `QualityTestItemFields`가 아니라 `QualityTestCommonFields`로 옮겨 재구현. 한 제출건(같은 serial_no) 안의 여러 시험 항목 행에는 동일한 photo_url이 공통 필드처럼 중복 저장된다(test_date·work_type 등 기존 공통 필드와 동일한 저장 방식). 사진대지 PDF 출력 시 serial_no 기준으로 중복 제거해서 1건만 출력.
- **타설(시공)일자 — 사용자 확인 후 생략**: AskUserQuestion으로 확인 — 기존 "연월일" 필드 하나만 시험일자로 쓰고, 사진대지 출력물의 타설(시공)일자 칸은 공란으로 출력. 데이터 모델(날짜 필드 추가) 변경 없음.
- **출력 형식 — PDF (사용자 확인)**: 참고 PDF와 동일하게 jsPDF+html2canvas 기반, 페이지당 사진 2건(참고 PDF의 실제 레이아웃과 동일 — heatwave/page.tsx의 `addPhotoPagesToPdf` 관례 재사용). `applyHtml2canvasTextFix()` 적용 필수(CLAUDE.md에 문서화된 img{display:block} baseline 버그 회피).
- **Storage 버킷 정책**: 업로드 경로가 `${projectId}/...`라 `auth.uid()` 폴더 매칭 정책(예: 초기 inspection-photos 버킷)은 맞지 않음 → 최근 관례인 `safety-inspection-photos`(모든 CRUD를 `auth.role() = 'authenticated'`로 판단)를 그대로 따름.
- **버킷 신규 생성 이유**: 코드베이스 관례 조사 결과(Explore 서브에이전트) 공용 사진 버킷이 없고 기능별 전용 버킷(`{기능}-photos`)이 표준이라 `quality-test-photos`를 새로 만듦.

## 추가 피드백: 실시대장 목록 컬럼 보강 (2026-07-14)

- 기존 데이터 모델과 작성 폼에는 `test_standard`, `test_result`, 두 기술인의 이름·서명이 이미 존재했지만 목록에서는 시험 종목과 판정만 표시하고 있었음. 데이터베이스 변경 없이 목록 헤더와 행 렌더링만 보강함.
- 공식 서식 구조에 맞춰 시험·검사 종목 → 시험 기준 → 시험 결과 → 판정 → 품질관리기술인(이름·서명) → 건설사업관리기술인(이름·서명) 순서로 배치함.
- 두 기술인 컬럼은 각각 이름과 저장된 서명 이미지를 한 셀에 나란히 표시하고, 서명이 없을 때는 이름만 표시함.
- `border-collapse`와 헤더·데이터 셀 우측 테두리를 적용해 모든 컬럼 사이에 세로 구분선을 표시함. 그룹 제목 행은 단일 병합 셀이므로 내부 구분선 없이 전체 12개 컬럼을 병합함.
- 항목 하위 입력 영역은 `lg` 이상에서 12열 그리드를 사용해 연월일·시험 종목·시험 기준·측정값·판정을 한 행에 배치함. 모바일·태블릿은 기존 줄바꿈 구조를 유지함.
- 측정값을 적는 `test_result` 입력은 유지하고, `result_verdict` 선택 상자를 합격·불합격·재시험 3개 버튼으로 교체함. 선택 상태는 합격 초록색, 불합격 빨간색, 재시험 주황색으로 구분함.
- 실시대장 황색 헤더는 항상 유지하고 표 또는 빈 상태 본문만 접도록 `isListExpanded` 상태를 추가함. 최초 값은 펼침이며 헤더 버튼으로 수동 전환 가능함.
- `추가` 또는 기존 일련번호 행을 선택하면 목록을 자동으로 접어 바로 아래 작성·수정 폼의 접근성을 높임. 저장·취소가 호출하는 `resetForm`에서는 목록을 다시 펼쳐 반영 결과를 확인할 수 있게 함.
- 성과총괄표의 제출건 선택 모달과 선택 상태를 제거함. `실시대장 전체 자동집계` 버튼은 프로젝트의 모든 `quality_test_records`를 조회해 ④·⑤ 실적을 한 번에 다시 계산함.
- 전체 재계산 방식이라 버튼을 반복 실행해도 수치가 중복 가산되지 않으며, 기존 행의 계획 횟수와 비고는 `aggregatePerformanceRows`의 병합 규칙에 따라 보존됨.
- ④ 품질검사 실적은 자체(관리)시험·의뢰(수탁)시험·확인시험을 모두 포함한 전체 합계로 변경함.
- ⑤ 확인시험 실적은 `확인시험`과 `의뢰(수탁)시험`만 대상으로 하고 시험 구분까지 집계 키에 포함해 별도 행으로 생성함. 확인시험 행의 `verification_type`은 `공사감독`, 수탁시험 행은 `건설엔지니어링사업자`로 자동 입력함.
- 자체·수탁·확인시험 각 1건의 예시 데이터로 집계 함수를 실행해 ④ 실시 3건과 ⑤ 분리 행 2건 및 구분값을 확인함.
- 성과총괄표 엑셀 서명자 행에서 소속·직위가 두 줄로 표시되는 문제를 수정함. 소속 병합 범위를 B:D, 직위를 E:G로 넓히고 `wrapText: false`, `shrinkToFit: true`를 적용해 긴 회사명과 직위를 한 줄로 유지함.
- 실시대장 제출건 삭제 후 남은 고유 `serial_no`를 오름차순으로 정렬해 1부터 연속 번호로 다시 저장함. 같은 일련번호의 하위 시험 항목은 ID 목록으로 함께 갱신되어 화면·엑셀·사진대지 번호가 일치함.
- 삭제 또는 재정렬 대상에 다른 작성자의 기록이 포함되면 RLS로 일부만 처리되는 상태를 방지하기 위해 삭제 전에 중단하고 안내함. 재정렬 중 오류가 발생하면 최신 목록을 다시 불러옴.
- 대상 파일 ESLint와 전체 `npx tsc --noEmit` 통과. 실행 중인 로컬 개발 서버에서 대상 경로 HTTP 200 응답과 라우트 콘텐츠 포함을 확인함. `agent-browser` CLI가 설치되어 있지 않아 자동 스크린샷 검증은 수행하지 못함.

- **문제**: `loadRecords`가 `test_date, created_at` 순으로 정렬 — 같은 일련번호(제출건)에 나중에 항목을 추가(수정)하면 그 행만 `created_at`이 최신이라 정렬 시 원래 형제 행들과 떨어져 나감. 목록 표와 엑셀 대장 출력이 같은 `records` 배열을 그대로 쓰므로 둘 다 동일하게 깨짐.
- **수정**: 정렬 키를 `serial_no, created_at`으로 변경. `serial_no`는 이미 생성 시점에 실제 컬럼으로 채번·저장되는 값이라(오늘 일련번호 표시 기능에서 확인) 이 값을 1차 정렬 키로 써도 항상 같은 제출건이 붙어 나온다.
