# 컨텍스트 노트.

- 현재 반려는 `/api/quality-summary/reject` POST에서 인증·발주청 역할 확인 후 service-role UPDATE로 처리한다.
- `loadReports()`는 rejected_at이 있고 rejection_read_at이 없는 보고서 수를 상위 페이지에 전달한다. 취소 후 이 경로를 재사용한다.
- 취소는 반려 메타정보만 초기화한다. 반려 시 삭제된 과거 검토자 서명은 저장돼 있지 않으므로 복원하지 않고, 현재 서명값을 유지한다.
- 기존 반려 API에 DELETE를 추가하고 공통 인증·권한 검사를 재사용했다. 취소 UPDATE는 `rejected_at IS NOT NULL`인 대상만 초기화하며 없는 대상은 404로 안내한다.
- 취소 버튼은 반려 중인 보고서에만 표시되고 저장·반려 처리와 동시에 실행되지 않는다. 성공 시 목록/미확인 수를 재조회하고 편집 입력은 유지한다.
- 신규 API·실제 UI handler 및 기존 품질 권한 회귀 44개 통과, 대상 린트·전체 타입체크 통과. 독립 리뷰에서 중대한 결함 없음.
- 실제 로컬 Next DELETE 요청의 null/빈 본문 400, 무인증 401을 확인했다. 사용자의 브라우저에서 반려 통보 취소 버튼이 활성 상태로 표시됨을 확인했으며 실제 보고서의 반려를 대신 취소하지 않았다.
