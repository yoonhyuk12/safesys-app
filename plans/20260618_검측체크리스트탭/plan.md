# 검측요청서 등록 — 검측 체크리스트(별지 제5호) 탭 추가

## 목표

`/project/[id]/inspection-request` 등록 폼에 탭을 두어, 기존 **검측요청서(탭1)** 에 더해
**검측 체크리스트(별지 제5호, 탭2)** 도 같은 화면에서 작성·저장·엑셀 출력한다.

## 결정 사항 (사용자 확인됨)

- 저장 구조: 요청서 1건에 체크리스트 1건 **1:1 첨부** → 기존 `inspection_requests` 테이블에 컬럼 추가.
- 항목 행: **고정 행 수** — 양식과 동일하게 14행으로 고정(`CHECKLIST_ROW_COUNT`).
- 시설물명·위치·공종명·물량·점검일자는 탭1 값에서 자동 채움(탭 전환 시 1회 복사, 이후 수정 가능).
- 현장대리인·감독원 서명은 탭1 서명을 재사용(탭2에서 미리보기만).

## 양식 구조 (별지 제5호)

- 헤더: 시설물명 / 위치 또는 부위 / 공종명 / 물량(길이 면적 등)
- 표: 검측항목 | 검사기준(시방서·도면) | 검사결과(합격/불합격) | 조치사항
  - 각 항목 2행 — 상단=시공자 점검, 하단=감독원 검측
- 푸터: 시공자 점검일자 + 현장대리인(인), 감독원 검측일자 + 감독원(인)
- 주석: 검사결과 상단은 시공자, 하단은 감독원이 기록. 매몰부분 등 검측 사진 첨부.

## 작업 단계

1. DB 마이그레이션 SQL 작성 → 사용자가 Supabase 콘솔에서 실행 → verify: 컬럼 7개 존재
2. 타입/헬퍼 추가(`inspection-types.ts`) → verify: 빌드 통과
3. 체크리스트 엑셀 출력(`inspection-checklist-export.ts`) → verify: 다운로드되는 xlsx가 양식과 일치
4. 탭2 편집 컴포넌트(`InspectionChecklistTab.tsx`) → verify: 입력/저장 반영
5. 폼에 탭 바 추가(`InspectionRequestForm.tsx`) → verify: 탭 전환·자동 채움 동작
6. 페이지에 체크리스트 다운로드 버튼(`page.tsx`) → verify: 저장 후 엑셀 생성
7. `npm run lint` 통과

## 마이그레이션 필수

코드 배포 전 반드시 마이그레이션을 먼저 실행해야 한다. 컬럼이 없으면 저장이 실패한다.
