# 폭염대비 점검 일괄 등록 기능

## 요구사항 (사용자 페이지 피드백)

`/project/[id]/heatwave` 페이지에서.

1. 기존 "일괄"(일괄 다운로드) 버튼 **좌측**에 **"일괄 등록"** 버튼 추가.
2. 버튼을 누르면 일괄 등록 모드 진입 → 달력에서 등록할 날짜들을 다중 선택.
3. "등록" 버튼을 누르면 모달이 열림.
   - **체감온도 조회 시간 구간을 바(bar) 형태로 선택** (예. 8시 ~ 17시).
   - 시작 시각부터 2시간 간격으로 측정 시각 생성 (8 → 8, 10, 12, 14, 16시. 종료 시각 이하까지).
   - 각 시각의 **기상청 시간별 체감온도**를 자동 조회해 입력.
   - 나머지 점검 항목(5대 기본수칙 + 작업시간 조정)은 모두 양호(O) 처리.
   - 확인자 이름 입력.
4. 제출 → "폭염 조치에 대한 모든 책임은 본인에게 있습니다" **동의** 버튼 → 서명 모달 → 일괄 등록 실행.

## 기술 조사 결과

- 기존 단건 등록의 체감온도 조회(`/api/weather-crawl`)는 **초단기실황**이라 과거 날짜 조회 불가.
- 기상청 API 허브 **ASOS 시간자료 `kma_sfctm3.php`** 로 과거 시간별 관측값 조회 가능함을 실호출로 검증 완료 (2026-07-08).
  - URL. `https://apihub.kma.go.kr/api/typ01/url/kma_sfctm3.php?tm1=YYYYMMDDHHmm&tm2=YYYYMMDDHHmm&stn={stnId}&help=0&authKey=...`
  - 데이터 행은 12자리 `YYYYMMDDHHMI`로 시작. 공백 분리 0-based 컬럼. **WS=3(풍속 m/s), TA=11(기온 ℃), HM=13(습도 %)**. 결측값 `-9`/`-9.0`.
  - 인증키는 `src/lib/kma-auth.ts`의 `getKmaHubKey()` 재사용.
- 체감온도 산식은 `weather-crawl/route.ts`의 `calculateApparentTemperature()`(기상청 2022.6.2 개정 여름철 산식 + 겨울철 풍속냉각)를 그대로 복사 사용.
- 최근접 관측소 선정은 `asos-range/route.ts`의 `ASOS_STATIONS` 하드코딩 목록 + 하버사인 방식 복사 (기존 라우트들도 동일하게 중복 보유 — 기존 파일은 건드리지 않음).

## 구현 설계

### 1) 신규 API 라우트 `src/app/api/weather/hourly-feels-like/route.ts`

- POST `{ lat, lng, date: 'YYYY-MM-DD', hours: number[] }` — **날짜 1개씩** 처리 (클라이언트가 날짜별 순차 호출 → Vercel 함수 타임아웃 회피 + 진행률 표시 용이).
- 최근접 ASOS 관측소 결정 → `kma_sfctm3.php` 1회 호출(tm1=최소시각, tm2=최대시각) → 요청 시각별 TA/HM/WS 파싱 → 체감온도 계산.
- 응답. `{ date, stnId, stnName, results: [{ hour, apparentTemperature, temperature, humidity, windSpeed }] }`. 관측값 없는 시각은 `apparentTemperature: null` (가짜 값 금지 — weather-crawl과 동일 원칙).
- 유효성 검증. lat/lng 숫자, date 형식, hours 1~12개·0~23 정수.

### 2) 신규 모달 `src/components/project/HeatWaveBulkRegisterModal.tsx`

- Props. `isOpen`, `onClose`, `dates: string[]`, `onSave(data: { hours: number[]; inspectorName: string; signature: string }) => Promise<void>`.
- 내용.
  - 선택 날짜 요약 표시.
  - 시간 구간 듀얼 레인지 슬라이더 (범위 5~20시, 기본 8~17, 시작<종료 보장). 결과 측정 시각 칩 표시 (예. 08시·10시·12시·14시·16시).
  - 안내 문구. 각 시각 기상청 체감온도 자동 입력, 나머지 항목 전부 양호(O) 처리.
  - 확인자 이름 입력 (필수).
  - 제출 → 모달 내 동의 단계 전환. "폭염 조치에 대한 모든 책임은 본인에게 있습니다" + [동의] 버튼.
  - 동의 → 기존 `SignatureModal` 재사용 → 서명 완료 시 `onSave` 호출, 완료 후 닫기.

### 3) 페이지 수정 `src/app/project/[id]/heatwave/page.tsx`

- 상태 추가. `isBulkRegisterMode`, `selectedRegisterDates: Set<string>`, `isBulkRegisterModalOpen`, `isBulkRegistering`, `bulkRegisterProgress`.
- 달력 헤더에 "일괄 등록" 버튼 (기존 "일괄" 버튼 좌측). 모드 진입 시 일괄 다운로드 모드는 해제 (상호 배타). 모드 중 선택 수 있으면 "등록(n)" 버튼 표시.
- 달력 클릭. 일괄 등록 모드에서는 **오늘 이하 날짜만** 선택 토글 (미래 날짜 불가). 선택 표시는 주황(amber) 계열로 일괄 다운로드(보라)와 구분.
- `handleBulkRegister(data)` 흐름.
  1. 좌표 없으면 중단 안내 (단건과 동일).
  2. 날짜별로 `/api/weather/hourly-feels-like` 순차 호출, 진행률 갱신.
  3. 선택 날짜들의 기존 점검을 DB에서 조회해 **같은 날짜·같은 시(hour)에 기록이 이미 있으면 해당 시각은 건너뜀** (중복 방지).
  4. 서명 1회 업로드 (기존 버킷 폴백 목록 재사용) → 모든 행이 URL 공유.
  5. `heat_wave_checks` 일괄 insert. `check_time='YYYY-MM-DD HH:00:00'`, `feels_like_temp`, 6개 boolean 모두 true, `photos: null`, `inspector_name`, `signature`.
  6. 결과 요약 alert (등록 n건 / 중복 건너뜀 m건 / 체감온도 미확보 k건) → 목록 재조회, 모드 해제.
- 텔레그램 알림은 일괄 등록에서는 발송하지 않음 (수십 건 연속 발송 방지).
