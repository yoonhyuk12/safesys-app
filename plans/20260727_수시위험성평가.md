## 아키텍처 (4층)

1. **데이터층** — 참조 테이블 `risk_hazards`(위험요인) + `risk_hazard_measures`(감소대책), 1회 임포트. 평가서 저장은 `risk_assessments`(project_id CASCADE). `projects.risk_business_type`(nullable) 추가로 확정 사업별 기억.
2. **매칭층** — 캐스케이드 선택(사업별→공사→단위작업→세부단위작업) API + 프로젝트명 기반 사업별 유추 유틸(키워드+별칭 매핑). "사업 무관(전체)" 모드 지원.
3. **생성층** — 선택된 세부단위작업의 위험요인·대책 원문을 Gemini에 투입. LLM 역할은 (a) 상황 관련 위험요인 선별 (b) 빈도·강도 산정(SIF·중대재해 플래그=강도 상향 근거) (c) 장비/인원 제안뿐. **위험요인·대책 텍스트는 DB 원문 그대로 사용(환각 차단·법령 근거 보존).** 출력은 hazardId+판정값 JSON.
4. **출력층** — exceljs로 빈양식 재현(`src/lib/excel/risk-assessment-export.ts`), 8:9 인쇄 제목행 반복, 결재란 서명 이미지는 안내 문구 위 겹침(핵심 제약 #5).

## 코드 계약 (Worker 병렬 작업의 고정점)

`safesys-app/src/lib/risk-assessment/types.ts`에 코디네이터가 선작성. 모든 Worker는 이 파일을 수정하지 않고 참조만 한다(변경 필요 시 코디네이터에게 ask).

## 업무 분담 (Worker 3인, model opus, 같은 워크트리)

| Worker | 담당 | 소유 파일 영역 |
|--------|------|----------------|
| A. DB 검색 전문 | 참조 테이블 마이그레이션 SQL, 엑셀 임포트 스크립트, taxonomy/hazards 조회 API, 사업별 유추 유틸 | `database/20260727-*_risk_hazards*.sql`, `safesys-app/scripts/import-risk-hazards.js`, `src/app/api/risk-db/**`, `src/lib/risk-assessment/business-type-infer.ts` |
| B. 기능 구현 | 작성 마법사 UI, 평가서 저장 테이블 마이그레이션, Gemini 판정 API, 목록/상세/삭제, 다운로드 버튼 연결 | `src/app/project/[id]/risk-assessment/**`, `src/components/project/risk-assessment/**`, `src/app/api/ai/risk-assessment/route.ts`, `database/20260727-*_risk_assessments.sql` |
| C. 엑셀 출력 | 빈양식 재현 export 모듈(레이아웃 리버스엔지니어링), 인쇄 제목행 반복, 서명 겹침 | `src/lib/excel/risk-assessment-export.ts` |

- A·B·C 병렬 디스패치. B는 A의 API·C의 export 함수를 types.ts 계약 기준으로 호출(통합 검증은 코디네이터).
- DDL 적용은 Worker가 직접 못 하므로, 마이그레이션 SQL 완성 시 `ask`로 코디네이터에게 적용 요청.
