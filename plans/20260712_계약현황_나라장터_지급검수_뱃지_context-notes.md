# 컨텍스트 노트 — 계약현황 나라장터 대금지급·검사검수 뱃지 (2026-07-12)

## 방향 전환 이력

1. 최초: `payment_completed` 수동 토글 뱃지 구현·마이그레이션 적용(사용자 실행).
2. 사용자 지시로 자동 판정 전환 — 준공일 경과 기준 "완료" 뱃지.
3. 사용자가 나라장터에서 대금지급 정보 노출을 발견(`FIUA027_01_...pyprWfrm...` 엘리먼트 제보) → 실제 데이터 기반으로 재구현.
4. `payment_completed` 컬럼은 폐기 — 정리 SQL `database/20260712-2100_*.sql` (선택 실행, 남겨둬도 무해).

## 데이터 출처 (2026-07-12 실호출 검증)

- 공공데이터포털 공식 API에는 대금지급·검사검수 데이터가 없다(검색 0건). 계약정보서비스의 `payDivNm`(지급구분명)은 지급방법(직불/대지급)이지 완료 여부가 아니다(실측 "대지급").
- **나라장터 차세대 통합검색(비로그인 공개)** 내부 엔드포인트 사용.
  - `POST /fi/fiu/fiua/UntySrch/srchUntyTotal.do` — 문서 검색. `untySrchSeCd`: KG=대금지급, NZ=검사검수, CC=계약현황, CD=납품요구. 키워드(`searchKeyword`/`bizNm`)는 사업명 부분일치 — 계약·납품요구 번호로는 KG/NZ 문서가 색인 안 됨.
  - `POST .../srchPprcGiveDtl.do`·`srchInspIgiDtl.do` — 상세. `dlSrchParamM.bizNo`에 문서번호(dqId, R##KG/R##NZ).
  - 대금지급 상세 연결 필드: `bizDtlItm01`=계약번호(구형은 `_1` 접미), `bizDtlItm02`=계약차수, `bizDtlItm03`/`ldocNoVal`=납품요구번호+차수2자리, `bizYmd`=지급일, `ctrtAmt`=지급금액, `bizDtlItm12`=지급구분(일반급 등).
  - 검사검수 상세: `dlreqNo`(단가계약 납품요구 건은 납품요구번호, 직접구매 건은 계약번호 — 매칭률 한계), `bizYmd`=검수일.
  - 쿠키·인증 불필요, 서버(Node fetch)에서 직접 호출 가능 확인.
- 실증: 망월 지급자재 납품요구 R25TB01289113 → KG 문서 R25KG11316969 (지급 2025-12-26, 53,003,800원, 번호 일치). 원곡지구 사업 지급자재 KG 17건.

## 구현

- `/api/g2b/pay-insp` 라우트 — nm(키워드)·inst(수요기관 필터)·기간으로 KG/NZ 검색 후 상세 병렬 해석(카테고리당 25건 캡, 4개씩). 비공식 API라 실패 시 뱃지만 안 뜨는 부가 기능으로 설계.
- 페이지: 사업명 키워드(숫자 시작 토큰 제외 첫 단어)별 세션 캐시(`payInspCache`) 배경 조회 → 문서번호 중복 제거 풀에서 번호 매칭.
  - 물품 행: 지급 문서 매칭 → "지급완료"(초록), 없고 검수 문서만 → "검수"(하늘). 툴팁에 일자·누계.
  - 공사·용역 그룹: 지급 누계 ≥ 총액 → "지급완료", 아니면 준공일 경과 "완료"(툴팁에 지급 누계 병기).
- 물품 행 링크 개선(납품요구 상세 딥링크)은 **불가 확인** — 나라장터 단독 URL(openUrl=Y)은 srchName=ctrtCrst(계약현황)만 지원(화면 모듈 UntySrchBsneDtl.js 분석·실접속 확인). 링크는 현행(단가계약) 유지.
