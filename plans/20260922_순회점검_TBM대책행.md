# 순회점검 점검사항에 TBM 대책 이행 여부 3행 추가

작성일 2026-09-22. 요청자 피드백 — 순회점검 작성 화면 점검사항에 3줄을 추가해, 당일 TBM(없으면 최근 TBM)의 위험요소 대책(대책 1~3) 이행 여부를 넣는다.

## 결정 사항 (사용자 확인 완료)

- 점검사항은 **13행**으로 늘린다. 앞 10행은 지금처럼 AI(작업장 공통 5 + 테마 5), 뒤 3행은 TBM 대책 이행 여부.
- 당일 TBM이 여러 건이면 **가장 최근 제출 1건**의 대책 1·2·3을 쓴다. 당일 제출이 없으면 그 이전 가장 최근 제출 1건.
- HWPX 양식(A4 한 쪽)은 항목 행 높이 3092→2600, 사진 칸 18750→15870으로 줄여 표 높이 56291을 유지한다(서명 좌표·2쪽 밀림 방지).

TBM 대책 원천은 `tbm_submissions.solution_1~3`(TBM 제출 모달 "대책 1~3", maxLength 50). `meeting_date`는 타임스탬프 문자열 비교로 조회한다(기존 `loadTbmWorkForDate`와 동일 필터 두 갈래: project_id / project_name+headquarters+branch).

## 설계

1. **types.ts** — `PATROL_LEDGER_AI_ITEM_COUNT = 10`(AI 생성분), `PATROL_LEDGER_TBM_SOLUTION_COUNT = 3`, `PATROL_LEDGER_ITEM_COUNT = 13`(양식 총 행). `PATROL_LEDGER_CATEGORIES`에 `'TBM 대책'` 추가. 주석 갱신.
2. **tbm-work.ts** — `pickTbmSolutions(rows)` 순수 함수(최신 1건의 solution_1~3을 공백 정리·빈 값 제외·중복 제거, 최대 3건)와 `loadTbmSolutionsForDate(client, project, date)`(두 갈래 각각 `lte meeting_date ${date}T23:59:59`, `order meeting_date desc, created_at desc`, `limit 1` → 둘 중 최신 1건). 반환 `{ solutions: string[]; meetingDate: string | null }`. `tbmSolutionItems(solutions): PatrolLedgerAiItem[]` — text는 `${대책} 이행 여부`, category `'TBM 대책'`.
3. **records.ts** — 검증 1~13건, 분류는 `PATROL_LEDGER_CATEGORIES` 사용. 오류 문구 `점검항목은 1~13건이어야 합니다.`
4. **PatrolLedgerForm.tsx** — 날짜 effect에서 대책도 함께 조회(state `solutions`). 생성 시 `buildPatrolLedgerItems([...result.items, ...tbmSolutionItems(solutions)])`. 작업내용 카드에 안내 한 줄(`TBM 대책 N건 · YYYY-MM-DD TBM` / 없으면 `TBM 대책 없음`). 기존 안내문에 TBM 대책 3건 설명 추가.
5. **PatrolLedgerDetail.tsx** — 13행(`PATROL_LEDGER_ITEM_COUNT`).
6. **patrol-ledger-hwpx-export.ts** — 행 3~15 채움, 사진 `16,1`, 지적사항 `16,3`. 서명 좌표 상수는 유지(표 높이 불변).
7. **양식** — `scripts/patrol-ledger-template-add-rows.mjs`로 표1 행 12를 3번 복제(rowAddr 13·14·15, 번호 11·12·13), 옛 13행→16, rowCnt 17, 높이 조정. 한글 2022 크래시 테스트 + PDF 렌더 육안 확인.
8. **DB** — `database/20260922-1100_순회점검_TBM대책행.sql` 함수 교체(1~13, 분류 3종) + COMMENT. 픽스처에 경로 추가.
9. **테스트** — records(대책 선별·항목 변환·13건 검증), sql(14건 거부·no 14 거부·TBM 대책 허용), hwpx(13행·16행 주소), route는 10건 그대로.
10. **docs/database.md** — `항목 1~10건` → `1~13건`, 적용 순서에 새 SQL 추가.

## 리스크

- 항목 문구가 두 줄로 접히면 행이 자라 2쪽으로 밀릴 수 있다(현행에도 있던 위험). 대책 문구는 50자 제한이라 `(TBM 대책) … 이행 여부`가 두 줄이 될 수 있다 — 렌더로 확인하고 필요하면 안내.
- DB 마이그레이션은 사용자 승인 후 적용. 적용 전 main 푸시 금지([[supabase-mcp-ddl-consent]]).
