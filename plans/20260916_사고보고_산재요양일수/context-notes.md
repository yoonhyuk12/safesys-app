# 컨텍스트 노트

- worker-opus 세션 사용량 한도에 대한 기존 종료 증거를 근거로 코디네이터가 Codex 복구 경로를 지정했다. 추가 에이전트 없이 부모가 독립 리뷰한다.
- 공통 `ACCIDENT_REPORT_TEXT_KEYS`를 추가하면 기본값·정규화·빈 항목 안내·AI 스키마·병합에 일관되게 연결된다. 일수 전용 유효성 헬퍼를 추가해 AI에서도 재사용한다.
- 저장 문자열은 trim한다. 미입력을 0으로 바꾸지 않으며 음수·소수·비숫자·안전 정수 초과는 거부한다.
- 추출 지시문에 명시된 요양기간만 옮기고 휴업일수에서 복사·추정하지 않도록 구분한다. 실제 모델 호출이나 사용자 원본 전송은 하지 않는다.
- HWPX는 기존 피해자 인적사항 문단 확장기를 사용한다. 파일 생성·COM·브라우저 검증은 부모 소관이다.
- Supabase 스킬과 PostgreSQL CREATE OR REPLACE FUNCTION 문서를 확인했다. 지정된 파일명과 로컬 PGlite 적용은 사용자 지시가 일반 스킬 CLI 생성 절차에 우선한다.
- TDD RED로 공통·추출·병합 3개 및 기존 1418 SQL의 새 키 거부를 확인한 뒤 GREEN으로 전환했다.
- HWPX 격자는 원본 전체 XML과 생성물의 쪽 분할 순서를 혼동하지 않도록 동일 생성 경로의 미입력 출력과 비교한다. 새 필드의 셀 주소·span·폭과 헤더 보존을 검증했다.
- 부모 독립 리뷰에 따라 사용자 오류 문구의 안전 정수 최대값 표기를 없앴다. 내부 안전 정수 상한과 입력 max·SQL 검증은 유지한다.
- 부모의 신규 저장 오류·PDF 사진 요청은 부모 소관으로 전달받았으며 이 작업 범위를 확장하지 않았다.
