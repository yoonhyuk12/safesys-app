# 구현 결과

`report_details.expectedTreatmentDays`를 공통 타입·기본값·정규화·검증·추가상세폼·상세화면·AI 스키마/정규화/병합·HWPX에 연결했다. 별도 API나 라이브러리는 추가하지 않았다.

필드 계약은 빈 문자열 또는 0 이상 `Number.MAX_SAFE_INTEGER`(9,007,199,254,740,991) 이하의 십진 숫자 문자열이다. 기존 공통 trim을 적용하고 문자열 길이 상한은 200자다. 키 없는 기존 보고서는 빈값으로 읽는다. `0`은 입력된 값이므로 빈칸 AI 병합과 저장에서 보존한다. 음수·소수·비숫자·안전 정수 초과 문자열은 저장 전에 거부하며 DB는 JSON 숫자·null도 거부한다.

휴업일수와 상호 복사·추정하지 않는다. 추출 프롬프트는 일 단위 요양기간이 명시된 경우만 옮기도록 하며 진단 주수·입원기간·사고일에서 계산하지 않는다. 입력은 `number`, `min=0`, `step=1`, 일 단위 안내이며 상세에는 `N일`, HWPX 피해자 인적사항 다음에는 `산재요양 예상 N일`로 표시한다. HWPX 원본과 정제 양식은 변경하지 않았다.

## SQL 적용 순서와 인계

기존 `20260718-0506` → `20260718-0830` → `20260831-1730` → `20260916-1032` → `20260916-1418_사고보고_보고서_항목.sql` → **`20260916-1720_사고보고_산재요양_예상일수.sql`** 순서다. 테스트 fixture도 이 순서로 PGlite에 적용한다. 1720은 검증함수만 교체하고 기존 RLS·트리거·데이터·사진 검증을 유지한다. 앱 배포 전 후속 SQL 적용이 필요하다.
