# 판단 기록

- 기존 answers JSONB가 항목 text를 보관하고 상세와 HWPX가 이 값을 읽으므로 새 컬럼은 불필요하다.
- 기존 UPDATE RLS 정책이 없어 제출된 내역의 직접 수정에는 별도 정책 설계가 필요하다.
- 원문 PDF에서 유래한 강제 줄바꿈은 입력 표시에서 공백으로 처리하고 가로폭을 사용한다.
- 기존 editEquipmentInspectionDraft의 서명 무효화 흐름을 재사용한다.
- 원본 카탈로그와 다른 점검 기록은 변경하지 않는다.
- 사용자가 편집 화면 범위 질문에 새 점검 작성과 제출된 내역 모두라고 답해 범위를 확정했다.
- 제출된 내역은 당시 answers에서 초안을 복원해 현재 카탈로그 변경의 영향을 받지 않게 한다. 수정 실패 시 원본을 유지하고 입력 초안도 보존한다.
- 브라우저 QA 탭의 snapshot은 runtime_unavailable로 실패했다. 사용자 탭은 조작하지 않았다.
- 대체 검증은 별도 headless Chrome과 가짜 Supabase 응답으로 수행했다. 실제 DB 요청을 차단하고 기존 사용자 브라우저 세션과 분리했다.
- 브라우저에서 수정 진입, 저장된 18개 항목 표시, 수정 시 서명 무효화, 빈 문구 저장 차단을 확인했다. 데스크톱에서 모바일로 화면 폭을 바꾸면 고정 높이 때문에 긴 문구가 잘리는 문제를 재현하여 작업자에게 보완을 요청했다.
- 수정 문구와 XML 특수문자(<, &, >)가 담긴 HWPX를 한글 2022에서 직접 열고 PDF로 변환했다. PDF 텍스트와 전체 페이지 이미지에서 문구 보존, 표 정렬, 기존 서명 배치를 확인했다. 표본은 scratch/equipment-inspection/item-text-edit에 보관했다.
- 모바일 폭 전환 시 잘림을 ResizeObserver 기반 높이 재측정으로 수정했다. 1275px → 390px 전환 후 모든 문구의 scrollHeight가 clientHeight 범위 안에 들어오는지 검증했다.
- 브라우저 최종 검증 통과. 제출 내역 수정·빈 문구 차단·서명 초기화·실제 캔버스 재서명·수정 저장 payload·상세 갱신·실제 HWPX 다운로드 내 변경 문구·취소 시 원본 복귀·새 점검의 원문 보존 및 편집을 확인했다. 저장은 가짜 응답이며 실제 DB는 변경하지 않았다.
- 관련 테스트 55개, SQL 테스트 18개를 코디네이터가 직접 실행하여 통과했다. 타입 체크와 변경 파일 ESLint도 통과했다. 작업자는 전체 lint 오류 없음과 병합 SQL 테스트 28개 통과를 보고했다.
- Astra low 독립 검토에서 새로운 차단 결함은 없었다. 검토에서 재확인한 컬럼 권한 제한과 모바일 높이 보정을 Opus가 후속 구현했고 코디네이터가 코드·SQL 테스트·브라우저로 재검증했다.
- 제출 내역 수정은 database/20260915-0448_장비_일일점검_작성자_수정_정책.sql의 사용자 직접 실행이 필요하다. UPDATE 행 정책은 작성자와 현장 조회 권한을 확인하며, 열 권한은 점검 내용 칸에만 부여한다. 기존 현장 병합의 SECURITY DEFINER 권한은 유지한다.
