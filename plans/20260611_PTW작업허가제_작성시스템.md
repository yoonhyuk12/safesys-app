# PTW(위험공종 작업허가제) 작성 시스템 계획

> 작성일: 2026-06-11
> 대상: 프로젝트 대시보드 `D (실행)` 그룹 "위험공종 작업허가제(PTW)" 카드 활성화 + `/project/[id]/ptw` 페이지 구현
> 근거 자료: 「붙임6. 안전작업허가제 운영 매뉴얼(26년)」 PDF (허가서 서식 4종 + 승인대장)

## 1. 목표

준비중인 PTW 카드를 활성화하고, 허가서를 **작성·서명·저장·수정·PDF 다운로드**할 수 있는 시스템 구축.

### 사용자 플로우
1. PTW 페이지 진입 → **좌측 목록 / 우측 작성 영역** (모바일: 상단 목록 / 하단 작성)
2. `추가` 클릭 → **허가서 종류 선택** (4종) → 종류별 입력칸 표시
3. 하단에 **각종 서명** (서명패드) → `저장` → 목록에 추가
4. 목록 항목의 `PDF` 버튼 → 해당 허가서 양식 그대로 PDF 다운로드
5. 목록 항목 클릭 → 우측 폼에 불러와서 **수정** 가능

## 2. 허가서 종류 및 입력 항목 (PDF 서식 분석)

### ① 위험공종 작업허가서(PTW) — `high_risk`
- **공사개요**: 관리부서, 공사명, 작업기간, 수급인(원도급사), 공사비, 책임자(연락처)
- **작업내용**: 공종명, 작업업체명(하도급사), 대상공종 체크 8항목(고소작업/굴착·가설/철골/외부도장/승강기/수중·수면/복통·잠관/기타), 작업세부공종, 작업인원, 작업위치
- **중장비 작업**: 장비종류, 규격, 검토내용 체크 6항목(작업계획서/운전자자격/작업지휘자/간섭물/기상·노면/줄걸이용구)
- **위험요소 / 개선대책 / 재해형태**
- **공사감독 검토내용**: 검토의견, 조치결과
- **서명 3개**: 작성자(현장대리인), 허가자(공사감독원·계획확인), 확인자(공사감독원·이행확인)

### ② 정전작업 허가서 — `electrical`
- 신청인(업체명/직책/성명+서명), 작업허가시간(시작~종료), 작업장소, 작업내용, 출입자 명단
- 사전 필요유무: 밀폐공간출입 / 화기작업
- **안전조치 체크 10항목** (적정/부적정/해당없음 + 비고): 주차단스위치, 제어차단기, 잠금장치, 시험전원차단, 차단표지판, 잔류전하방전, 검전기확인, 단락접지, 현장스위치, 차단표지판
- 점검확인결과(점검기기/차단확인자/전기담당자/현장정비), 특별조치 필요사항
- **서명 2개**: 허가자(용역감독), 확인자(용역감독)

### ③ 화기작업 허가서 — `hot_work`
- 신청인, 작업허가시간, 작업장소/내용/출입자 (②와 동일 구조)
- 사전 필요유무: 밀폐공간출입 / 정전작업
- **안전조치 체크 20항목** (작업구역설정, 가스농도측정, 경보장치, 밸브차단, 맹판설치, … 방폭형기기)
- 산소·유해가스 농도 측정결과(물질명/농도/시간/측정자/감시인), 기기점검 결과, 특별조치
- **서명 2개**: 허가자, 확인자

### ④ 밀폐공간 작업 허가서 — `confined_space`
- 신청인 + **감시인**, 작업허가시간, 작업장소/내용/출입자
- 사전 필요유무: 화기작업 / 내연기관·갈탄 사용여부
- **안전조치 체크 13항목** (감시인배치, 밸브차단·치환·세정, 측정자자격, 농도측정, 환기장치, …)
- 산소·유해가스 농도 측정 (전/중/중 3회: O₂, CO₂, H₂S, CO, EX + 입·출 인원), 특별조치
- **서명 2개**: 허가자, 확인자

> ②③④는 골격이 동일(신청인→허가시간→장소/내용/출입자→사전유무→체크리스트→측정/점검→특별조치→서명)
> → **설정 기반 공용 폼** 1개로 처리, ①만 전용 폼. 체크리스트 항목은 상수 파일로 분리.

### 목록(승인대장) — PDF의 「붙임3 안전작업허가 승인대장」 그대로
| 번호 | 신청인 | 작업유형 | 작업내용 | 완료여부 | 비고 |
- 목록 자체가 승인대장 역할 → 별도 화면 불필요

## 3. DB 설계 — `database/add_ptw_permits_table.sql` (신규)

```sql
CREATE TABLE ptw_permits (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  project_id UUID REFERENCES projects(id) ON DELETE CASCADE,
  created_by UUID REFERENCES auth.users(id),

  permit_type TEXT NOT NULL CHECK (permit_type IN ('high_risk','electrical','hot_work','confined_space')),
  permit_date DATE,                 -- 작업(허가) 일자
  work_content TEXT,                -- 작업내용 (목록/승인대장 표시용)
  applicant_name TEXT,              -- 신청인/작성자 (목록 표시용)
  is_completed BOOLEAN DEFAULT false, -- 완료여부 (승인대장)

  form_data JSONB DEFAULT '{}',     -- 종류별 입력값 전체 (체크리스트, 측정결과 등)
  signatures JSONB DEFAULT '{}',    -- { applicant:{name,signature}, permitter:{...}, confirmer:{...}, watcher:{...} }
  remarks TEXT,

  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

ALTER TABLE ptw_permits ENABLE ROW LEVEL SECURITY;
-- RLS: new_worker_orientations 패턴 동일
-- SELECT: true / INSERT·UPDATE·DELETE: auth.uid() = created_by
```

- 종류별 필드 차이가 크므로 `form_data` JSONB 방식 채택 (기존 `new_worker_orientations` 패턴과 동일)
- 서명은 base64 문자열로 JSONB 내 저장 (기존 패턴 동일)
- **적용 방법**: Supabase MCP는 읽기 전용이므로 SQL 파일 작성 후 **Supabase 웹 콘솔에서 실행** 필요

- UI 원칙: 흰 배경 카드, 컴팩트, 내용물 맞춤 폭 (사용자 선호)

## 6. PDF 다운로드

- `lib/reports/ptw-permit-report.ts`: 기존 `tbm-submission-report.ts` 패턴 — 숨김 DOM에 원본 서식과 유사한 표 레이아웃 렌더 → html2canvas → jsPDF A4 세로 1장
- 종류별 템플릿 4종 (체크박스 ☑ 표기, 서명 이미지 삽입)
- 파일명: `위험공종작업허가서_{공종명}_{날짜}.pdf` 형식

## 7. 작업 단계

1. **DB**: SQL 파일 작성 → 사용자가 Supabase 콘솔에서 실행 (또는 요청 시 안내)
2. **타입/상수**: `permit-types.ts` — 4종 정의, 체크리스트 항목 전체 입력 (PDF 원문 기준)
3. **페이지 골격**: 반응형 2단 레이아웃 + 목록 조회 + 추가/수정 모드 전환
4. **폼 구현**: ① 전용 폼 → ②③④ 공용 폼 (체크리스트/측정표) → 서명 연동
5. **저장/수정/삭제**: supabase insert/update/delete + 목록 갱신
6. **PDF 생성**: 종류별 템플릿 → 다운로드 버튼 연결
7. **카드 활성화**: `isPending` 제거
8. **검증**: `npm run lint`, dev 서버에서 작성→서명→저장→목록→수정→PDF 전체 플로우 확인 (모바일 뷰포트 포함)
