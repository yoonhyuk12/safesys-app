# 사고보고 문서 업로드·사진·HWPX 출력

사용자가 제공한 파주 PDF(본문+사진 2쪽)와 평택 HWPX의 사고발생보고 양식을 분석했다. 직접 입력과 PDF/HWPX 업로드 자동 채움을 모두 제공하고 부족한 보고 항목을 보충하며 사진 최대 2컷을 포함한 한글 보고서를 내려받는다.

## 공통 데이터 계약

- 기존 `project_accidents`와 사고현황 집계를 유지한다. 새 nullable JSONB 컬럼 `report_details`에 보고서 추가 항목과 사진을 보관한다. 사진을 DB 행과 함께 관리하여 삭제·병합 시 별도 파일이 남지 않는다.
- 신규 `src/lib/accident-report.ts`가 `AccidentReportDetails`, `AccidentReportPhoto`, 기본값/정규화/검증을 제공한다. `ProjectAccident.report_details?: AccidentReportDetails | null`, `AccidentFormInput.report_details?: AccidentReportDetails`를 추가한다. 기존 대시보드 모달이 이 값을 보내지 않으면 기존 보고서 값을 지우지 않는다.
- `AccidentReportDetails`의 문자열 필드는 `reportTitle`, `reportDate`(YYYY-MM-DD), `reporterName`, `reporterPosition`, `reporterPhone`, `summary`, `accidentTime`(HH:mm 또는 빈 값), `victimDetails`(여러 피해자 인적사항), `damageDetails`(인명피해 상세), `propertyDamage`, `responsibility`, `noNotificationReason`, `compensationDetails`, `actionDetails`, `otherNotes`, `relatedContacts`다. `notifications`는 `emergency119|police|laborOffice|family` 배열, `victimActions`는 `hospital|funeralHome|home` 배열, `photos`는 `{dataUrl: string, caption: string}[]`다. 기존 `prevention_action`이 향후 추진계획을 겸한다.
- 사진은 브라우저에서 JPEG로 축소(maxEdge 1200)하며 1장당 1MB 이하, 2장까지. SQL에서도 2장 제한·객체/필드/사진 data URL 형식과 길이를 검증한다. 대시보드 집계에서 사진 JSON을 함께 읽지 않는다.
- `src/lib/accident-report-import.ts`의 `requestAccidentPrefill(file: File, projectId: string, accessToken: string)`는 `{fields: Partial<AccidentFormInput>, warnings: string[]}`를 반환한다. HWPX는 JSZip으로 텍스트만 추출하여 전송(원본 최대 15MB, 압축해제 안전 상한), PDF는 원본 최대 4MB를 전송한다. API는 `/api/ai/accident-report`, FormData `project_id`와 `file`(PDF) 또는 `text`(HWPX)로 받는다. 작성자·프로젝트·권한·사진은 AI에서 받지 않는다.
- API는 토큰을 검증하고 해당 사용자의 projects RLS로 접근을 확인한 뒤 기존 Gemini 모델 설정/사용량 기록 패턴으로 문서를 추출한다. 누락 내용을 지어내지 않으며 사용자가 저장 전 보완한다. 기존 입력을 교체하기 전 화면에서 확인한다. 입력 내용을 서버가 자동 저장하지 않는다.
- `src/lib/hwpx/accident-report-hwpx-export.ts`는 `downloadAccidentReportHwpx(accident: ProjectAccident, projectName: string): Promise<void>`와 테스트용 `buildAccidentReportHwpx(accident, projectName): Promise<Blob>`를 제공한다. 본문은 보고 요지→피해자현황→인명 외 피해→사고내용→조치→향후계획→특이사항→연락처, 사진대지는 별도 쪽. 장문은 내용이 잘리지 않도록 이어지는 쪽으로 나눈다.

## 작업 분담·검증

1. UI/데이터/SQL 담당은 공통 타입·페이지·모달·상세·사진·SQL·권한/저장 테스트를 구현한다.
2. 문서 추출 담당은 HWPX 텍스트 추출·인증된 Gemini API·결과 검증·테스트를 구현한다.
3. HWPX 담당은 사용자가 확정한 평택지사 원본 서식의 텍스트·사진 치환 코드와 익명화 템플릿 생성 스크립트를 담당한다. 실제 HWPX 파일 생성과 한글 COM 개방·재저장·PDF 검증은 Coordinator가 단독·순차로 수행한다.
4. Coordinator는 인터페이스를 조율하고 실제 예시 추출, 입력→저장→다운로드 브라우저 검증, SQL·타입·린트·독립 리뷰를 확인한다. 운영 DB 실행·프로덕션 빌드·푸시 없이 로컬 커밋하고 SQL 경로와 적용 순서를 안내한다.

사용자가 준 원본은 읽기 전용 참고 자료로만 사용하고 Git에 추가하지 않는다. 기존 미추적 `사용방법.md`도 대상 밖이다.

## 사용자 확정 양식 (14시 38분 변경)

출력은 `사고보고_평택지사(20260610).hwpx`의 양식을 그대로 사용한다. 새로 조립한 유사 양식은 대체하며, 원본의 표·문단·글꼴·체크항목·사진대지 구조를 보존하고 내용만 치환한다. 운영에 넣는 템플릿에서는 원본 개인정보·사진·미리보기·메타데이터를 제거한다. 원본은 SHA256으로 불변을 확인한다.

논문 프로젝트 `hwpx-thesis-editing` 스킬과 표 배치·출력 검증 규칙을 참고한다. 실제 설치 버전은 한컴오피스 2022(HOffice120)이며, 해당 버전에서 개방·재저장·PDF 전체 쪽 확인을 수행한다.
