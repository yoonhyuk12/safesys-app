# 프로젝트 현장 AI 비서 챗봇 (2026-07-20)

## 목표

프로젝트 상세 페이지(`/project/[id]`) 우하단에 플로팅 챗봇을 추가한다. 모델은 GPT-5.6 Luna(`gpt-5.6-luna`). 챗봇을 열면 해당 현장의 오늘 TBM 작업 브리핑과 감독(공사감독원) 미서명 문서 목록을 자동으로 안내하고, 이후 자유 질문은 tool calling으로 해당 프로젝트의 데이터를 실시간 조회해 답한다(하이브리드).

사용자 결정 사항.
- 형태는 플로팅 버튼(대시보드 TBM 챗봇과 동일 패턴).
- 데이터 접근은 하이브리드(브리핑 사전 주입 + 자유 질문 tool calling).
- 커밋까지만 진행, main 푸시(운영 배포)는 사용자 확인 후.

## 재사용 자산

| 자산 | 경로 | 용도 |
|------|------|------|
| TBM 챗봇 UI | `src/components/ui/TBMChatBot.tsx` | 플로팅 버튼·채팅 패널 골격 복제 |
| TBM 챗봇 라우트 | `src/app/api/chat/tbm/route.ts` | gpt-5.6-luna 호출·lazy 클라이언트·KST 오늘 계산 패턴 |
| 미서명 레지스트리 | `src/lib/bulk-sign/bulk-sign-targets.ts` | supervisor 대상 11종 테이블·컬럼·JSONB 판정 |
| 미서명 집계(클라) | `src/lib/bulk-sign/bulk-sign-counts.ts` | 쿼리 로직 참고(수정하지 않음) |

## API 계약 (고정)

`POST /api/chat/project-assistant`

- 헤더. `Authorization: Bearer <supabase access token>`, `Content-Type: application/json`
- 요청 본문.

```json
{
  "projectId": "uuid (필수)",
  "mode": "briefing | chat",
  "message": "string — chat 모드에서 필수",
  "conversationHistory": [{ "role": "user|assistant", "content": "..." }]
}
```

- 응답 200. `{ "response": "어시스턴트 텍스트" }`
- 오류. 400(파라미터 누락) · 401(토큰 무효) · 404(프로젝트 없음) · 500(서버/OpenAI 오류), 본문 `{ "error": "..." }`

## 백엔드 설계 (codex 담당)

신규 파일 2개.

1. `src/lib/bulk-sign/unsigned-supervisor-details.ts`
   - `getUnsignedSupervisorDetails(client, projectId)` — `BULK_SIGN_SIGNERS.supervisor.targets`를 순회하며 미서명 행의 `id`와 날짜(대상별 날짜 컬럼, 없으면 `created_at`)를 반환. 대상별 결과 `{ label, count, items: [{id, date}] }`(items 최대 10건).
   - 판정 로직은 `bulk-sign-counts.ts`의 `countTarget`과 동일 조건(TEXT null/빈문자, `unsignedBoolColumn=false`, JSONB keyedObject/roleArray). 기존 counts 파일은 수정 금지.
2. `src/app/api/chat/project-assistant/route.ts`
   - 인증. anon 클라이언트 `auth.getUser(token)`으로 토큰 검증, 실패 시 401.
   - 데이터 접근. service role lazy 클라이언트(chat/tbm 패턴).
   - 브리핑 컨텍스트(매 요청 주입). projects 행 + 오늘(KST) TBM + 감독 미서명 상세.
     - 오늘 TBM 조회는 레거시 호환. `project_id = :id` 또는 (`project_id IS NULL` 그리고 `project_name = 프로젝트명`).
   - tool calling. 함수 1개 `query_project_table(table, columns?, date_from?, date_to?, limit?)`.
     - 화이트리스트 테이블만 허용(직접 `project_id` 컬럼 보유 테이블). 서버가 `project_id` 필터 강제.
     - 응답 정제. 컬럼명에 signature/photo/image 포함 시 제거, 300자 초과 문자열 절단, 최대 50행.
     - 도구 왕복 최대 5회.
   - 모델 호출. `gpt-5.6-luna`, `reasoning_effort: 'none'`, `max_completion_tokens: 8192`.
   - briefing 모드는 도구 없이 1회 호출로 브리핑 생성(오늘 작업 요약 + 미서명 안내). chat 모드는 도구 포함.

## 프론트엔드 설계 (grok 담당)

1. 신규 `src/components/project/ProjectAssistantBot.tsx`
   - TBMChatBot 골격 복제. props `{ projectId: string; projectName?: string }`.
   - 열릴 때 1회 `mode: 'briefing'` 호출로 첫 어시스턴트 메시지 생성(로딩 표시).
   - 전송 시 `mode: 'chat'` + 최근 10개 히스토리. 토큰은 `supabase.auth.getSession()`에서 획득해 Authorization 헤더로 전달.
   - 헤더 "현장 AI 비서", 부제 "GPT-5.6 Luna · {프로젝트명}". 빠른 질문 4개.
2. `src/app/project/[id]/page.tsx` 장착
   - 모달들 옆(컴포넌트 끝부분)에 `<ProjectAssistantBot projectId={...} projectName={project?.project_name} />` 1곳 추가. 우하단에 기존 플로팅 요소 없음(겹침 없음).

## 검증 기준

1. `npx tsc --noEmit` 통과.
2. `npm run lint` 통과(신규/수정 파일 기준 신규 오류 없음).
3. Advisor(Fable)가 diff 직접 검토 — API 계약 준수, project_id 필터 강제, 서명 base64 제거 확인.
4. 의미 단위 커밋(푸시는 사용자 확인 후).
