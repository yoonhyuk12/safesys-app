# 관리자 로그인 인증번호 자체 발송 (유효시간 5분)

작성일 2026-08-02. 선행 작업 [20260802_관리자페이지.md](./20260802_관리자페이지.md).

## 배경

관리자(`admin`) 로그인 인증번호를 Supabase Auth(`signInWithOtp`)가 만들고 보내는 구조라, 유효시간이 Supabase 전역 설정 `mailer_otp_exp`에 묶여 있다. 현재 값은 **86400초(24시간)** 이고, 이 값은 신규 가입자 이메일 확인 링크와 공유된다. 가입 확인 만료 24시간은 미인증 계정 정리 크론(24시간 기준)에 맞춰 2026-07-23에 의도적으로 설정한 값이라 낮출 수 없다.

## 목표

관리자 로그인 인증번호만 **5분** 만에 만료시킨다. 가입 확인 메일(24시간)은 그대로 둔다.

## 설계

인증번호의 **생성·저장·검증·발송을 앱이 직접 수행**하고, Supabase는 세션 발급에만 쓴다.

```
[발송] /api/admin/otp/send
  6자리 난수 생성 → HMAC 해시로 admin_otp_codes 저장(만료 5분)
  → nodemailer(Gmail SMTP)로 ADMIN_OTP_EMAIL에 발송

[검증] /api/admin/otp/verify
  코드 대조(만료·시도횟수·1회용) → 통과 시
  supabaseAdmin.auth.admin.generateLink({ type: 'magiclink' })
  → 반환된 hashed_token을 서버에서 즉시 verifyOtp({ token_hash })로 교환
  → access/refresh 토큰만 클라이언트에 반환 (기존과 동일한 응답 형태)
```

Supabase가 만든 24시간짜리 토큰은 서버 안에서만 생성·소비되고 메일로 나가지 않는다. 사용자가 받는 것은 우리가 만든 5분짜리 코드뿐이므로 5분 제한이 실제로 강제된다.

### 검증된 전제 (GoTrue 소스 확인, 2026-08-02)

| 전제 | 근거 |
|------|------|
| `generateLink`는 메일을 보내지 않는다 | `internal/api/mail.go`의 `adminGenerateLink`는 `mailer.GetEmailActionLink`로 URL만 만들고 `sendEmail`을 호출하지 않는다 |
| `generateLink`엔 60초 발송 빈도 제한이 없다 | 같은 함수에 `validateSentWithinFrequencyLimit` 호출 없음 |
| magiclink로 교환한 세션도 JWT `amr`이 `otp`다 | `internal/api/verify.go`의 POST /verify는 타입과 무관하게 `issueRefreshToken(..., models.OTP, ...)`를 호출 |

→ `admin-auth.ts`의 `hasOtpLogin`(amr에 `otp` 요구)은 수정하지 않는다.

### DB 스키마

```sql
create table public.admin_otp_codes (
  id uuid primary key default gen_random_uuid(),
  code_hash text not null,        -- HMAC-SHA256(코드)
  expires_at timestamptz not null,
  attempts integer not null default 0,
  consumed_at timestamptz,
  created_at timestamptz not null default now(),
  request_ip text
);
```

RLS 활성화 + 정책 없음(= service role 전용 접근).

### 보안 파라미터

- 유효시간 **5분**, 코드 **6자리**(`crypto.randomInt`).
- 검증 실패 **5회** 초과 시 코드 소각.
- 발송 서버측 쿨다운 **60초**, 시간당 최대 **10건**.
- 저장은 원문이 아니라 `SUPABASE_SERVICE_ROLE_KEY`를 키로 한 HMAC-SHA256. 6자리는 평문 해시면 전수 대조가 자명하므로 pepper가 필요하고, 새 환경 변수를 늘리지 않기 위해 기존 서버 전용 키를 재사용한다.
- 비교는 `crypto.timingSafeEqual`.
- 발급 즉시 이전 미사용 코드는 소각(항상 최신 1건만 유효).

## 리스크

- **Vercel 서버리스에서 Gmail SMTP(465) 연결.** 아웃바운드 TCP는 허용되지만 콜드스타트 시 발송에 1~3초 걸린다. 만약 차단·타임아웃이 확인되면 Resend 같은 HTTP 메일러로 교체한다(교체 지점은 `admin-mailer.ts` 한 파일).
- **Gmail 계정 의존.** 앱 비밀번호가 폐기되거나 계정 보안 조치가 걸리면 관리자 로그인이 막힌다. 복구 수단은 이 문서와 컨텍스트 노트에 남긴 env 재등록 절차.
- **자체 발송으로 Supabase의 기본 rate limit 보호가 사라진다.** 위의 서버측 쿨다운·시간당 한도로 대체한다.

## 완료 기준

1. `npm run lint`, `npx tsc --noEmit` 통과.
2. 로컬에서 `admin` 입력 → 메일 수신 → 5분 내 입력 시 `/admin` 진입.
3. 만료(5분 경과) 코드 거부 확인.
4. 이미 쓴 코드 재사용 거부 확인.
5. 발급된 세션 JWT의 `amr`에 `otp`가 있어 `/api/admin/*`가 통과.
6. Supabase 전역 `mailer_otp_exp`는 86400 그대로.
