# 확인시험 의뢰서 감독서명 컨텍스트 노트

## 2026-07-15

- 확인시험 의뢰서 서명 저장 컬럼은 기존 `quality_verification_requests.sender_signature`를 그대로 사용한다.
- 일괄서명 레지스트리에 이미 `quality_verification_request` 대상이 등록되어 있으므로 새 API나 데이터베이스 마이그레이션은 만들지 않는다.
- 권한은 실시대장과 동일하게 페이지의 사용자 역할이 `발주청`일 때만 UI를 노출한다.
- 기존 직접 작성 폼의 서명 기능은 유지하고, 목록 일괄 감독서명 모달 상태와 분리한다.
- 이미 `sender_signature`가 있는 의뢰서는 선택 불가로 처리해 기존 서명을 덮어쓰지 않는다.
- 엑셀 내보내기는 이미 `addSignatureImage`로 보냄 행에 이미지를 추가하므로 실제 셀 좌표가 감독 이름 오른쪽에 놓이는지 검증 후 필요한 경우에만 조정한다.
- 기존 일괄서명 레지스트리에서 `quality_verification_request`가 시공사 그룹에 잘못 속해 있었다. 새 UI가 `signer: supervisor`로 정상 처리되고 시공사가 감독 서명을 할 수 없도록 감독 그룹으로 이동했다.
- 메모리에서 실제 엑셀 내보내기 함수를 실행한 결과 보냄 텍스트는 `E6`, 서명 이미지는 같은 행의 0-based `col 5.6`, 크기 70×26으로 생성되었다. 따라서 내보내기 파일은 수정하지 않았다.
- 대상 파일 ESLint, 전체 `npx tsc --noEmit`, `git diff --check`를 통과했다.
- Chrome의 로컬 앱 탭은 인증 세션이 없어 `/login`으로 이동했으므로 실제 UI 저장 시나리오는 실행하지 않았다. 운영 데이터 보호를 위해 임의 서명 저장도 하지 않았다.
