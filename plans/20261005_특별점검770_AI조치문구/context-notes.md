# 컨텍스트 노트

- AI 조치 문체를 개조식으로 변경했다. `작업별 유해·위험요인 재검토 및 위험성평가 보완.`처럼 조치 명사와 마침표로 끝내도록 지시하며 서술형/존댓말/예정 종결과 중복 글머리표는 금지한다. 직접 작성한 조치사항은 기존 보존 정책을 유지한다.

- 개발환경 오류 후속 조치. 모든 경로가 500/텍스트 `Internal Server Error`를 반환했고 dev 로그에서 `.next/static/chunks/app/layout.js`의 `UNKNOWN` 읽기 오류를 확인했다. 기존 dev 서버 재시작 후 같은 점검의 실제 Luna 요청이 JSON 200으로 복구됐다. 클라이언트에 비 JSON/빈/null 응답 방어를 추가했으며 관련 테스트 14개, lint와 tsc가 통과했다. 작은 오류 처리 수정이라 Advisor가 직접 처리했다.

- 기존 accident-report의 사용자 JWT 클라이언트 인증, patrol-inspection의 gpt-6-luna strict JSON 및 제한 패턴을 재사용한다. 새 패키지나 스키마 변경은 없다.
- 순수 HWPX builder에는 AI/인증 의존성을 넣지 않는다. 다운로드 준비 시 필요할 때만 인증 모듈을 불러온다.
- 모델에는 실제 result.finding만 전달하며 체크리스트 질문을 지적사항으로 대체하지 않는다. 수기 조치는 그대로 유지한다.
- OpenAI Structured Outputs 공식 문서의 strict schema·refusal 처리, Supabase getUser 공식 문서를 확인했다.
- 워크스페이스의 선행 변경과 미추적 파일을 유지한다. 부모가 독립 리뷰하며 위임 없이 구현한다.
- 부모의 추가 사용자 맥락에 따라 실제 지적의 저장된 예정일은 수기/AI 조치 모두 보존했다. 빈 실제 지적의 조치 칸만 날짜까지 완전히 비운다.
- gpt-6-luna를 고정하고 전용 기능 키 ai.special-770-actions를 인벤토리/사용량 기록에 추가했다. 관리자 설정으로 모델을 바꾸지 않는다.
- API는 20항목씩 순차 생성, 최대 160항목, 배치당 60초/전체 150초, 사용자 동시 1요청/분당 60요청으로 제한한다. 원본 지적 2,000자 초과는 잘라서 추측하지 않고 오류를 반환한다.
- special770 53개 테스트 및 lint/tsc 통과. API 인증/원본 접근/거절/잘림/오류/시간초과/순차 배치, 다운로드 단건·묶음 실제 파일, 사본 불변성, 빈 칸 날짜 누출을 검증했다.
- 부모가 실제 사용자 JWT로 API 성공과 원본 action 미변경, 실제 브라우저 다운로드를 확인했다. Worker는 실제 provider 호출 없이 해당 산출물을 숨김 COM으로 변환했다.
- 한글 COM에서 단일·복수·빈 지적·실제 브라우저 HWPX 모두 정상 열기와 PDF 저장을 확인했다. 전체 페이지 contact PNG 및 결과표 확대를 육안 확인했다.
- 제한사항. 2500 행 높이를 유지하므로 긴 AI 문구 여러 개와 예정일이 겹치면 결과표 전체가 다음 쪽으로 이동할 수 있다. 복수 샘플은 10쪽이며 내용/사진/점검표 누락은 없다. 부모 독립 리뷰에서 범위를 늘리지 않고 기존 레이아웃 동작으로 기록하기로 했다.
