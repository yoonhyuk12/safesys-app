# 계약(공사·용역) 현황 서류철 — 기타 캐비넷

## 배경

프로젝트에는 본 공사 외에 부대 공사·용역 계약이 여러 건 붙는다. 이를 프로젝트 상세의 기타 캐비넷에서 "계약(공사·용역) 현황" 서류철로 관리한다. 내부는 표 형태로 보여주고, 등록은 조달청(나라장터) 계약현황 API에서 불러오는 방식이다. 등록 순서는 공사 → 용역 (사용자 지정). 조회 UX는 지급자재 수불부의 "조달청 일괄 조회" 모달을 참고한다 (사용자 지정).

## API 검증 결과 (2026-07-07 실호출 확정)

- 서비스: 조달청_나라장터 계약정보서비스 (`https://apis.data.go.kr/1230000/ao/CntrctInfoService`)
- 오퍼레이션: `getCntrctInfoListCnstwkPPSSrch`(공사), `getCntrctInfoListServcPPSSrch`(용역)
- 일자 조회: `inqryDiv=1` + `inqryBgnDate`/`inqryEndDate`(YYYYMMDD) — **파라미터명이 번호 조회의 inqryBgnDt와 다름에 주의**
- 기관 필터: `insttNm` 부분일치 (예: "여주.이천지사" → 월 9건). `dminsttNm`/`cntrctInsttNm` 파라미터는 무시됨
- **다개월 범위는 응답 타임아웃** → 월 단위 분할 조회 필수 (수불부 일괄 조회와 동일 패턴)
- `numOfRows` 999 동작 확인. 같은 계약이 중복 행으로 반환됨 → dedupe 필요
- 응답 필드: 공사 계약명 `cnstwkNm` / 용역 `cntrctNm`, `cntrctCnclsDate`(체결일, 빈 값 가능), `totCntrctAmt`, `thtmCntrctAmt`, `cntrctPrd`(자유 텍스트), 공사 `cbgnDate`·`ttalCcmpltDate` / 용역 `wbgnDate`·`ttalScmpltDate`, `cntrctInsttNm`, `dminsttList`/`corpList`(캐럿 구분 — 기관명 idx2, 업체명 idx3), `untyCntrctNo`, `dcsnCntrctNo`(빈 값 가능), `cntrctDtlInfoUrl`(상세 딥링크)

## 범위

1. **DB** `database/20260707-1323_add_project_contracts.sql`
   - `project_contracts` 테이블: project_id FK CASCADE, contract_type('공사'|'용역'), 계약명·번호·업체·금액·일자·기간·기관·URL, created_by, RLS 4정책 (방문일지 패턴)
   - `merge_projects` 함수 갱신: UPDATE 목록에 추가 + 개수 가드 21→22
   - Supabase MCP 읽기전용 → 웹 콘솔 적용 (사용자 액션)
2. **API 라우트** `src/app/api/g2b/cntrct-list/route.ts`
   - GET `?div=cnstwk|servc&inst=기관명&bgn=YYYYMMDD&end=YYYYMMDD` (한 달 단위)
   - 최대 3페이지 × 999건, 정규화 + 라우트 내 dedupe, `{ success, data, error }` 포맷
3. **페이지** `src/app/project/[id]/contract-status/page.tsx`
   - 표: 구분(공사/용역) | 계약명(상세 링크) | 계약상대자 | 총계약금액 | 계약체결일 | 계약기간 | 수요기관 | 삭제
   - 정렬: 공사 먼저 → 용역, 같은 구분 안에서는 체결일 오름차순
   - "조달청 조회" 모달: 구분 탭(공사/용역) + 기관명(관리지사 프리필, '·'→'.') + 기간(월 프리셋은 기간 설정만) + 계약명 검색어(클라이언트 필터) → 월 분할 병렬 조회(진행률) → 체크박스 선택 등록, 등록된 건은 "등록됨" 비활성
4. **기타 캐비넷 진입점** `src/app/project/[id]/page.tsx`
   - "P (계획)" 점선 박스 신설 + DocumentFolder("계약(공사·용역) 현황") + 건수 카운트
