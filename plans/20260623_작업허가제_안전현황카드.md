# 작업허가제(PTW) 안전현황 카드 추가

## 목표
`/safe` 개요 그리드에 "작업허가제(PTW)" 카드 1개를 추가하고, 클릭 시 전용 현황 뷰를 띄운다.
뷰는 안전서류 점검(SafeDocumentView)과 동일한 2단 구조다.
- 본부뷰 = 지사목록 테이블 → 행 클릭 → 지사뷰 = 프로젝트목록 테이블
- 컬럼(두 테이블 공통): 제출건수 / 사인완료 여부 / 비고

## 확정된 결정 (사용자 답변 2026-06-23)
- 사인완료 판정 = **모든 서명란 작성 완료**. 허가서 종류별 필수 signRoles(PERMIT_TYPE_CONFIGS) 전원의 `signatures[role].signature`(base64)가 비어있지 않으면 완료.
- 시간 범위 = **연도 필터만** (분기 없음). 상단에 연도 선택.
- 비고 컬럼 = **빈 칸**(수동 메모용 placeholder, 저장 로직 없음).
- 집계행(지사/프로젝트)의 사인완료는 "완료 N / 전체 M" 카운트로 렌더.
- 데이터 권한/대상 = 발주청 전용 (다른 안전 카드와 동일 패턴).

## 미해결/주의
- 제출건수 시간기준은 `created_at`(제출 시각, null 없음)으로 연도 필터. `permit_date`는 null 가능성이 있어 제외.
- signatures(base64) 전체를 fetch → 대량 시 페이로드 부담. 현재는 form_data 제외 select로 경감. 추후 RPC/생성컬럼으로 최적화 여지.

## 후속 수정 (피드백 반영)
1. 프로젝트 PTW 페이지 뒤로가기 returnUrl 처리 — /safe/ptw에서 진입 시 목록으로 복귀.
2. 지사 드릴다운을 URL(`/safe/branch/[지사]/ptw`)로 관리하도록 변경(worker 패턴). SafetyPtwView가 `selectedSafetyBranch` prop으로 viewLevel 초기화 → 프로젝트 PTW에서 돌아오면 그 지사의 **프로젝트 테이블**로 복귀. `/safe/branch/[branch]/ptw/page.tsx` 라우트 추가, 브랜치 라우팅 배열에 'ptw' 추가.
3. PTW 삭제 권한 확장 — 작성자 본인 외 **프로젝트 소유자·공유받은자·발주청**도 삭제. 앱: PtwPermitList `canDelete` prop + page에서 `canManageAll` 계산(role·project.created_by·project_shares 조회). DB: `database/update_ptw_permits_delete_policy.sql` (사용자가 Supabase 콘솔에서 실행 필요 — 미적용 시 비작성자 삭제는 RLS에 막힘).
