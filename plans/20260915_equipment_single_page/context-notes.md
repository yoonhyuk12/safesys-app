# 판단 기록

- 이전 구현은 67mm 안내 그림을 예약하고 여러 쪽으로 분할했다. 사용자의 최신 요구는 한 장이므로 출력 우선순위를 변경한다.
- 원문과 서명을 삭제하거나 표 높이만 강제로 줄이면 실제 한글에서 내용이 잘릴 수 있으므로 글자·줄 간격·사진 크기를 계산에 반영해야 한다.
- 이전 안내 그림 자산 22개와 공통 매핑 및 native 검증 하니스를 재사용한다. 다른 사용자의 품질 기능 변경은 건드리지 않는다.
- Astra 독립 검토에서 핵심 제약을 확인했다. 행 높이를 동일하게 유지하려면 개별 행 높이 합계가 아니라 가장 긴 행 높이 × 항목 수로 계산해야 한다. 건설용 리프트(24항목)가 긴 문장으로 인한 주요 경계 사례이며 준설선은 29항목이다.
- 인쇄용 글자 크기 하한은 8pt로 두고, 내용 높이와 실제 한글 문단 줄 간격을 같은 설정으로 산출한다. 종합 의견의 최소 높이는 3000 HWPUNIT로 보존한다.
- 실제 한글 2022에서 single-page-final 표본 24개(23종 + 일반 비고)를 열고 PDF로 변환했다. 모든 문서가 1쪽이며 원문 471개, 안내 사진·서명 개수와 비율, 하단 경계 검사가 통과했다. 최소 실제 렌더 글자 크기는 8.04pt였다.
- 최초 구현의 개별 행 높이 합산을 검토 중 발견해 최대 행 높이 × 항목 수로 직접 보정했다. 보정 전 일부 행이 한글에서 커져 하단 여백을 침범했고, 보정 후 모든 문서의 행 높이와 하단이 일치했다.
- 격리 브라우저에서 굴착기·덤프트럭·준설선·쇄석기 다운로드가 표 1개를 포함하는지 확인했다. 아주 긴 종합 의견은 한 장 용량 안내를 표시하고 다운로드하지 않는다. 실제 DB 쓰기는 없었다.
- 타입 검사와 변경 출력 모듈 ESLint가 통과했다.
- 최종 장비 점검 테스트 64개가 통과했다. 한 장 출력·23종 보통 비고·8pt 하한·동일 행 높이·각 행의 최소 내용 높이·과도한 분량 거부·동시 생성 번호 분리까지 검증했다.
