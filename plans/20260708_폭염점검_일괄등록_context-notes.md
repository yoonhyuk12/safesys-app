# 폭염점검 일괄 등록 컨텍스트 노트

## 결정 사항과 근거

- **과거 시간별 체감온도 출처**. 단건 등록이 쓰는 `/api/weather-crawl`(초단기실황)은 최근 정각만 제공해 과거 날짜 불가. 기상청 허브 `kma_sfctm3.php`(ASOS 시간자료)를 실호출 검증(2026-07-08, stn=108, 2026-07-07 08~16시 정상 수신) 후 채택. 컬럼(공백 분리 0-based). WS=3, TA=11, HM=13. 결측 `-9`.
- **관측소 선정**. AWS가 아닌 ASOS 주요 관측소 하드코딩 목록(기존 asos-range·historical 라우트와 동일 데이터) + 하버사인 최근접. 기존 라우트들이 이미 목록을 각자 중복 보유하는 패턴이라, 기존 파일 리팩터링 없이 신규 라우트에도 복사(외과적 변경 원칙).
- **체감온도 산식**. weather-crawl의 `calculateApparentTemperature()` 복사 — 기상청 2022.6.2 개정 여름철 산식(Stull 습구온도) + 겨울철 풍속냉각. 단건 등록과 값 산출 방식 일치.
- **API를 날짜 1개 단위로 설계**. 한 요청에 여러 날짜를 넣으면 KMA 순차 호출로 Vercel 함수 타임아웃(기본 10초) 위험. 클라이언트가 날짜별 순차 호출하면서 진행률 표시.
- **측정 시각 규칙**. 시작시각부터 2시간 간격, 종료시각 이하까지 (8~17 → 8,10,12,14,16). 사용자 예시 그대로.
- **중복 방지**. 등록 직전 선택 날짜들의 기존 기록을 조회해 같은 날짜·같은 시(hour)가 이미 있으면 그 시각만 건너뜀. 일괄 등록을 두 번 눌러도 중복 행이 안 생김.
- **결측 시각 처리**. 관측값 없는 시각(예. 오늘의 미래 시각)은 가짜 온도를 넣지 않고 건너뛰고 결과 요약에 표기 — weather-crawl의 "가짜 값 금지" 원칙 유지.
- **나머지 항목 양호 처리**. 5대 기본수칙 5개 + 작업시간 조정까지 6개 boolean 모두 true(O). 관리대장 PDF에서 ×(미이행)가 적색 강조되므로 "양호"는 전부 O로 해석.
- **서명 1회 업로드 공유**. 서명 이미지 1장을 업로드해 모든 행의 `signature`에 같은 URL 저장. 단건 등록의 버킷 폴백 목록(`heatwave-inspections` → `inspections` → `uploads` → `files`) 재사용.
- **사진 없음**. 일괄 등록 행은 `photos: null`. PDF 사진대지는 사진 있는 기록만 캡처하므로 영향 없음.
- **텔레그램 미발송**. 단건은 발주청 텔레그램 알림을 보내지만 일괄은 수십 건 연속 발송이 되므로 보내지 않기로 함.
- **달력 선택 제한**. 일괄 등록 모드에서는 오늘 이하 날짜만 선택 가능(미래 관측값 없음). 기존 기록이 있는 날짜도 선택 허용 — 시(hour) 단위 중복 건너뜀이 안전장치.
- **동의 문구**. "폭염 조치에 대한 모든 책임은 본인에게 있습니다"에 [동의] 버튼 → 기존 `SignatureModal` 재사용.
