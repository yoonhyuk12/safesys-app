# 법적이행 확인 서류철 (안전활동 점검표) 구현 계획

작성일 2026-07-14. 근거 양식: "붙임. 2026년 2분기 경기지역본부 안전활동점검표(경기).xlsx" (시트 2개).

## 목표

프로젝트 캐비넷(프로젝트 대시보드)에 "법적이행 확인" 서류철을 추가한다. 엑셀 안전활동점검표(발주자 시트 + 도급사업 시트)를 웹 폼으로 옮겨 프로젝트마다 분기별로 여/부 체크를 입력·저장할 수 있게 하고, 사업개요는 서버 projects 테이블 기본정보로 자동 채운다.

## 배치 결정

- 캐비넷: **안전(green) 캐비넷의 C(점검) 섹션**. 양식 자체가 "안전활동 점검표"이고 성격이 점검(Check)이므로. (발주청 캐비넷은 롤 게이팅으로 다른 역할에게 안 보여서 제외.)
- 라우트: `/project/[id]/legal-compliance`
- 서류철 라벨: `법적이행\n확인`, `pdcaCategory="C"`, `bottomLabel="사업"`, docCount 뱃지 표시.

## 데이터 모델

새 테이블 `legal_compliance_checks` — 작업계획서(work_plans) JSONB 패턴을 따른다.

```sql
id uuid PK default gen_random_uuid()
project_id uuid NOT NULL references projects(id) ON DELETE CASCADE
check_year int NOT NULL
check_quarter int NOT NULL CHECK (check_quarter BETWEEN 1 AND 4)
form_data jsonb NOT NULL default '{}'
created_by uuid references auth.users(id) ON DELETE SET NULL
created_at / updated_at timestamptz default now()
```

- 엑셀에서 한 지구에 공종별로 행을 추가하는 구조 → 웹에서는 (project, 연도, 분기)당 여러 건 저장 허용(공종별 1건). unique 제약 없음.
- RLS 정책은 `20260707-1323_add_project_contracts.sql`의 project_contracts 정책 스타일을 따른다.
- **merge_projects() 함수의 자식 테이블 목록에 legal_compliance_checks 추가 + 기대 카운트 증가 필수** (최신 정의를 database/*.sql에서 찾아 갱신).

## form_data 구조 (TypeScript)

```ts
type YN = '여' | '부' | '';   // 미기재 허용

interface LegalComplianceFormData {
  overview: {                      // 사업개요 (자동 채움 + 수정 가능)
    hq: string;                    // 본부/사업단   ← projects.managing_hq
    implementer: string;           // 사업시행자    ← projects.managing_branch
    sector: string;                // 사업분야      ← projects.project_category
    subProject: string;            // 세부사업명    (수동)
    districtName: string;          // 지구명        ← projects.project_name
    phase: '기본' | '설계' | '시공' | '';  // 구분 (기본값 '시공')
    discipline: string;            // 공종: 토목/건축/기계/전기/통신/소방 등 (기본 '토목')
    dateBasicSurvey: string;       // 기본조사 실시 (수동)
    dateDesignBid: string;         // 설계입찰 공고 (수동)
    dateContract: string;          // 착공(계약서)  ← 대표계약 project_contracts.start_date
    dateActualStart: string;       // 착공(실착공)  ← projects.construction_start_date
    dateCompletion: string;        // 준공(예정)    ← projects.construction_end_date
    costTotal: string;             // 총공사비 합계(백만원) ← g2b_tot_amt ?? total_budget (원→백만원 반올림)
    costNet: string;               // 순공사비(백만원, 수동)
    costMaterial: string;          // 자재대(백만원, 수동)
    budgetIndustrial: string;      // 산업안전보건관리비(천원, 수동)
    budgetSafety: string;          // 안전관리비(천원, 수동)
    safetyPlanTarget: string;      // 안전관리계획서 대상공종: '①'~'⑧' | '해당없음'
  };
  ownerBasic: {                    // 안전활동 기본사항 (발주자 시트 T~AK열)
    basicLedger:        { applicable: YN; implemented: YN; adequacy: YN };          // 기본안전보건대장
    designLedger:       { provided: YN; applicable: YN; implemented: YN; adequacy: YN }; // 설계안전보건대장(+기본대장 제공여부 공문)
    constructionLedger: { provided: YN; applicable: YN; implemented: YN; adequacy: YN }; // 공사안전보건대장(+설계대장 제공여부 공문)
    designSafetyReview: { applicable: YN; implemented: YN };                        // 설계의 안전성검토
    safetyMgmtPlan:     { applicable: YN; implemented: YN };                        // 안전관리계획서 수립
    coordinator:        { applicable: YN; designated: YN; notified: YN };           // 안전보건조정자 지정
  };
  ownerDetail: {                   // 안전활동 세부사항 (AL~BQ열)
    dailySelfCheck: YN;                          // 일일 자체점검 확인여부(매일/1회)
    riskWorkPermit: {                            // 위험공종 작업허가제
      applicable: YN;
      targetWorks: string[];                     // '①'~'⑨' 다중 체크
      planConfirmed: YN;                         // 작업계획서 작성·확인여부
    };
    workDirector: YN;                            // 작업지휘자 지정여부
    coordinatorActivity: {                       // 안전보건조정자 활동
      multiDiscipline: YN;                       // 복합공종 시행여부
      meeting: YN;                               // 회의(최초·정기) 실시여부(매월/1회)
      jointInspection: YN;                       // 합동점검 실시여부(매월/1회)
    };
    ledgerImplCheck: YN;                         // 공사안전보건대장 이행 - 공사감독 점검(분기별/1회)
    safetyCostCheck: YN;                         // 안전관리비 사용내역확인(분기별/1회)
    industrialCostCheck: YN;                     // 산업안전보건관리비 사용내역확인(반기별/1회)
    educationCheck: YN;                          // 안전교육 이행여부 확인(반기별/1회)
    implMeeting: { applicable: YN; implemented: YN };  // 안전관리실태 이행점검회의
    riskAssessment: {                            // 위험성평가 이행 점검 5항목
      conducted: YN; participants: YN; nearMiss: YN; reduction: YN; sharing: YN;
    };
    smartEquipment: {                            // 스마트 안전장비의 운영
      adopted: YN;
      costTotal: string; costIndustrial: string; costSafety: string;  // 정산액(천원)
      adoptedAt: string;                         // 도입시기(연월)
    };
  };
  isContractedWork: YN;            // 도급사업 해당여부
  contractChecks: {                // 도급사업 안전관리 의무사항 (시트2 T~AB열, 도급사업='여'일 때만 노출)
    qualifiedContractor: YN;       // 적격수급업체 선정
    adequatePeriod: YN;            // 적정공사기간 반영
    safetyManager: YN;             // 안전보건관리책임자 지정
    council: YN;                   // 안전보건협의체 구성
    councilMeeting: YN;            // 정기회의 이행여부(월별/1회)
    contractorPatrol: YN;          // 도급자 작업장 순회점검(2일/1회)
    jointPatrol: YN;               // 합동 작업장 순회점검(2개월/1회)
    evacuationDrill: YN;           // 비상시 대피훈련 실시(반기별/1회)
    infoProvision: YN;             // 안전·보건에 관한 정보 제공
  };
  remarks: string;                 // 비고
}
```

## UI 구성

- 목록 화면: 저장된 점검표를 연도·분기·공종별 행으로 나열(수정·삭제), "새 점검표 작성" 버튼. 기본 분기는 오늘 날짜 기준.
- 작성 화면: 엑셀 순서 그대로 섹션 5개 — ① 사업개요 ② 안전활동 기본사항 ③ 안전활동 세부사항 ④ 도급사업 의무사항(도급사업='여'일 때만) ⑤ 비고.
- 여/부는 세그먼트 토글 버튼(여=파랑/부=빨강 계열, 미선택 회색). 위험공종 ①~⑨는 체크박스 다중 선택.
- 각 항목의 근거법령(엑셀 메모)은 ⓘ 아이콘 툴팁/팝오버로 제공.
- 스타일: 흰 배경, 컴팩트, 내용물 맞춤 폭(사용자 UI 선호 반영). 기존 서류철 페이지 헤더/뒤로가기 관례를 따른다.

## 컨텍스트 노트

- 배치를 "안전 캐비넷 C섹션"으로 정한 이유: 양식이 안전활동 점검표이고 PDCA상 점검(Check) 성격. 발주청 캐비넷은 롤 게이팅 때문에 제외. 사용자가 다른 캐비넷을 원하면 폴더 JSX 이동만 하면 됨.
- 분기(연도+분기) 필드를 넣은 이유: 원본 양식이 분기 단위 제출물("2026년 2분기")이라 덮어쓰면 이력이 사라짐. (project, 연도, 분기)당 공종별 여러 건 허용.
- 안전예산(산안비·안전관리비)·기본조사일·설계입찰공고일·순공사비·자재대는 projects에 없어 수동 입력. 총공사비는 g2b_tot_amt(나라장터 총계약금액) 우선, 없으면 total_budget, 원→백만원 반올림.
- 엑셀의 음영(작성 불필요) 셀 로직은 웹에서는 미기재('') 허용으로 대체. 수식 기반 자동 '여' 판정은 옮기지 않음(수동 체크).
- 값 체계는 원본 그대로 여/부 2값 + 미기재. safe-documents의 '이행/불이행/해당없음' 3값 체계와 다르지만 원본 양식 충실도를 우선함.
