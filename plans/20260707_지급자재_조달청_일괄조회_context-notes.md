# 컨텍스트 노트 — 지급자재 조달청 일괄 조회

- **(7차) 조달수수료 자동 계산.** 근거는 조달수수료 고시(조달청고시 제2025-33호, 2025-12-01 시행, law.go.kr 요율표 이미지 실독) 내자구매 '단가(일반·3자·MAS)' 요율 — 10억원까지 0.54%, 10억 초과분 0.47%, 100억 초과분 0.37% 초과분 체감적용. 체감 요율이라 **납품요구 건 전체 금액으로 산출 후 품목 금액 비례 안분** (`calcG2bFee`/`calcG2bItemFee`). 조달청 등록·일괄 등록·연계 적용 시 자동 입력, 수동 수정 가능. 면제·감경 특례(전체 감경률 최대 20%)는 미반영 추정치 — 고시 개정 시 요율 상수 갱신 필요.

- **(6차) 수불부 표에 인도조건·품대·수수료·합계 컬럼 추가** (발주량 우측). DB는 material_ledger_entries에 dlvr_cndtn·prdct_amt·fee_amt 3컬럼 (`20260707-1151_add_material_ledger_amount_columns.sql`, **사용자 실행 필요 — 실행 전에는 내역 등록/수정·조달청 등록이 insert 오류로 실패**). 합계는 품대+수수료 화면 계산(저장 안 함).
- **품대·인도조건은 조달청 자동, 수수료는 수동.** 품대는 납품요구 상세의 incdecAmt 차수 합산. 인도조건은 품목식별번호(prdctIdntNo)로 종합쇼핑몰 품목 API(다수공급자 getMASCntrctPrdctInfoList → 제3자단가 getThptyUcntrctPrdctInfoList 순, `prdctDlvryCndtnNm`)를 품목별 병렬 조회 — 실호출 확인("현장설치도"). 조달수수료 금액은 어떤 오퍼레이션에도 없음(포함 여부 Y/N만) → 내역 모달 수동 입력.
- **(6차) 표의 잔량은 표시 시점 자동 계산.** 같은 규격 행들의 (반입-불합격-출고) 누적을 현재 행까지 계산해 표시 — 저장된 remain_qty는 행 수정 순서에 따라 낡을 수 있어 표에서는 계산값 사용 (반입·출고가 전혀 없는 발주 행은 '-'). 저장 로직·엑셀 내보내기는 기존 저장값 그대로 (엑셀 반영은 별도 요청 시).

- **(5차 수정) 모달 열 때 자동 조회 제거** (사용자 지정). 검색어(프로젝트명)·수요기관 프리필만 하고, 사용자가 확인 후 조회 버튼을 눌러야 조회 시작. 기간 프리셋 버튼은 명시적 조회 의사로 보고 클릭 즉시 조회 유지.
- **(5차 수정) 정렬 최종형**: 사업명 일치 건 우선(좌측 금색 테두리 강조, 비일치 건은 흐리게 아래 표시) → 납품기한 늦은 순 → 접수일 최신순. 전체 선택은 "사업명 일치 + 미등록" 건만 대상.

- **(4차 수정) "조회 눌러도 무반응"의 원인은 기간 상한.** 착공일 기준 기본 기간이 36개월 상한을 넘는 장기 공사(북내지구 2023-01 착공 = 43개월)에서 자동 조회·수동 조회가 모두 작은 오류 문구만 내고 시작되지 않아 무반응으로 보였음. 상한 60개월로 확대, 기본 기간은 최근 12개월로 클램프(첫 자동 조회 속도 확보), 오늘 기준 6~36개월 프리셋 버튼(클릭 즉시 조회) 추가. 수요기관 미입력도 버튼 비활성 대신 클릭 시 안내 메시지로 변경.
- **(4차 수정) 정렬은 최종납품기한 늦은 순** (사용자 지정). 기한 없는 건은 뒤로, 동률은 접수일 최신순.

- **(3차 수정) 수요기관 기본값은 관리지사 우선.** 북내지구 프로젝트(여주·이천지사)의 연계 계약(2412000104)이 실제로는 "민북지구"(파주지사) 계약이라 계약 기반 프리필이 틀린 수요기관을 띄웠음 — 계약 연계가 잘못될 수 있으므로 SafeSys 원천 데이터인 managing_branch를 우선 사용. 조달청 등록명은 "한국농어촌공사 경기지역본부 여주.이천지사" 형태로 '·'→'.' 변환하면 지사명만으로 부분일치(중간 문자열 매칭 실호출 확인, 월 18건 수준으로 본부 검색보다 가볍고 정확). 지사가 아닌 본부 관리 프로젝트만 계약 수요기관 프리필로 폴백.
- **(3차 수정) 건명 매칭은 OR 부분일치.** 사용자 피드백 "프로젝트명이 모두 포함되어야 하는 건 아니야" — 검색 단어 중 하나라도 포함되면 표시하고 일치 단어 수 많은 순 → 접수일 순으로 정렬.

- **(2차 수정) UX는 프로젝트명 중심.** 사용자 피드백 "프로젝트 명으로 조회를 해야지" — 모달을 열면 수요기관·기간은 자동 결정(계약정보 + 착공월~이번 달)하고 즉시 자동 조회, 검색어 입력란은 프로젝트명으로 프리필해 매칭 건만 바로 보여준다. 수요기관·기간은 보조 조건으로 남김(재조회 버튼).
- **건명 매칭은 공백 무시 + 단어 AND 포함.** 조달청 건명은 띄어쓰기가 제각각("캠프 레드클라우드" vs 프로젝트명 "캠프레드클라우드")이라 양쪽 공백 제거 후 비교. 프로젝트명 말미의 "용역/공사"는 건명에 잘 안 붙어 기본 검색어에서 제거. 일치 0건이면 전체 건수와 함께 검색어 축소 안내.

- **dminsttNm(부분일치)로 검색, dminsttCd는 쓰지 않음.** 계약의 수요기관이 지역본부(D150116)여도 실제 납품요구는 산하 지사 명의로 나가는 경우가 있어, 이름 부분일치가 지사 건까지 잡는다. 코드 정확일치는 이를 놓친다 (2026-07-07 실호출 확인 — 경기지역본부 이름 검색 월 97건 vs 코드 검색 1건).
- **건명(dlvrReqNm) 파라미터는 API가 무시**하므로 키워드 필터는 조회 결과에 대해 클라이언트에서 수행한다. 기본값은 빈 값(전체 표시) — 납품요구 건명에 사업명이 반드시 들어간다는 보장이 없어서 기본 키워드를 넣으면 누락 위험.
- **월 단위 분할 조회.** API가 1개월 초과 범위를 거부(resultCode 07). 클라이언트가 착공월~이번 달의 월 목록을 만들어 동시 3개씩 호출. 서버 라우트는 한 달만 처리(서버리스 타임아웃 회피, 진행률 표시 가능).
- **차수(dlvrReqChgOrd) dedupe는 클라이언트에서.** 변경 차수가 다른 달에 접수될 수 있어 전체 수집 후 dlvrReqNo별 최신 차수만 남긴다.
- **수요기관 프리필**: 프로젝트 `g2b_cntrct_no` → 기존 `/api/g2b/contract` → `dminsttNms[0]`. 실패해도 조용히 넘어가고 직접 입력.
- **등록됨 판정**: materials.dlvr_req_no + material_ledger_entries.dlvr_req_no 양쪽 수집 (연계 모달로 행 단위 연결된 번호 포함).
- **선택 등록은 순차 처리** — 자재 sort_order(realOrder)가 순번 기반이라 동시 insert 시 순번 충돌.
- 검증 시점(2026-07-07)에는 캠프레드클라우드 프로젝트의 수요기관(한국농어촌공사 경기지역본부+지사, 2025-08~2026-07)에 캠프 관련 납품요구가 0건 — 아직 관급자재 발주 전으로 보임. 기능 검증은 타 기관 데이터로 수행.
