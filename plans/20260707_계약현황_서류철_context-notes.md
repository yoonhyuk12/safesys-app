## 2026-07-07 페이지 피드백 반영 (6차) — 계약 단위 한 행 병합 표시

- **"장기계약건으로 등록하고 차수분은 연도 컬럼에만" 요청 반영.** 저장(DB)은 차수별 행 유지(조달청 원형·행별 업데이트 갱신 유지), **표시·집계만 계약 단위로 병합**하는 방식 채택 — 스키마 변경 없음.
- **그룹 키는 계약명(공백 제거)+구분(`nameGroupKey`).** 연차별 차수 계약은 확정·통합계약번호가 모두 달라(실측) 번호로 못 묶는다. 같은 프로젝트 서류철 안에서는 계약명 동일성이 안정적.
- **병합 행 표시 규칙**: 총액·체결일·계약상대자·수요기관·링크 = 최신 차수(체결일 기준, `repr`). 계약기간 = 멤버 최초 착수일 ~ 최종 준공일. 연도 컬럼 = 각 차수 금차가 각자 귀속 연도에 (`yearAmts`, 같은 연도 복수 차수는 합산). 차수 2건 이상이면 계약명 아래 "장기계속 · 차수 N건 병합" 표기.
- **소계 총액의 차수 중복 합산 버그도 함께 해소** — 기존엔 차수 행마다 같은 총액(예: 10,840,000×2)이 더해졌다. 이제 계약당 1회(repr)만 합산. 건수 표시(공사/용역·소계)도 계약 단위.
- **삭제는 그룹 단위** — 차수 포함 N건 confirm 후 `.in('id', members)` 일괄 삭제.
- **조회 모달 체크박스는 같은 계약명의 차수를 함께 토글** — 한 번 체크로 차수 전부 선택돼 "따로따로 등록" 불편 해소. 미등록 건만 대상.
- **기존 등록 건 주의**: `thtm_end_date`가 없는 구버전 행은 연도 폴백(진행 중=올해)이라 차수 2건이 같은 연도로 합산될 수 있음 — "업데이트" 버튼 한 번으로 금차준공일이 채워져 연도별로 분리된다.

## 2026-07-07 페이지 피드백 반영 (5차) — 장기계속계약 차수 구분

- **"같은 계약이 2건씩 조회" 원인은 취소·중복이 아니라 장기계속계약의 차수(연차)별 계약** (실호출 확정: 판부지구 재해예방기술지도 — 12월 건 R25TA0088725201 금차 1,320,000·금차준공 2025-12-20, 1월 건 R26TA0136334700 금차 9,520,000·금차준공 2026-12-20, 금차 합=총액 10,840,000). 계약번호가 서로 다른 별개 계약이라 `latestPerContract`(같은 계약의 변경차수 병합)에 안 걸리는 게 정상 — 걸러내면 안 됨.
- **API 필드**: 금차준공일은 공사 `thtmCcmpltDate`·용역 `thtmScmpltDate`, 장기계속구분은 공통 `lngtrmCtnuDivNm`(값: "신규"/"차수", 실호출 확인). 두 라우트(`cntrct-list`, `contract`) 모두 `thtmEndDate`·`lngtrmDiv`로 정규화해 반환 (additive — 기존 소비자 영향 없음).
- **모달 표시**: `lngtrmDiv === '차수'`면 계약명 옆 amber 배지 "장기계속(차수)" + title 툴팁. 메타 줄은 금차준공≠총준공일 때만 "금차준공 X · 총준공 Y"로 분리 표기 (같으면 기존 "준공 Y" 유지 — 단년 계약 노이즈 방지).
- **연도 귀속 규칙 변경**: `contractYear`는 `thtm_end_date`가 있으면 그 연도를 그대로 사용 (차수분 준공 연도 = 귀속 연도). 없는 행(직접 등록·구버전 등록 건)은 기존 폴백 유지 — 총준공 지난 계약은 준공 연도, 진행 중이면 올해. 이로써 12월 차수분 1,320,000이 25년 컬럼, 1월 차수분 9,520,000이 26년 컬럼으로 정확히 배치됨.
- **DB**: `project_contracts.thtm_end_date DATE` 추가 (`20260707-1503` 마이그레이션, 사용자 실행 필요). 등록·일괄 갱신(fill-if-present) 모두 저장. **마이그레이션 전에 배포하면 insert에 없는 컬럼이 포함돼 등록이 실패하므로 마이그레이션 먼저.**

## 2026-07-07 페이지 피드백 반영 (4차)

- **프로젝트 나라장터 연계 계약은 목록에 무조건 포함** (사용자 지정, 수정 폼 연계 박스 기준). 서류철 페이지 로드 시 `projects.g2b_cntrct_no/g2b_ntce_no`가 있고 목록에 매칭되는 행이 없으면 `/api/g2b/contract` 최신 차수(contracts[0])로 자동 등록. 모듈 스코프 `linkSyncTried` Set(`projectId|번호` 키)으로 StrictMode 이중 실행·재방문 중복 insert 방지 — 번호가 바뀌면 키가 달라져 재동기화됨. 실패는 조용히 무시(계약번호 탭 수동 등록 경로 존재).
- **차수(회차) 중복 노출 방지 — 조회는 무조건 최신 차수만** (사용자 확인 질문에서 도출). 기간 조회에서 원계약·변경계약이 다른 달에 걸리면 별개 행으로 수집되던 것을, 딥링크의 `ctrtNo`(계약 판별)+`ctrtChgOrd`(차수 비교, 폴백은 체결일)로 묶어 최신 차수만 남김(`latestPerContract`). 계약번호 조회 결과에도 동일 적용. 업데이트 버튼·연계 자동 등록은 원래 contracts[0](최신)만 사용.
- 조회 응답 매핑을 `contractRespToItem`/`itemToRow` 공용 헬퍼로 정리 (번호 조회·연계 자동 등록·선택 등록이 공유).

## 2026-07-07 페이지 피드백 반영 (3차)

- **계약번호 등록 건의 링크가 나라장터 홈으로 가던 문제**: `/api/g2b/contract`가 `cntrctInfoUrl`(홈)만 반환하고 상세 딥링크 `cntrctDtlInfoUrl`을 매핑하지 않았음. 라우트에 필드 추가(기존 소비자에 영향 없는 additive), 페이지는 딥링크 우선 사용. 홈만 가리키는 URL은 링크로 렌더하지 않는 방어 추가(`isDetailUrl`).
- **기등록 건이 조회에서 다시 선택되던 문제**: 같은 계약이라도 조회 경로(기간/번호)마다 `untyCntrctNo`가 다르고 목록 응답의 `dcsnCntrctNo`는 빈 값이 많아 번호 매칭이 놓침. **딥링크 URL의 `ctrtNo`(기본 계약번호, 차수·경로 무관 동일)를 판정 키로 추가**하고, 결합형 확정계약번호(13자리+)는 차수 2자리를 뗀 기본번호도 키로 등록.
- **업데이트(일괄 갱신) 버튼** (사용자 지정, 추가 버튼 좌측): 계약번호가 있는 등록 건을 순차로 `/api/g2b/contract` 재조회해 최신 차수 기준 금액·기간·업체·번호·딥링크를 갱신. 조회값이 빈 항목은 기존 값 유지(fill-if-present). RLS로 작성자 외 행은 갱신 불가 — 실패 목록에 표시. 홈 URL로 저장된 기존 행도 이 버튼으로 딥링크 보정됨 (service-role 직접 UPDATE는 권한 정책상 미실행).

## 2026-07-07 페이지 피드백 반영 (2차)

- **헤더 버튼 "조달청 조회" → "추가"** (사용자 지정). 모달 제목도 "계약 등록"으로.
- **모달 상위 탭 [직접 등록 | 조달청 조회] 신설** (사용자 지정). 기본 탭은 직접 등록 — 지급자재 등록 모달의 '직접 입력' 기본과 동일 관례.
- **조달청 조회 서브탭 [공사 | 용역 | 계약번호]** (사용자 지정). 계약번호 탭은 기존 `/api/g2b/contract` 재사용 — 확정계약번호·공고번호·통합계약번호 자동 판별, 공사/용역 구분은 응답 `bsnsDivNm`에 '용역' 포함 여부로 분류(물품·외자는 프로젝트 성격상 배제하고 공사로 폴백). 계약번호 결과에는 계약명 검색어 필터를 적용하지 않음(프리필 검색어가 단건 결과를 숨기는 사고 방지).
- **직접 등록 폼**: 구분/계약명(필수)/계약상대자/수요기관/총·금차계약금액(쉼표 자동)/체결·착수·준공일. 조달청 미등재 계약 대응.
- **표 소계행**: 헤더 아래 첫 행에 소계(N건) + 총액·금차 합계. 금차는 별도 컬럼 분리 (사용자 지정).
- 조회 결과 메타 줄에 준공일 표시 (공사 ttalCcmpltDate·용역 ttalScmpltDate — 목록 응답에 포함 실측 확인).

## 2026-07-07 페이지 피드백 반영 (1차)

- **검색어도 조회 조건으로 함께 적용** (사용자 피드백 "이것과 여기가 함께 조회 되어야지"). 계약현황 API는 납품요구 목록과 달리 **계약명 서버측 필터를 지원** — 공사 `cnstwkNm`, 용역 `cntrctNm` (실호출 확인: 여주.이천지사 3월 9건 → cnstwkNm=백사지구 1건). 단 **원문 부분일치**라 두 단어("백사지구 자동화")는 어순 불문 0건 — 그래서 검색어가 한 단어면 서버로 전송하고, 여러 단어면 서버 전송 없이 조회 후 클라이언트 단어별 OR 부분일치로 거른다 (건명 띄어쓰기 편차 대응 — 수불부 일괄 조회의 교훈 재사용).
- 기관명·검색어 입력란에 Enter로 조회 실행 추가.
- **API 응답 지연**: 계약현황 API는 첫 호출이 25초를 넘기는 경우가 실측돼 라우트 타임아웃을 40초로 상향 (납품요구 목록은 25초).
- **중복 행 dedupe 키는 표시 필드 기준** (계약명+체결일+총액+업체). untyCntrctNo 기준으로는 같은 계약이 번호 변형으로 중복 반환돼 걸러지지 않음 (실측: 여주.이천지사 3월 9행 → 8건).

## 2026-07-07 설계 결정

- **PPSSrch 일자 조회 파라미터는 `inqryBgnDate`/`inqryEndDate`** (실호출 확정). 번호 조회에서 쓰던 `inqryBgnDt` 형태나 `insttDivCd`+`insttNm` 조합, `dminsttNm` 등은 전부 resultCode 08 "필수값 입력 에러" 또는 무시. 기본 오퍼레이션(getCntrctInfoListCnstwk)은 반대로 `inqryBgnDt`(YYYYMMDDHHMM)를 받지만 기관 필터가 없어 채택하지 않음.
- **기관 필터는 `insttNm` 부분일치 하나뿐.** 계약기관·수요기관 어느 쪽 매칭인지 구분 파라미터 없음 — 농어촌공사 지사는 계약기관=수요기관이 일반적이라 실용상 문제 없음. "여주.이천지사"만으로 월 9건 수준.
- **다개월 범위는 API가 거부하지 않고 타임아웃**(40초+) — 수불부 일괄 조회처럼 클라이언트에서 월 단위 분할, 동시 3개 호출로 구현. 서버 라우트는 한 달만 처리 (같은 달 검증 포함).
- **등록 키는 `untyCntrctNo` 우선.** 신형 계약은 `dcsnCntrctNo`가 빈 값인 경우가 있어(실측) 등록됨 판정·dedupe는 untyCntrctNo → dcsnCntrctNo → 계약명+체결일 순 폴백.
- **목록 응답만으로 등록** — 수불부처럼 단건 상세 재조회가 필요 없음(목록 행에 금액·기간·업체 등 전부 포함). 선택 등록은 supabase 직접 insert.
- **공사 → 용역 표시 순서** (사용자 지정): 표 정렬은 contract_type '공사' 우선, 그 안에서 체결일 오름차순.
- **기간 프리셋은 기간 설정만** — 수불부 일괄 조회의 최종 결정(9d41960)을 그대로 따름. 조회는 조회 버튼으로만.
- **기타 캐비넷에 "P (계획)" 점선 박스 신설.** 기존에는 "C (점검)" 박스(방문일지)뿐인데 계약 현황은 점검 서류가 아니라서 계획 그룹을 새로 만듦. bottomLabel은 "계약".
- **수기 등록·수정 폼은 이번 범위에서 제외** — 사용자 요청이 "조달청에서 불러올 수 있게"라서 조회 등록 + 삭제만. 금액 등 보정 필요 시 후속.
- 조달청 계약현황 목록의 **같은 계약 중복 행**(untyCntrctNo 변형)은 라우트에서 dedupe.
- DATA_GO_KR_API_KEY는 Vercel Preview/Production에 등록 확인 (2026-07-06자 등록, vercel env ls 확인).
