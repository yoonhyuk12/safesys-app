# 관리자 페이지 (가입자·프로젝트 등록 현황 관리)

## 목표

admin 계정으로 (1) 가입자(사용자) 인증·정보 관리와 (2) 프로젝트 등록 전체 현황 관리를 할 수 있는 관리자 화면을 safesys-app 안에 `/admin` 섹션으로 추가한다.

## 핵심 결정

- **별도 사이트가 아닌 기존 앱 내 `/admin` 라우트.** Supabase 인증·배포 파이프라인을 재사용한다. 별도 배포가 필요해지면 나중에 분리한다.
- **관리자 판별은 `ADMIN_EMAILS` 환경 변수(서버 전용, 콤마 구분 허용목록).** `user_profiles`에 `is_admin` 컬럼이 없고, DDL 마이그레이션은 사용자 실행이 필요해 차단 요인이 된다. env 방식은 즉시 동작하며 추후 컬럼 방식으로 전환 가능.
- **보안 경계는 서버.** 모든 `/api/admin/*` 라우트는 Bearer 토큰 → `supabaseAdmin.auth.getUser` → 이메일 허용목록 검증(`requireAdmin`)을 거친다. 클라이언트 가드(`/admin` 레이아웃)는 UX용이다.
- **프로젝트 삭제는 기존 `/api/projects/[id]/delete` 재사용.** Storage 사진 정리 로직이 이미 있으므로 직접 DELETE 금지.

## 작업 분할 (병렬, Orca 오케스트레이션 · codex 워커)

- **골격 (Advisor 직접)** — `src/lib/admin-auth.ts`, `/admin` 레이아웃·가드, `/api/admin/me`.
- **Worker A — 가입자 관리** — `/api/admin/users*` + `/admin/users` 페이지 (목록·검색·필터, 이메일 인증 처리, 프로필 수정, 계정 삭제).
- **Worker B — 프로젝트 등록 현황** — `/api/admin/projects` + `/admin/projects` 페이지 (집계 카드, 목록·검색·필터, 상세 링크, 삭제).

## 검증 기준

- `npx tsc --noEmit`·`npm run lint` 통과.
- 비관리자 토큰으로 `/api/admin/*` 호출 시 403.
- diff 검토 후 의미 단위 커밋.
