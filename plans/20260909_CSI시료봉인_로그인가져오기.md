# CSI 시료봉인 목록 로그인 가져오기 — 계획서 (2026-09-09)

## 요청
품질시험 실시대장의 "CSI 성적서" 버튼을 누르면 CSI 아이디·비밀번호 입력이 뜨고, 로그인 뒤
CSI 시료봉인 목록(`/cmq/qtr/sample/sealng/sampleSealngList.do`)의 시험정보를 가져와 등록 폼에 프리필한다.
기존 공개 성적서 검색(로그인 불필요)은 두 번째 탭으로 유지한다.

## 실측으로 확정한 CSI 프로토콜 (2026-09-09, Advisor 직접 curl/Node 검증)
- 로그인: `POST https://gcloud.csi.go.kr/cmq/com/loginProc.do`, form-urlencoded.
  필드 `userId`, `pswd`(평문, 암호화·캡차·키보드보안 없음), hidden `nextUrl=/qtr/sample/sealng/sampleSealngList.do`, `bbsId=`, `bbsNo=`, `caseNo=`, `reprtSeq=`.
  사전 GET 없이도 된다. Node 기본 fetch(UA=node)도 통과한다(curl 기본 UA만 WAF가 400 "Request Blocked").
  - 성공: `302` + `Location: https://gcloud.csi.go.kr/cmq/qtr/...;jsessionid=...`, `Set-Cookie: WMONID=...; Path=/` 와 `JSESSIONID=...; path=/cmq`.
  - 실패: `200` + `<script>alert('아이디를 찾을 수 없습니다.') history.back();</script>` (본문 UTF-8). alert 문구를 그대로 사용자에게 보여준다.
- 목록: `POST .../sampleSealngList.do` (쿠키 필요). 파라미터 `pageCount`(1부터), `searchKey=cstrnNm`, `searchVal`, `onlyInst=N`, 나머지(`sortCol,sortDesc,excelYn,startYmd,endYmd,sealSttsCd,pourCd,smpslSeCd,smpslNo`)는 빈 값. 응답은 전체 HTML(UTF-8), 10행/페이지, `총 40\r\n 개` 형태의 총건수, 페이저 `goPage(n)`.
  - 행: `tr.odd.gradeX` → `a.goSelectLink[data-smpslNo]`(No), td 순서 = No, 성과이용목적, 구분, 공사명(`title` 속성에 전체 이름), 시료봉인명(`title`), 참관자, 봉인자, 봉인일, 시료상태.
  - 0건: `등록된 자료가 없습니다` 문구 + 총 0 개. 비로그인/세션만료: 200이지만 `name="loginForm"` 이 있고 결과 테이블이 없다.
- 상세: `POST .../sampleSealngView.do` with `smpslNo` (+ 목록 폼 필드). 전체 HTML. `<table>` 마다 `<caption>`:
  - `시료정보 테이블입니다.`(1번째) → 시료봉인번호·시료봉인 상태·성과 이용 목적·등록기관·시료봉인 구분
  - `사업정보 테이블입니다.` → 공사명·착공일·준공예정일·발주자·시공자
  - `시료정보 테이블입니다.`(2번째) → 시료봉인명·봉인일·채취자/봉인자/참관자(소속·성명·담당업무)
  - `시료종별 정보 테이블입니다.` → 시험분류(`토목 &gt; 도로공사 &gt; 흙, 혼합골재`)·시험종별
  - `시험종목정보 목록 테이블입니다.` → 기준 카탈로그(고유번호·시험·검사종목·시험·검사방법) — 실제 수행 종목이 아니라 종별 전체 목록
  - 이후 `시료정보 테이블입니다.` N개 → 시료 1건씩: 시료명·시료구분·생산국·제조사·규격·채취장소·채취일·채취량·시료설명
  - `봉인사진정보 테이블입니다.`, `... 반려사유 ...` 는 무시
- 로그아웃: `POST /cmq/com/logoutProc.do` → 302. 조회 끝나면 호출해 세션을 닫는다.

## 설계
### 서버
- `src/lib/quality/csi-session.ts` — `loginCsi(userId, password)` → `{ cookie }` 또는 `CsiLoginError(message)`. 쿠키는 Set-Cookie 들의 `name=value` 만 모아 `Cookie` 헤더로 보낸다(둘 다 /cmq 하위에서 유효). `logoutCsi(cookie)` 는 실패해도 무시.
- `src/lib/quality/csi-sample-seal-types.ts` — `CsiSampleSealRow`, `CsiSampleSealDetail`(+`samples[]`, `catalog[]`), 응답 타입.
- `src/lib/quality/csi-sample-seal-scrape.ts` — `parseSampleSealList(html)`, `parseSampleSealDetail(html)`, `fetchSampleSeals(cookie, {constNm?})`(최대 10페이지·100행, 순차), `fetchSampleSealDetail(cookie, smpslNo)`. 기존 `csi-scrape.ts` 스타일(cheerio, `CsiParseError`, 상한 상수)을 따른다. 세션만료(loginForm 존재)는 별도 오류.
- `src/app/api/csi/sample-seals/route.ts` (POST `{userId,password,constNm?}`) 와 `src/app/api/csi/sample-seals/detail/route.ts` (POST `{userId,password,smpslNo}`). 둘 다
  SafeSys Bearer 토큰 검증(`supabaseAdmin.auth.getUser(token)`, ai/risk-row 패턴) → CSI 로그인 → 조회 → 로그아웃 → JSON. `maxDuration = 60`. 로그인 실패는 400 + CSI alert 문구. 비밀번호는 어떤 로그·응답에도 남기지 않는다. 재시도 없음(계정 잠금 방지).
- 세션을 서버에 보관하지 않는다(Vercel 서버리스). 호출마다 로그인하며, 자격증명은 모달 상태에만 있고 닫으면 버린다.

### 클라이언트
- `CsiReportImportModal.tsx` — 상단 탭 2개: `시료봉인 목록 (CSI 로그인)`(기본) / `발급 성적서 검색`(기존 UI 그대로). prop `onImportSampleSeal` 추가.
- 새 `CsiSampleSealImport.tsx` — 1단계 로그인 폼(아이디·비밀번호, `autoComplete="off"`, Enter 제출, 안내 "비밀번호는 저장되지 않으며 CSI 로그인에만 사용됩니다"), 2단계 목록(공사명 필터 입력은 클라이언트 필터, 행마다 `가져오기` → 상세 API → `onImport(detail)`), 오류·로딩 상태. 디자인 시스템 클래스 사용.
- `QualityTestRecordsTab.tsx` — `handleCsiSampleSealImport(detail)` 프리필:
  - `test_date` = 봉인일, `test_category` = `COMMISSIONED_TEST_CATEGORY`, `target_material` = 시험종별(없으면 시료봉인명), `supplier_factory` = 첫 시료 제조사, `test_place` = 시료가 1개면 그 채취장소, 여러 개면 빈 값, `note` = `CSI 시료봉인 {번호} ({시료상태})`.
  - 항목 = 시료 1건당 1행: `test_item` = 시료가 1개면 시료봉인명, 여러 개면 `{시료봉인명} - {채취장소}`; `test_standard` = 카탈로그에서 종목명이 시료봉인명(끝의 '시험' 제거·공백 무시)과 일치하면 그 시험·검사방법, 아니면 빈 값; `test_result` = 빈 값(의뢰 단계라 결과 없음); 시료 0건이면 빈 항목 1행.
  - 기존 `handleCsiImport` 와 같은 후처리(폼 열기, 모달 닫기).
