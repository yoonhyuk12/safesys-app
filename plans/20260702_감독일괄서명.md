# 감독 일괄서명 기능 계획

작성일: 2026-07-02

## 목표

프로젝트 상세의 **발주청 캐비넷**에서 감독(공사감독원)이 이 프로젝트에서 서명해야 할 미서명 건들을 한 화면에서 보고, 전체/부분 선택해 일괄 서명한다.

## 스키마 조사 결과 (감독 서명 대상)

실제 DB(information_schema) + 코드 라벨 조사로 판별한 **일괄서명 대상 5종**.

| 테이블 | 서명 컬럼 | 근거 | 미서명 판정 |
|---|---|---|---|
| manager_inspections | signature | 발주청 지사현황(SafetyManagerView)에 기존 일괄서명 존재 | has_signature = false (GENERATED 컬럼) |
| tbm_safety_inspections | signature | TBMStatus에 "공사감독 서명" 모달 | null 또는 '' |
| inspection_requests | supervisor_signature | 폼 라벨 "공사감독원" | null 또는 '' |
| quality_test_records | supervision_engineer_signature | 건설사업관리기술인(감독) | null 또는 '' |
| quality_summary_reports | confirmer_signature | 확인자(감독소장) | null 또는 '' |

**제외 및 사유**
- safety_inspections.signatures — 이름·직급이 지정된 서명자 JSONB 배열(공사감독원 role 포함)이지만 개인 지정 서명이라 개별 문서에서 서명
- ptw_permits.signatures — permitter/confirmer 서명은 허가·이행확인 "행위"라 일괄 처리 부적합
- heat_wave_checks.signature — 점검자 서명(Storage URL 방식)
- headquarters_inspections.signature — 본부 점검자 서명 (지사 감독 아님)
- new_worker_orientations.manager_signature — 확인자(시공사 관리자) 서명
- quality_verification_requests.sender_signature — 보냄(시공자) 서명

## 설계

1. **API** `src/app/api/supervisor-bulk-sign/route.ts` (service-role)
   - 대상 테이블들의 UPDATE RLS가 created_by 본인 한정이라 감독 계정 직접 update 불가 → 기존 `/api/projects/merge` 패턴(Bearer 토큰 인증 + role='발주청' 확인) + supabaseAdmin으로 갱신
   - body: `{ project_id, signature_data(base64 PNG), items: { <type>: id[] } }` — 타입 화이트리스트 5종만 허용
   - 안전장치: `.eq('project_id', ...)` + 미서명 조건을 update WHERE에 포함해 기존 서명 덮어쓰기 방지
2. **모달** `src/components/project/SupervisorBulkSignModal.tsx`
   - 열릴 때 5종 미서명 목록 병렬 조회 (base64 컬럼은 select하지 않음 — 용량)
   - 종류별 섹션 + 항목 체크박스, 전체선택/섹션별 전체선택
   - "서명하기(N건)" → 기존 `SignaturePad` 컴포넌트로 서명 1회 입력 → API 호출 → 재조회
3. **진입점**: 발주청 캐비넷 C(점검) 그룹에 "일괄 서명" 서류철 추가 (발주청 사용자만 보이는 캐비넷이므로 별도 게이팅 불필요)

## 구현 단계

1. API 라우트 → 2. 모달 컴포넌트 → 3. 캐비넷 서류철 연결 → 4. lint/tsc → 5. 커밋
