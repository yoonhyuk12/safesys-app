# 컨텍스트 노트

- 사용자 지적 대상은 프로젝트 상세 우측 나라장터 갱신 버튼이다.
- `handleG2bSync`는 최신 계약 착공일과 선택적 공고 조회의 최솟값을 저장한다. 기존 전체 착공일은 조회값이 전혀 없을 때만 유지된다.
- API는 총 준공일(`ttalCcmpltDate`/`ttalScmpltDate`)과 금차 준공일을 구별해 반환한다. 연차 계약의 착공일은 별도 검토가 필요하다.
- 기존 유틸리티와 `test:g2b`를 재사용한다. 새 패키지 또는 범용 구현 탐색이 필요하지 않은 프로젝트 내부 데이터 선택 오류다.
- 별도 superpowers 스킬은 세션 카탈로그에 없으므로 계획·재현 테스트·직접 diff 검토 절차를 적용한다.
- 실제 용담지구는 대표계약 선택으로 공고번호가 비어 있다. 최신 `R26TA0138828601`의 착공/총준공/금차준공은 2026-02-02/2026-12-18/2026-12-18이다. 원차수도 공고번호가 없어 공고 재조회만으로 해결되지 않는다.
- 프로젝트에 저장된 동일 대표 토목공사 2024·2025·2026년 계약의 전체 범위는 2024-06-17~2027-03-18이다. 다른 용역은 집계에서 제외한다. 기존 계약현황의 그룹 규칙을 재사용한다.
- 브라우저의 기존 로그인 Supabase 클라이언트로 해당 프로젝트 계약만 SELECT하여 확인했다. 키·세션 값을 출력하지 않았다. Supabase select 공식 문서 및 changelog를 확인했으며 스키마·인증 변경은 없다.
- Worker의 재현 테스트 실패 후 구현을 확인하고 Advisor가 diff·`npm run test:g2b` 11건·`npm run lint`·`npx tsc --noEmit`·`git diff --check`를 직접 검증했다. 린트 기존 경고만 있으며 종료코드는 0이다.
- 실제 사용자 화면의 갱신 버튼을 실행해 2024-06-17~2027-03-18로 복원됨을 확인했다. 총액 5,867,336천원·금차 3,160,786천원·대한건설 주식회사는 유지됐다.
- 외부 API 응답 정규화는 변경하지 않는다. 전체기간은 기존 확보 범위를 보존하므로 자동 갱신으로 기간을 단축하지 않는다.
- 갱신 후 `projects`를 재조회하여 전체 착공·준공일 저장을 확인했다. Worker 완료를 수락하고 release를 요청했으며 Orca는 사용자 소유 전환(`user_takeover`)으로 터미널을 유지했다.
