- patrol-ledger-hwpx-export의 템플릿 복사·셀 채우기 패턴과 accident-report-xml의 중첩 XML 스캐너를 재사용한다.
- 기존 patrol-inspection API는 getUser 토큰 검증 후 발주청 프로필 및 isOrganizationInUserScope로 원본 점검 관할을 검사한다.

- 공식 자료 확인. https://developers.openai.com/api/docs/models/gpt-6-luna 및 structured-outputs 가이드, https://supabase.com/docs/reference/javascript/auth-getuser, JSZip loadAsync 문서. Supabase changelog.md 조회는 내부 오류였다.
- 요구서는 표 1개, 계획서는 표 1개, 결과보고서는 제목·본문 표 2개다. 계획 서명란 원문은 유지하고 이름/서명을 생성하지 않는다.
- 원본 문서 보존과 페이지 간 레이아웃 간섭 방지를 위해 일괄은 점검별 HWPX ZIP으로 구현한다.

## 최종 구현 및 검증

- 요구서 점검부서장은 개인명 근거가 없어 공란, 점검종류는 KRC 패트롤 점검, 점검자·점검일·사업명은 실제 기록이다.
- 계획서 왼쪽 요구사항 칸은 실제 지적을 5글자 폭으로 나누며, 오른쪽 칸은 시정조치·재발방지 계획만 넣는다. 양쪽을 독립적으로 분할하여 모든 내용을 보존한다.
- 결과보고서는 지적마다 별도 페이지이며 전후 사진을 해당 지적에 연결한다. 완료 상태 단정 대신 조치사진 등록 여부를 표시하고 실제 완료일은 비운다.
- 한글 COM 실행은 Advisor가 담당했다. 기본 요구서1쪽·계획서1쪽·결과2쪽, 사진결과2쪽(4사진), 장문 요구2쪽·결과7쪽·계획21쪽 모두 Open/SaveAs PDF 성공. 모든 장문 끝표식을 PDF 텍스트로 확인했고 페이지 렌더에서 잘림 없음(2026-10-06 Advisor 보고).
- 브라우저 실제 21건 요구서 ZIP과 계획서 ZIP(실제 gpt-6-luna low, 20+1 배치) 생성 성공(Advisor 검증).
- 표본 재생성은 safesys-app에서 `$env:PATROL_SAMPLE_DIR='C:/Users/User/AppData/Local/Temp/safesys-patrol-review-20261006'; node --test tests/patrol-corrective-hwpx.test.mjs`로 한다. 하니스는 DB/API 키 없이 합성 사진과 시험 데이터만 사용한다.
- 결과표 문단에 '3. 점검자'가 들어가면 전체 표가 치환되던 리뷰 발견은 RED 회귀테스트 후 표 포함 문단을 제외하여 수정했다.
- `npm run lint` exit0(기존 프로젝트 경고), `npx tsc --noEmit` exit0, 기존 `test:patrol` 66개 통과. 최종 신규 테스트 수는 체크리스트에 기록한다.

## 제한

- 원본 계획서의 좁은 요구사항 칸을 보존하므로 긴 지적은 페이지 수가 많아질 수 있다.
- AI 계획은 제출 전 사용자가 검토해야 한다. 실제 완료일·제출일·점검부서장·서명은 추정하지 않는다.
- 다운로드는 전체 결과가 준비된 뒤 한 번만 저장하므로 사진/AI 실패 시 일부 파일만 다운로드하지 않는다. 여러 건의 사진이 매우 많으면 브라우저 ZIP 생성 메모리를 사용한다.
- 분당 요청 제한은 기존 API와 같은 인스턴스 메모리 방식이다. DB나 패키지는 추가하지 않았다.
- 빌드·커밋·푸시는 하지 않았으며 기존 untracked 사고 폴더와 사용방법.md는 그대로 두었다.

- 최종 신규 테스트 37개 통과, 최종 tsc 및 변경 소스 ESLint 무경고 통과. 수신자 조직명+장(본부장·지사장·사업단장) 회귀테스트를 추가했다. 원본 템플릿 3개는 복사본과 SHA-256이 일치한다.

- Advisor가 실제 조치결과보고서도 21건(약11MB) ZIP 생성과 내부21개 항목을 확인했다. 개별행 결과보고서·계획서 HWPX 직접 다운로드와 화면 이동 방지까지 확인했다. 실제 결과보고서는 한글 2쪽에 전후 사진 4개가 정상 표시되었고, 최종 계획서는 1쪽으로 열리며 경기본부장 수신자 문구도 PDF 텍스트로 검증했다.
- Advisor 최종 직접 검증은 신규 테스트 37개·기존 패트롤 66개 통과, 타입 검사 통과, 전체 린트 통과(기존 경고)다. 브라우저 검증용 다운로드 가로채기를 해제하고 처음의 3분기 지사 목록으로 복귀했다. 두 Orca Worker는 결과 검토 후 모두 해제했다.

## 해당 사항 없음 제외 보정

점검 단위로 `getPatrolActionState(row).notApplicable`이 참이면 3종 HWPX에서 제외한다. 지적유형이 해당없음이거나 필요한 조치가 모두 면제인 경우이며, 같은 지구의 다른 유효 점검은 유지한다. AI 호출·문서 생성 전에 필터하고 진행·파일명·완료 건수와 버튼 상태에 반영한다. 엑셀·원본 행·통계·양식·AI API는 유지한다.

추가 요구. 요구서는 지적별 현장사진을 원본 큰 셀에 넣고 지적 단위로 쪽을 나누며 장문은 다음 양식으로 이어 쓴다. 기존 결과보고서 전후 사진은 유지하고 계획서는 텍스트만 출력한다. 기존 TBM 구조 사진 헬퍼를 재사용하며 사진 없는 지적도 유지한다. 한글 COM/PDF·브라우저 확인은 Advisor가 담당한다.
