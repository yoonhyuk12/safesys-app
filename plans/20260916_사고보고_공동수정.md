# 사고보고 공동 수정 권한

사용자가 프로젝트 소유자·공유받은 사용자·관할 발주청이 작성자에 관계없이 사고보고를 수정하도록 요청했다. 해당 프로젝트 접근 여부를 등록과 수정의 공통 기준으로 사용하고, 삭제는 작성자 또는 관할 본부급 이상이라는 기존 기준을 유지한다.

1. 기존 페이지·목록·상세의 수정/삭제 판정을 분리하고 저장 단계에도 적용한다.
2. 아직 운영 미적용인 사고보고 SQL의 UPDATE 정책을 프로젝트 접근 기준으로 바꾼다. INSERT 작성자 검증, 작성자 불변 트리거, DELETE와 외부 미등록 현장 정책은 보존한다.
3. PGlite 권한 테스트 및 UI 회귀 테스트를 먼저 변경하고 구현 후 통과시킨다. 타입검사·린트·독립 리뷰로 검증한다.
4. 권한 문서와 검증 결과를 기록하고 로컬 커밋한다. 운영 SQL 적용과 배포는 이번 작업에서 하지 않는다.

기존 프로젝트 RLS·모달·PGlite 테스트를 재사용한다. 새로운 라이브러리나 API를 만들지 않는다. Supabase RLS 문서에서 UPDATE의 USING/WITH CHECK와 SELECT 정책 필요성을 확인했다. 참고 문서 https://supabase.com/docs/guides/database/postgres/row-level-security .
