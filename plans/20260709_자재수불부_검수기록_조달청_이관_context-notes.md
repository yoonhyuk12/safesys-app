# 컨텍스트 노트 — 자재수불부 검수기록 조달청 이관

## 판부지구 실데이터 (2026-07-09 service-role 조회)

- 자재 11건 전부 수기, `dlvr_req_no` 전무. 모든 행에 반입·불출 기록 있음.
- 같은 규격 다중 행 패턴 — 레미콘(25-21-80) 8행, Φ355 관 4행 등. 행마다 발주량이 달라 "한 행 ≈ 한 납품요구"로 추정되나, 사용자는 자동 매칭 대신 드래그앤드랍 수동 배정을 선택했다.
- 레미콘(25-18-80)은 행이 0개인 빈 자재 — 이관 삭제 대상 아님(원래 비어 있었음).
- 수기 오타 존재("수도용폴레에틸렌관") — 문자열 자동 매칭이 위험한 근거.

## 설계 결정과 이유

1. **자동 매칭(발주량 일치) 제안을 폐기하고 수동 드래그앤드랍 채택** — 사용자 지시. 사용자 발주량 자체를 신뢰하지 않기로 했으므로 발주량 기반 매칭도 성립하지 않는다.
2. **이관 행의 `order_qty`를 null로** — `calcEffectiveOrderQty`는 첫 행 + "발주량만 있는 증감 행"을 합산한다. 이관 행에 발주량이 남으면 위치에 따라 유효 발주량을 오염시킬 수 있고, 사용자 결정("발주량 건너뜀")과도 일치.
3. **이관 행 `created_at` 재부여** — 행 정렬이 created_at 기준(loadData, page.tsx 478행)이라 원래 타임스탬프를 두면 이관 행이 G2B 발주 행보다 앞에 정렬돼 첫 행=발주 행 관례와 반입잔량 누적 계산(calcRunningReceiveRemain)이 깨진다. created_at은 이 화면에서 정렬 키로만 쓰인다.
4. **행 재배치는 UPDATE** — 검수 사진(inspection_photos)·불합격 조치 등 모든 컬럼이 자동 보존된다. INSERT+DELETE 금지.
5. **`name_or_spec`을 조달청 품목 문자열(formatG2bSpec)로 통일** — 수불부 그룹핑·누계·검수조서 출력이 전부 name_or_spec 문자열 일치 기반이라 통일하지 않으면 별개 그룹으로 갈라진다. 수기 오타 규격 문자열은 이관 시 소멸(의도됨).
6. **빈 자재 삭제는 체크박스 + 삭제 직전 DB 재확인** — 남은 행이 있는 자재를 실수로 지우면 CASCADE로 행까지 소실되므로 0건 확인 후에만 삭제.
7. **매핑 화면을 일괄 조회 모달의 2단계로** — 조회→선택→배정→적용이 한 흐름. 기존 "선택 건 등록"(신규 등록만) 버튼은 그대로 유지.
8. **네이티브 HTML5 DnD** — Dashboard·ProjectCard에 기존 사례, 라이브러리 무추가. 터치 대체로 "선택 행 배정" 버튼 병행.
9. **1건=1자재 구조 유지** — insertMaterialFromDlvrReq의 기존 모델(납품요구 1건 → 자재 1건, 품목은 규격 행). 철근 3규격이 한 납품요구면 자재 하나로 합쳐지는데, 이는 G2B 등록의 기존 동작이며 수불부·검수조서 출력이 규격 그룹 기준이라 문제없다.

## 구현 후 검증 기록 (2026-07-09)

- Worker(Opus) 구현 → Advisor 직접 검증 완료. tsc·eslint 대상 파일 오류 0(잔존 오류는 전부 기존 무관 코드), dev 서버 컴파일 HTTP 200.
- `material_ledger_entries`는 RLS `USING (true)`(authenticated 전체 허용)·트리거 없음(20260211-0942_add_material_ledger_tables.sql) — `created_at`·`material_id` UPDATE 제약 없음 확인.
- created_at 재부여 기준은 새 자재 발주 행의 created_at 최댓값(서버 시각) + k초 — 클라이언트 시계 오차와 무관하게 발주 행 뒤 정렬 보장.
- 알려진 한계 — 실적 없이 발주량만 있는 행이 수기 자재에 남아 있으면 그 자재는 빈 자재 삭제 대상에서 빠진다(삭제 전 count 재확인이 0이 아니므로). 판부지구는 모든 행에 실적이 있어 해당 없음. 필요 시 수동 삭제.
- 상세 조회 일부 실패 시 bulkError를 설정한 채 매핑 화면으로 넘어가는데 매핑 화면엔 오류 표시가 없다 — 적용 시 alert로 실패가 다시 보고되므로 수용.

## 함정

- 로컬 dev가 운영 Supabase를 바라본다 — 판부지구에 대한 실제 "이관 적용"은 사용자가 실행. 개발 중 쓰기 테스트는 테스트 프로젝트로.
- `registeredDlvrNos`(page.tsx 719행)가 등록됨 뱃지·중복 방지의 근거 — 이관 적용 후 loadData로 자연 갱신됨.
- 납품요구 상세(/api/g2b/dlvr-req)는 전량 취소 품목(qty 0)을 포함할 수 있음 — 기존 등록 로직처럼 qty>0 품목만 사용.
