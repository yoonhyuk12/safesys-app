# 컨텍스트 노트.

- 사용자가 지목한 버튼은 성과총괄표 확인자 서명이다. 발주청 전체 수정 요청은 해당 품질시험 관리대장 세 탭으로 적용한다.
- 현재 세 탭 모두 작성자 전용 저장 검사다. 성과총괄표와 의뢰서는 UPDATE에도 created_by를 현재 사용자로 덮어쓴다.
- 기존 PTW 정책에 user_profiles의 발주청 역할 검사 패턴이 있다. 이를 재사용한다.
- 발주청의 기존 서명란 소속 제한은 작성 권한과 별개다. 삭제 권한은 기존 정책을 유지한다.
- 전용 worker-opus 모델 및 superpowers 스킬은 현재 도구에 제공되지 않아 제공된 협업 에이전트와 직접 계획·검증으로 진행한다.
- 연결 DB 읽기 확인 결과 세 테이블 UPDATE 정책은 모두 `auth.uid() = created_by`이고, 관련 사용자 트리거는 없다.
- 실시대장 편집 중 세부 항목 제거는 직접 DELETE를 사용하며 DB 정책은 작성자 전용이다. 삭제 정책은 이번 범위에서 확장하지 않고, 권한 없는 제거를 저장 전에 안내해 부분 저장을 막는다.
- Orca 브라우저에서 실제 성과총괄표 확인자 서명창 열기 및 취소를 확인했다. 서명을 대신 작성하거나 실문서를 저장하지 않았다.
- UPDATE 정책 마이그레이션을 앱 URL과 동일한 연결 프로젝트에 Management API로 적용했다. `pg_policies` 재조회로 3종 모두 작성자 또는 발주청 USING/WITH CHECK 적용을 확인했다. DB 이력 버전은 `20260914043806`이다.
- 독립 리뷰에서 발주청이 직접 API로 created_by를 자신으로 바꾼 후 작성자 전용 DELETE를 우회할 가능성을 재현했다. 화면 payload 보존에 더해 DB 직접 작성자 변경 보호를 후속 마이그레이션으로 보완한다. 관리 작업과 사용자 삭제 FK의 SET NULL은 유지한다.
- `20260914-1339_quality_preserve_created_by.sql` 후속 적용 완료. 세 테이블 보호 트리거 존재를 재조회했다. 회귀 26개 통과, 타입체크 통과, 전체 린트는 기존 경고만 있고 exit 0이다.

## 후속 요청 — 서명 삭제 버튼

- 성과총괄표의 서명이 있는 각 칸에 삭제 버튼을 추가했다. 발주청은 세 칸 모두 삭제할 수 있고, 그 외 계정은 문서 작성자이면서 해당 칸 서명 소속에 해당해야 한다. 저장·반려 처리 중에는 삭제 버튼을 비활성화한다.
- 삭제는 해당 서명 필드만 비우고 하단 수정 버튼으로 저장한다. 성명·직위·소속과 다른 칸의 서명은 유지한다.
- 실제 JSX를 실행한 임시 하니스로 발주청·시공사·감리단의 버튼 활성 상태 및 해당 서명만 삭제되는 것을 확인했다. 기존 권한 회귀 20개와 대상 린트·타입체크를 통과했다.
