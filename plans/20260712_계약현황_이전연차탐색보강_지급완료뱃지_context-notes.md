# 컨텍스트 노트 — 계약현황 이전 연차 탐색 보강 + 지급완료 뱃지

## 결정과 근거

- **번호 기반 이전 차수 역추적은 API 차원에서 불가** (2026-07-12 실호출 재확인). 확정계약번호 끝 2자리는 변경차수(`ctrtChgOrd`)이고, 연차별 계약은 번호가 전부 다르며 응답에 연결 필드(ntceNo·reqNo)가 빈 값. → 유일 경로는 기존 `handleRefreshAll` ②의 계약명+수요기관 월별 목록 조회이며, 이번 작업은 신규 구현이 아니라 그 탐색의 갭 보수다.
- **연도 접두·접미 제거를 차수분 계약(총액≠금차)에만 적용** — 무조건 벗기면 "2025년 ○○점검"·"2026년 ○○점검" 같은 별개 단년도 반복 계약이 한 그룹으로 잘못 병합돼 총액·합계가 틀어진다. 장기계속 차수 행은 총액≠금차라는 특성(메모리: 금차합=총액)이 판별 기준.
- **탐색 시작월은 `cntrct_prd` "총공사 N일" 역산** — 원곡 사례: 총준공 2026-12-21 − 1135일 ≈ 2023-11 → 2023-10부터 탐색해 2025-01 체결 이전 연차를 잡는다. `cntrct_prd` 없으면 기존 동작 유지(과거 미탐색) — 눈먼 24개월 역탐색은 호출량 낭비라 배제.
- **기존 36개월 캡(slice(-36)) 유지** — 3년 사업 ≈ 33개월이라 충분. 더 긴 사업은 가장 오래된 구간이 잘릴 수 있음(알려진 한계).
- **대금지급 완료는 수동 토글** — 공공데이터포털 "대금지급" API 0건 확인. 나라장터 대금청구·지급은 당사자 로그인 영역이라 개방 안 됨.
- **지급완료는 그룹 토글·행 단위 저장** — 멤버 전 행에 같은 값을 쓰고, 그룹 완료 판정은 "멤버 전원 완료". 이후 새 차수가 등록되면 그 행이 false → 뱃지 자동 해제(미완 계약으로 복귀)가 자연스러운 의미가 된다.
- **RLS**: `project_contracts` UPDATE는 `created_by = auth.uid()` 행만 허용 — 타인이 등록한 차수 행은 조용히 스킵되므로 `.select('id')` 반환 수로 부분 실패를 감지해 안내한다(기존 업데이트 플로우도 같은 제약).
- **Advisor 직접 구현** — 수정이 단일 파일의 외과적 편집 + 마이그레이션 1건으로, Worker 위임 브리프 작성 오버헤드가 diff보다 크다고 판단.
