# 가입자 관리 — 월별 가입자 현황 그래프

/ admin/users 요약 카드 하단에 최근 12개월 월별 가입자 현황을 역할별 누적 막대 그래프로 추가하고, 정렬 토글을 제공한다.

## 1. 계획 (Plan)

### 배경

`/admin/users`는 현재 전체·발주청·감리단·시공사·미인증 5개 요약 카드만 제공한다. 가입 추세를 시간축으로 볼 수단이 없다.

### 결정 사항 (사용자 확정)

- 그래프 구성 — 최근 12개월, 역할별 누적 막대.
- 정렬 — `월 순 ↔ 가입자 수 순` 토글 + 오름/내림 방향 토글.

### 범위

- 신규 컴포넌트 `src/components/admin/AdminMonthlySignupChart.tsx` 1개.
- `src/app/admin/users/page.tsx`에 `<SummaryCards />` 바로 아래 삽입 1줄.
- API·DB 변경 없음. 페이지가 이미 보유한 `users: AdminUser[]`의 `created_at`·`role`로 클라이언트에서 집계한다.

### 비범위

- 다크 모드 — 이 페이지는 라이트 전용이고 `dark:` 클래스가 없다. 기존 컨벤션을 따라 넣지 않는다.
- 차트 라이브러리 도입 — 프로젝트에 없다. `AccidentAnalysisView.tsx`의 순수 SVG 패턴을 따른다.
- 필터(검색·역할·미인증) 연동 — 요약 카드와 동일하게 전체 `users` 기준 고정 개요로 둔다.

## 3. 컨텍스트 노트 (Context Notes)

### 색상 — 기존 역할 색을 그대로 쓴다

앱 전역에서 역할 색이 이미 고정되어 있다 (`roleBadgeClass`, `ROLE_SUMMARY_META`). 새 팔레트를 만들면 카드/뱃지와 어긋나므로 그대로 승계한다.

| 역할 | 채움색 | 근거 |
|------|--------|------|
| 발주청 | `#2563eb` (blue-600) | 카드/뱃지 blue 계열 |
| 감리단 | `#f59e0b` (amber-500) | 카드/뱃지 amber 계열 |
| 시공사 | `#059669` (emerald-600) | 카드/뱃지 emerald 계열 |
| 미배정 | `#94a3b8` (slate-400) | 중립 회색, `role === null` 방어용 |

색각 검증을 돌렸고 전 항목 통과했다.

```
[PASS] Lightness band / Chroma floor
[PASS] CVD separation   worst #059669↔#f59e0b ΔE 13.0 (protan)
[PASS] Normal-vision floor  ΔE 27.5
[WARN] Contrast vs surface  #f59e0b 2.09 — relief required
```

**앰버 대비 경고에 대한 상쇄 조치.** 범례를 항상 노출하고, 막대 위에 합계를 직접 라벨로 찍고, sr-only 대체 표를 둔다. 색만으로 정보를 전달하지 않게 만드는 것이 목적이다.

### 정렬 — 기존 `sortRows`를 재사용하되 3단계 순환은 쓰지 않는다

`@/lib/admin-sort`의 `sortRows`는 안정 정렬(동점 시 원래 순서 유지)이라 그대로 쓴다. 다만 `nextSortState`의 `asc → desc → none` 3단계 순환은 쓰지 않는다 — 그래프에는 "정렬 없음" 상태가 의미가 없고 항상 월 오름차순이 기본이어야 하기 때문이다. `key`·`direction`이 항상 non-null인 자체 상태를 둔다.

`가입자 수 순`에서 동점 월은 안정 정렬 덕분에 월 오름차순으로 유지된다 — 버킷 배열을 월 오름차순으로 만들어 넘기는 것이 전제다.

### 월 버킷 — 가입 0건인 달도 남긴다

`월 순` 정렬일 때 시간축이 끊기면 추세를 오독하게 된다. 최근 12개월을 빠짐없이 만들고 0인 달은 높이 0으로 둔다.

`created_at`은 UTC ISO 문자열이다. `new Date()`로 파싱하면 브라우저 로컬(KST) 기준이 되는데, 같은 페이지의 `formatDate()`가 이미 로컬 기준이라 표기와 집계가 일치한다. 별도 타임존 보정을 넣지 않는다.

### 역할 미배정 (`role === null`)

현재 데이터는 488 + 3 + 593 = 1,084로 전체와 정확히 일치해 미배정이 0건이다. 하지만 `AdminUser.role` 타입이 `Role | null`이므로 방어적으로 4번째 세그먼트를 두되, **해당 기간에 1건 이상일 때만** 막대와 범례에 나타나게 한다. 0건인데 범례에 회색 항목이 뜨면 오해를 부른다.
