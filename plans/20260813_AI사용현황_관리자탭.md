# AI 사용현황 관리자 탭 — 계획서

작성일 2026-08-13. 요청 — 관리자 콘솔에 "AI 사용현황" 탭을 추가하고 제조사/모델명/위치/기능/비고 테이블을 제공한다. 관리자가 제조사·모델명을 편집할 수 있고, 편집한 모델명은 **실제 서비스가 사용하는 모델에 즉시 반영**된다(사용자 확정). "최신 모델명"은 제공자 API(모델 목록)를 조회 버튼으로 불러와 드롭다운으로 선택한다(사용자 확정).

## 배경

AI 모델명이 20개 라우트에 하드코딩되어 있다(전수 조사 2026-08-13). 공유 상수는 `src/lib/risk-assessment/types.ts:183`의 `RISK_AI_MODELS` 폴백 배열 하나뿐이다.

## 설계

### 1) DB — `ai_model_settings` 테이블 (마이그레이션은 사용자가 직접 실행)

`database/20260813-HHMM_ai_model_settings.sql`

- 컬럼 — `id uuid pk`, `feature_key text unique not null`, `provider text not null`('OpenAI'|'Google'), `model text not null`, `location text not null`(라우트 경로), `feature text not null`(기능 설명), `remarks text`, `sort_order int`, `updated_at timestamptz default now()`
- RLS enable, 정책 없음(서비스 롤 전용 접근 — supabaseAdmin은 RLS 우회, 클라이언트 직접 접근 차단)
- 시드 INSERT — 아래 인벤토리 22행 전부

### 2) 모델 해석 헬퍼 — `src/lib/ai-models.ts`

- `DEFAULT_AI_MODELS` — 22행 기본값 상수(featureKey, provider, model, location, feature, remarks). 시드·폴백·마이그레이션 전 표시용의 단일 출처.
- `getAiModel(featureKey): Promise<string>` — supabaseAdmin으로 조회, 모듈 스코프 캐시(TTL 60초), 실패·미존재 시 DEFAULT 폴백. **테이블이 없어도 기존과 동일하게 동작해야 한다(마이그레이션 전 안전).**
- `getAiModelChain(featureKey): Promise<string[]>` — 위험성평가 계열용. DB 모델을 선두로 두고 기존 `RISK_AI_MODELS`를 뒤에 붙여 중복 제거.

### 3) 라우트 연결 (외과적 — 모델 지정부만 교체)

하드코딩 모델명을 `await getAiModel('<feature_key>')` 호출로 교체. 위험성평가 4개 라우트는 `RISK_AI_MODELS` 순회를 `getAiModelChain()` 결과 순회로 교체. 각 라우트의 기존 모델명은 `DEFAULT_AI_MODELS`의 기본값으로 이동한다.

### 4) 관리자 API

- `GET /api/admin/ai-usage` — 목록. DB 우선, 테이블 없으면 DEFAULT 목록에 `source:'defaults'` 표시.
- `PATCH /api/admin/ai-usage` — `{featureKey, provider, model, remarks}` 업데이트. 모두 `requireAdmin`(`@/lib/admin-auth`) + `supabaseAdmin`(`@/lib/supabase-admin`) 패턴, 응답 `{success, ...}` 포맷(admin/projects/route.ts 참조).
- `GET /api/admin/ai-models/available?provider=OpenAI|Google` — OpenAI `GET https://api.openai.com/v1/models`(OPENAI_API_KEY), Gemini `GET https://generativelanguage.googleapis.com/v1beta/models`(GEMINI_API_KEY) 프록시. 모듈 캐시 10분. 채팅/생성용 모델 위주로 정렬해 id 배열 반환.

### 5) UI

- `src/app/admin/layout.tsx` — `TABS`에 `{ href: '/admin/ai-usage', label: 'AI 사용현황', icon: Bot }` 추가(lucide `Bot`). 모바일 nav `grid-cols-2`→`grid-cols-3`.
- `src/app/admin/ai-usage/page.tsx` — 클라이언트 페이지. 기존 admin 페이지(projects/page.tsx)의 세션 토큰 fetch 패턴을 따른다. 흰 카드·컴팩트 테이블(사용자 UI 선호). 컬럼 제조사/모델명/위치/기능/비고. 행 편집 모드에서 제조사 select, 모델명은 "최신 모델 조회" 버튼으로 불러온 목록 드롭다운 + 직접 입력 허용, 비고 텍스트. 저장 시 PATCH. `source:'defaults'`면 "마이그레이션 실행 전 — 편집이 저장되지 않습니다" 안내 배너.
