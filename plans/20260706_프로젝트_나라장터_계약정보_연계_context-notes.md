# 컨텍스트 노트 — 프로젝트 나라장터 계약정보 연계

## 2026-07-06 조사·설계 결정

- **서비스 선정**: 조달청_나라장터 공공데이터개방표준서비스(15058815)는 날짜 범위 검색만 지원해 번호 직접 조회 불가. **계약정보서비스(15129427)의 `getCntrctInfoListCnstwkPPSSrch`**가 공고번호(ntceNo)·확정계약번호(dcsnCntrctNo) 직접 조회를 지원해 이쪽으로 확정. Swagger는 data.go.kr 상세 페이지 HTML의 `var swaggerJson`에서 추출해 확인함.
- **한 개 입력창으로 두 번호 처리**: 사용자가 계약번호인지 공고번호인지 구분하지 않아도 되도록, 라우트에서 dcsnCntrctNo로 먼저 조회하고 0건이면 ntceNo로 재조회하는 방식 선택. (번호 형식으로 사전 구분하는 방식은 두 번호의 포맷 규칙이 문서화되어 있지 않아 배제.)
- **inqryDiv 실호출 확정 (2026-07-06)**: `1`=계약체결일자 범위 조회(inqryBgnDate/inqryEndDate 필수), `2`=확정계약번호(dcsnCntrctNo) 조회, `4`=공고번호(ntceNo) 조회, `5`=범위 초과 에러. 잘못된 조합은 resultCode 08 "필수값 입력 에러".
- **키가 이미 등록되어 있었음**: 별도 활용신청 없이 기존 `DATA_GO_KR_API_KEY`로 계약정보서비스 호출이 바로 성공함 (2026-07-06). 활용신청 사용자 액션 불필요.
- **응답 형태 실측**: 날짜는 이미 `YYYY-MM-DD` 문자열, 금액은 원 단위 숫자 문자열. `corpList`/`dminsttList`는 `[순번^역할^구분^업체명^...]` / `[순번^기관코드^기관명^...]` 형태의 캐럿(^) 구분 문자열 — 업체명 index 3, 기관명 index 2로 파싱.
- **중복 행**: 같은 계약이 `untyCntrctNo`만 다른 행으로 중복 반환됨 (표시 필드는 전부 동일). 라우트에서 표시 필드 기준으로 dedupe.
- **구 나라장터 번호 형식 (2026-07-06 실검증)**: 차세대 API에 2022년 등 과거 계약도 전부 있음. 단 구형 공고번호는 `공고번호11자리+차수2자리` 결합값으로 저장됨 — "20221008901-000"은 저장값 "2022100890100". 라우트에서 `\d{11}(-차수)?` 패턴이면 차수를 2자리로 정규화해 추가 시도. 구형 확정계약번호(예: 2222047803)는 그대로 조회됨. 검증 계약: 북내지구 다목적농촌용수개발사업 토목공사 (한국농어촌공사 여주.이천지사, 197.6억, 공동도급 4개사 corpList 파싱 확인).
- **총사업비 단위 변환**: 폼의 total_budget 단위는 백만원 — 적용 시 `Math.round(totCntrctAmt / 1_000_000)`.
- **마이그레이션 전 안전장치**: 수정 폼은 빈 값일 때 g2b 필드를 `undefined`로 보내 페이로드에서 생략 — DB 컬럼 적용 전에도 기존 프로젝트 수정이 깨지지 않음. 대신 연계 해제(값 비우기)는 v1 미지원.
- **DB 컬럼**: `g2b_cntrct_no`(확정계약번호), `g2b_ntce_no`(공고번호) 두 TEXT 컬럼. JSONB 스냅샷 저장은 후속 단계(변경이력 자동 갱신)에서 필요해지면 도입 — 지금은 연계 키만 저장 (단순성 원칙).
- **주소는 매핑 제외**: 계약 응답에 현장 주소가 없음(수요기관 소재지는 부정확). site_address는 기존 수기 입력 유지.
- **시공사·수요기관은 미리보기만**: SafeSys의 시공사는 user_profiles 관계로 관리되므로 프로젝트 컬럼에 저장하지 않음.
- **관련 작업**: 같은 g2b 계열인 관급자재 납품요구번호 자동입력(`plans/20260706_관급자재_납품요구번호_자동입력.md`)과 별개 기능. API 키(`DATA_GO_KR_API_KEY`)는 공유.

## 2026-07-06 추가 — 본부·지사 자동 매칭 + 등록 방식 탭

- **수요기관 → 관할 본부·지사 매칭**: dminsttNm(예: "한국농어촌공사 경기지역본부 여주.이천지사")을 `BRANCH_OPTIONS`와 대조해 managing_hq/managing_branch까지 자동 적용. 구분자 차이(G2B는 `.`, 상수는 `·`)와 공백을 제거해 비교하고, `{본부}지역본부`/`{본부}사업단`/`{본부}본부` 패턴으로 본부를 먼저 확정한 뒤 그 안에서 지사를 찾는다 (같은 지사명이 여러 본부에 있는 '지하수지질부' 오매칭 방지). 농어촌공사가 아닌 수요기관은 매칭하지 않음. 지사 없이 본부만 매칭되면 branch는 '{본부}본부' 옵션. 10개 케이스 node 스크립트로 검증 완료.
- **등록 폼 탭**: ProjectRegistrationForm 상단에 '직접 입력'/'나라장터 연계' 2버튼 탭 추가 (기본 '직접 입력'). 나라장터 탭에서만 조회 박스 노출. 수정 폼은 탭 없이 항상 노출 유지.
- **본부만 매칭되고 지사가 안 잡히면** 기존 지사 선택을 비운다 — 다른 본부의 지사가 남아 있으면 안 되기 때문.
