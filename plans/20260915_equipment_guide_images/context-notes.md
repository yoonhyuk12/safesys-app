# 판단 기록

- 사용자 제공 PDF에서 원본 이미지 바이트를 추출했다. 이미지 생성이나 재제작은 필요하지 않다.
- 추출 위치는 safesys-app/scratch/equipment-inspection/pdf-guidance/extracted이며 manifest.json에 장비 ID·출처 페이지·치수가 있다.
- 장비 23종 중 준설선(equipment-20)·쇄석기(equipment-21)는 안내 이미지가 없다. 덤프트럭(equipment-23)은 2개, 나머지 20종은 1개다.
- 수정 문구는 기존 answers 스냅샷에서 출력하고 안내 이미지는 장비 ID에 연결된 정적 자산을 사용한다.
- 기존 한글 2022 COM 검증 도구와 PDF 분석 하니스를 재사용한다. 사용자 한글 프로세스·브라우저 탭은 종료하거나 조작하지 않는다.

- 안내 그림은 새 작성·제출 내역 수정·상세의 기본정보 아래에서 같은 컴포넌트로 표시한다. 원본 픽셀 폭 이상으로 확대하지 않고 모바일에서는 두 그림을 세로로 배치한다.
- HWPX는 첫 쪽 안내 그림 전용 행을 예약하고, 원본 JPEG를 그대로 패키지에 포함한다. 계속 쪽에는 그림을 반복하지 않는다.
- 실제 한글 출력 검토에서 첫 쪽 한 항목만 과도하게 늘어나는 경우와 짧은 종합 비고만 마지막 쪽에 남는 경우를 발견했다. 쪽 수를 유지하는 후보 배치 중 행을 채우기 위해 가장 크게 늘어나는 높이를 최소화하도록 수정했다.
- 격리 브라우저에서 굴착기·덤프트럭·준설선·쇄석기 상세/수정/모바일/다운로드를 확인했다. Supabase는 전부 가짜 응답을 사용했으며 실제 DB 쓰기는 없었다.
- 타입 검사와 변경 소스 ESLint가 통과했다. 새 SQL이나 운영 빌드는 필요하지 않다.
- 최종 검증은 scratch/equipment-inspection/guide-final-samples의 25문서(23종 + 일반/장문 서명 표본), 총 49쪽을 한글 2022에서 열어 PDF로 변환했다. 모든 문서 열기·변환 성공, 원문 471개 보존, 안내 그림 비율·첫 쪽 배치·본문 경계와 표 하단 769.08pt 확인, 49쪽 전체 시각 검토를 마쳤다.
- 기존 guide-samples 마지막 문서는 COM 종료 뒤에도 파일 잠금이 남아 새 폴더에서 검증했다. 사용자 앱을 종료하지 않았다.
- 최종 test:equipment 62개가 모두 통과했다. 테스트는 추출 scratch 대신 저장소의 원본 이미지 메타데이터·SHA-256 지문 fixture를 사용하며, 22개 지문을 추출 원본과 독립 대조했다.
