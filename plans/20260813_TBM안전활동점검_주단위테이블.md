# TBM 안전활동점검 현황 주단위 테이블 전환

대상 화면. `/safe/tbm` (및 `/safe/branch/[branch]/tbm`) → `src/components/dashboard/SafetyTBMView.tsx`.

## 배경

현재 이 화면은 **선택 일자 1일 + 전일** 2개 컬럼 기준으로 3단계 테이블(본부별 집계 → 지사별 집계 → 프로젝트별 상세)을 그린다. 한 주의 실시 추이를 보려면 날짜를 하루씩 바꿔가며 확인해야 한다.

## 요구사항 (사용자 확정)

1. **테이블 형태** — `(전일)TBM확인수` / `TBM확인수` 2개 컬럼을 **일~토 7개 요일 컬럼**으로 교체. 기존 입회 관련 상세 컬럼은 뒤에 유지.
2. **적용 범위** — 3단계 전부 (본부별 집계 · 지사별 집계 · 프로젝트별 상세).
3. **주 이동 UI** — 상단 date input을 `◀ 2026.08.09(일) ~ 08.15(토) ▶` 형태의 주 이동 버튼으로 교체. 초기값은 오늘이 속한 주.
4. **주 시작 요일** — 일요일.

## 설계

### 주 계산 유틸 (신규 `src/lib/tbm-week.ts`)

순수 함수로 분리해 단위 테스트 대상으로 삼는다.

| 함수 | 역할 |
|------|------|
| `normalizeTbmDate(value)` | `tbm_date`(DATE 컬럼, `'YYYY-MM-DD'`)를 `YYYY-MM-DD`로 정규화. 타임존 왜곡 없이 앞 10자만 취함 |
| `getWeekDays(anchorDate)` | 앵커 날짜가 속한 주(일→토) 7일을 `{ date, weekdayLabel, dateLabel, isSunday, isSaturday }[]`로 반환 |
| `getWeekRangeLabel(anchorDate)` | `2026.08.09(일) ~ 08.15(토)` 헤더 문구 |
| `shiftWeek(anchorDate, delta)` | 주 단위 이동(앵커 날짜 ±7일) |

`date-fns` v4의 `parseISO` / `startOfWeek({ weekStartsOn: 0 })` / `addDays` / `format` 사용.

### 상태 관리

`selectedDate`(Dashboard 전역 상태)를 **주 앵커**로 그대로 재사용한다. 주 이동 버튼은 기존 `onDateChange(shiftWeek(selectedDate, ±1))`을 호출한다 — Dashboard prop 시그니처 변경 없음(외과적 변경).

### 3단계 테이블 컬럼 구성

**1단계 · 본부별 집계**
`본부 | 일 | 월 | 화 | 수 | 목 | 금 | 토 | 입회/미입회 | 지사수 | 비고`
→ 요일 셀 = 해당 일자 TBM 확인 **건수**. 입회/미입회는 주 전체 합계.

**2단계 · 지사별 집계**
`지사 | 일 ~ 토 | 입회/미입회 | 입회 정보(지구명:입회자) | 비고`
→ 요일 셀 = 건수. 소계행도 요일별 합계.

**3단계 · 프로젝트별 상세**
`프로젝트명 | 일 ~ 토 | 입회여부 | 미입회사유 | 입회자 | 비고`
→ 요일 셀 = `O` / `-` (해당 일자 TBM 확인 여부). 소계행은 요일별 실시 지구 수.
→ 뒤쪽 상세 컬럼은 **주 전체 집계** 기준. 입회여부 = `입회수 / TBM수`, 미입회사유·입회자는 주중 값 중복 제거 목록.

### 제거되는 것

`previousDate`, `previousDayTbmInspections`, `previousTbmCount`, `previousDayInspection` 및 노란 배경 `(전일)` 컬럼 — 7개 요일 컬럼이 전일을 포함하므로 변경으로 인해 고아가 된 코드다.

### 유지되는 것

엑셀 다운로드 모달, 보고서(비활성) 버튼, 행 클릭 이동, 권한/필터 로직은 손대지 않는다.

## 컨텍스트 노트

- **`tbm_date`는 DATE 컬럼**(`database/migrations/20260211-0942_add_tbm_safety_inspections_table.sql:12`)이라 `'YYYY-MM-DD'` 문자열로 온다. 기존 코드의 `new Date(x).toISOString().split('T')[0]`은 지금은 우연히 맞지만, 요일 컬럼은 하루만 밀려도 즉시 눈에 띄므로 문자열 slice 방식으로 통일한다.
- **데이터 조회 범위는 이미 충분하다.** `Dashboard.tsx:994`가 `getTBMSafetyInspectionsByUserBranch`를 `startDate`/`endDate` 없이 호출해 전 기간을 받아온 뒤 클라이언트에서 필터링한다. 주간 전환에 API 변경이 필요 없다.
- **오늘 열 강조.** 제거되는 `(전일)` 노란 강조 대신 오늘 날짜 컬럼에 옅은 강조를 준다 — 화면에서 기준일을 잃지 않기 위함.
- **테스트 러너는 Playwright.** `package.json`에 `test` 스크립트가 없고 순수 로직 테스트도 `tests/*.spec.ts`에서 `@playwright/test`로 작성한다(`tests/admin-sort.spec.ts` 참고).

### 구현 중 추가로 결정한 것

- **3단계 소계행의 순회 대상 변경.** 기존 `branchSummary`는 프로젝트당 `latestInspection` 1건만 셌다. 그대로 두면 소계행이 데이터행(`입회수 / 주간TBM수`)의 열 합계와 어긋나 표로서 틀린 값이 된다. 표기 형식은 유지한 채 순회 대상만 `weekInspections`(주간 배열)로 바꿨다.
- **`tbmCount` 전면 제거.** `branchStats` · `hqStats` · `hqSummary` · `branchSummary`의 `tbmCount`는 전부 `TBM확인수` 컬럼 3개에만 쓰이던 값이라, 요일 컬럼 교체로 참조처가 0이 됐다. 이번 변경이 만든 고아 코드라 제거했다. 반면 `totalWorkers` · `tomorrowWorkYes` 등 **기존부터** 미사용이던 필드는 손대지 않았다.
- **`colSpan` 정정.** 3단계 "데이터가 없습니다" 행은 7컬럼 테이블에 `colSpan={8}`로 원래부터 어긋나 있었다. 컬럼 수가 바뀌면서 어차피 고쳐야 해 정확한 값(12 / 11 / 11)으로 넣었다.
- **빈 `selectedDate` 폴백.** 기존엔 `selectedDate`가 비면 전 기간을 반환했으나, 이제 오늘이 속한 주로 폴백한다. Dashboard가 항상 오늘로 초기화(`Dashboard.tsx:86`)하므로 실사용 영향은 없다.
