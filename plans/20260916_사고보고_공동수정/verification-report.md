# 공동 수정 검증 기록

## 직접 확인

- SQL UPDATE 정책에서 작성자 조건을 제거하되 프로젝트 SELECT RLS 기반 USING/WITH CHECK를 유지한다. DELETE 조건과 기존 본부급·외부 미등록 현장 정책은 보존한다.
- `npm run test:accident-report` 결과 46건 중 45건 통과, 실패 0건, 기존 회원 삭제 트리거 결함 TODO 1건.
- `npx tsc --noEmit` 및 `npm run lint` 종료 코드 0. 기존 저장소 린트 경고는 남아 있다.
- `git diff --check` 통과.
- 최종 보강으로 현재 프로젝트와 사고보고의 `project_id` 일치 가드가 추가됐다. 반영 후 타입검사와 브라우저 검증을 재실행해 통과했다.
- 공유 감리단 비작성자 수정 성공·작성자 보존·삭제 차단, 공유 철회 전 성공/철회 후 차단 테스트 2건을 최종 상태에서 직접 실행해 통과했다.
- 독립 리뷰어가 최종 전체 테스트 47건 중 46건 통과, 실패 0건, 기존 TODO 1건을 확인하고 승인했다.

## 브라우저

기존 로컬 개발 서버와 Playwright/Edge를 사용했다. HTTPS 요청을 모두 가로채고 Supabase에 가상 응답을 제공하여 운영 DB에 쓰지 않았다. 검증 스크립트는 gitignore된 `safesys-app/scratch/accident-report-smoke.cjs`다.

- 변경 전에는 타인 보고의 수정 버튼이 없어 공동 수정 검증이 실패했다.
- 변경 후에는 타인 보고의 수정 버튼과 수정 저장이 동작하며, 바꾼 내용이 상세 화면에 표시된다.
- PATCH에 `created_by`가 포함되지 않고 기존 작성자가 유지된다.
- 타인 보고의 삭제 버튼은 목록과 상세 모두에 표시되지 않는다.
- 기존 본인 등록·삭제, 저장 실패 입력 유지, 삭제 실패 안내, 조회 오류 구별, 모바일 너비 검증도 통과했다.

## 운영 상태

운영 SQL 실행, 프로덕션 빌드, 푸시·배포는 하지 않았다. 운영 사용에는 수정된 `database/20260916-1032_사고보고_현장작성_권한.sql` 적용과 앱 배포가 필요하다.
