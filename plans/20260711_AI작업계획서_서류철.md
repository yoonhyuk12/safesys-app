## 요구사항

- 프로젝트 상세(`/project/[id]`) 안전캐비넷 **P (계획)** 영역에 "︵AI︶ 작업계획서" 서류철 추가.
- 아래 4종 작업계획서를 각각(또는 통합 선택으로) 작성·PDF 다운로드 가능하게 한다.
  1. 붙임2-1 차량계 하역운반기계 등 사용 작업계획서 (수급업체용)
  2. 붙임2-2 차량계 건설기계 등 사용 작업계획서 (수급업체용)
  3. 붙임2-3 전기 작업계획서 (수급업체용)
  4. 붙임2-4 중량물 취급 작업계획서 (수급업체용)
- 작성 플로우.
  1. **서류 선택** — 만들 서류를 체크(복수 가능, 양식 주석의 "다른 작업계획서와 통합 작성" 관행 반영).
  2. **기본정보 입력** — 프로젝트 정보에서 긁어올 수 있는 값은 전부 자동 인입, 사용자는 최소한만 입력.
  3. **지도 드로잉** — 위성지도 위에 장비·운행경로·유도자(신호수)·작업지휘자·출입통제구역·안전표지판을 배치하는 드로잉 UI. 결과가 보고서 지도 칸에 담긴다.
  4. **AI 생성·검토** — 위험요인/개선대책·작업순서 등 서술 항목을 AI(Gemini)로 초안 생성, 사용자가 수정 확정.
  5. **저장 + PDF 다운로드** — 선택한 서류별로 붙임 양식과 동일한 레이아웃의 PDF 출력.

## 참조 양식 구조 (PDF 4종 공통/개별)

- **공통 골격** — 결재란(담당=수급업체 / 승인=현장 소장), 기본정보 표(작업명(장소)·작업기간·작업업체·작업자·작업지휘자/운전원/유도자 성명·연락처), 작업내용, 지도(범례 ▣장비 →경로 ⊙유도자 ★작업지휘자 출입통제구역 안전표지판 + 중점관리사항 4개 고정), 위험요인/개선대책 표(작업순서별), 산업재해 예방 체크리스트(양호/미흡/해당없음).
- **2-1 하역운반기계** — +차량번호·작업시간, 장비 제원 표(11개 항목), 건설기계 인양능력 검토(안전율 자동계산), 줄걸이 인양능력 검토(용구·규격·방법·안전계수·장력계수, 안전율 자동계산), 체크리스트 12문항.
- **2-2 건설기계** — +사전조사표(작업유형별 4종 — 건설기계/굴착/터널굴착/해체, 조사내용+현장사진), 운전원 면허, 유도자 신호방법, 작업방법·작업순서, 장비 종류·성능(장비명·등록번호·차체중량·능력), 체크리스트 18문항.
- **2-3 전기** — 지도 없음(전기도면·현장사진 첨부). 발주처·담당자·작업책임자, 작업목적·공사범위, 작업자 명단(성명·보유자격·근로형태), 안전보건교육 계획, 보호구 지급·사용장비, 작업 전 지시/협의사항, 작업순서·안전작업방법 표, 체크리스트 9문항, 인계/인수, 첨부자료 체크.
- **2-4 중량물** — 공통 + 지도, 중량물 제원(품명·형상·규격·중량·1회 운반중량·고정방법), 기계 제원(크레인 등 10개 항목), 인양능력·줄걸이 검토(2-1과 동일 로직), 체크리스트 13문항.
- 체크리스트 문항·범례·중점관리사항·안전계수/장력계수 표는 양식 고정 텍스트 → 상수로 하드코딩.

## 설계

### 1. DB — `work_plans` 테이블 신설

`database/20260711-HHMM_add_work_plans.sql` (사용자가 Supabase 콘솔에서 실행, 실행 전 main 푸시 금지).

```sql
CREATE TABLE work_plans (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  plan_types TEXT[] NOT NULL,            -- 'loading' | 'construction' | 'electric' | 'heavy'
  title TEXT NOT NULL,                   -- 작업명(장소)
  work_start_date DATE,
  work_end_date DATE,
  form_data JSONB NOT NULL DEFAULT '{}', -- 공통+종류별 폼 데이터 전체
  map_drawing JSONB,                     -- 지도 뷰(중심·줌) + 마커/경로 벡터(재편집용)
  map_image_url TEXT,                    -- 지도+드로잉 합성 PNG (Storage URL)
  site_photo_urls TEXT[] DEFAULT '{}',   -- 현장사진(2-2 사전조사, 2-3 도면·사진)
  created_by UUID,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);
```

- RLS는 기존 테이블 패턴과 동일하게 적용. `ON DELETE CASCADE` 필수(프로젝트 삭제 시 자동 삭제 규칙).
- Storage 신규 버킷 `work-plans`(public) — 지도 합성 이미지·현장사진 업로드. 경로 규칙 `${projectId}/${Date.now()}_...` 기존 관행 유지.

### 4. 지도 드로잉 에디터

- 배경지도 — **Leaflet + V-World 위성 WMTS 타일**(`NEXT_PUBLIC_VWORLD_API_KEY`, 기존 `src/lib/vworld.ts` 활용). 프로젝트 좌표 중심으로 로드, 이동·줌 후 "이 화면으로 고정".
- 고정 후 지도 위 absolute `<canvas>` 오버레이에 드로잉(기존 `SignaturePad.tsx`의 raw canvas 패턴 재사용). 도구 팔레트는 양식 범례와 1:1 — 장비 ▣, 경로(빨간 화살표 선), 유도자 ⊙, 작업지휘자 ★, 출입통제구역(보라 점선 타원), 안전표지판(녹색 사각), 텍스트 라벨, 개별 삭제·전체 지우기.
- 저장 시 ① 벡터 JSON(`map_drawing`, 재편집용) ② 지도 캡처+드로잉 합성 PNG를 Storage 업로드(`map_image_url`). PDF에는 합성 PNG + 범례 표 + 중점관리사항을 배치.
- 2-3(전기)만 선택된 경우 이 스텝은 현장사진·도면 업로드로 대체.

### 5. AI 초안 생성 — `src/app/api/ai/work-plan/route.ts`

- 기존 `api/ai/inspection-checklist/route.ts` 패턴 복제 — Gemini `gemini-3.1-flash-lite`, `GEMINI_API_KEY`, `responseMimeType: 'application/json'`.
- 입력 — 선택 서류 종류, 작업명·작업내용·장비명·중량물 품명 등 스텝2 입력값, 프로젝트 컨텍스트(공종·주소).
- 출력(JSON 강제) — 종류별로 ① 위험요인/개선대책 표(작업순서별) ② 작업순서(2-2)·작업순서/안전작업방법(2-3) ③ 사전조사 조사내용(2-2) ④ 작업내용 공유 문구. 체크리스트 문항은 고정 상수라 AI 생성 대상 아님(기본 "양호").
- AI 결과는 반드시 편집 가능한 표로 보여주고 사용자가 확정.

### 6. PDF 출력 — `src/lib/reports/work-plan/`

- `quality-monthly-report.ts` 패턴(html2canvas + jsPDF, A4 세로, 맑은 고딕, `applyHtml2canvasTextFix`) 그대로 사용.
- 종류별 빌더 4개 + 공통 조각(결재란·기본정보 표·지도 섹션·체크리스트 표) 분리.
  - `work-plan-loading-pdf.ts` (2-1, 3쪽 — 본표/지도·위험요인/체크리스트)
  - `work-plan-construction-pdf.ts` (2-2, 사전조사표 포함)
  - `work-plan-electric-pdf.ts` (2-3)
  - `work-plan-heavy-pdf.ts` (2-4)
  - `work-plan-pdf-common.ts`
- 표지(안내 페이지)는 출력 대상에서 제외하고 실무 서식 페이지만 출력. 다운로드 파일명 `작업계획서_{종류}_{작업명}_{YYYYMMDD}.pdf`. 복수 종류 선택 시 종류별 개별 PDF 다운로드.

## 구현 단계 (토큰 한도 대비 분할, 단계별 커밋)

1. **Phase 1 — 골격**. 마이그레이션 SQL, 진입점 폴더, work-plan 페이지(목록+마법사 골격), 스텝1·2(자동 인입 포함). → 검증: tsc·lint, 로컬에서 자동 인입 값 확인.
2. **Phase 2 — 지도 드로잉**. MapDrawingEditor + 합성 PNG 생성·Storage 업로드. → 검증: 캡처 이미지에 타일+드로잉 모두 포함되는지.
3. **Phase 3 — AI**. api/ai/work-plan 라우트 + AiReviewStep 편집 UI. → 검증: 4종 각각 JSON 스키마 파싱 성공.
4. **Phase 4 — PDF 4종**. 빌더 + 다운로드 연결 + 목록 화면 완성. → 검증: 붙임 양식과 페이지 단위 비교.

## 리스크·주의

- **지도 타일 CORS** — V-World WMTS 타일이 crossOrigin 캡처를 막으면 canvas가 taint되어 합성 PNG 생성 실패. 1차 시도는 타일 `crossOrigin: 'anonymous'`, 실패 시 서버 프록시 라우트(`/api/vworld-tile`)로 우회. `docs/troubleshooting.md`의 html2canvas 이슈 참조.
- **서명란** — 양식의 (서명)은 1차 범위에서 빈칸(출력 후 수기). 손글씨 서명 겹침은 추후 확장.
- **양식 재현도** — html2canvas 방식이므로 HTML 표로 원본과 동일 배치 재현 가능하나, 셀 줄바꿈·행 분할은 Phase 4에서 원본 PDF와 대조하며 조정.
- 2-2 사전조사표의 작업유형(굴착/터널/해체)은 선택형 — 선택된 유형의 표만 출력.
