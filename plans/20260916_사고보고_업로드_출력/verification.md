# 통합 검증 기록

## 검증 범위

- 실제 사용자 PDF/HWPX는 로컬에서 서식과 텍스트 구조만 확인했다. 원본 파일은 Git에 추가하지 않는다.
- 브라우저 저장 검증은 Supabase와 자동 채움 응답을 가로챈 가상 서버로 수행한다. 운영 데이터는 쓰지 않는다.
- 실제 AI 호출은 개인정보가 없는 합성 문서만 사용한다. 세부 결과는 `import-report.md`에 기록한다.
- HWPX 호환성 검증은 실제 설치된 한글 2022와 COM 재저장·PDF 변환을 사용한다. 세부 결과는 `hwpx-report.md`에 기록한다. 유사 양식 검증은 사용자가 확정한 평택 원본 양식 검증으로 대체한다.

## 검토 중 발견한 결함

- 사진을 처리하는 동안 다른 상세 항목을 수정하면 이전 상태로 돌아가는 비동기 상태 결함을 브라우저에서 재현하고 수정 후 보존을 확인했다.
- 자동 채움의 기준값 비교가 기존 저장값을 빈 칸으로 보는 문제를 수정하고, 수정 모드에서 기존 보고자와 사진이 보존되는 것을 확인했다.
- SQL의 사진 객체 허용 키와 선택 배열 길이 제한을 추가하고 실제 PGlite 검증을 통과했다.
- 사망자 수와 부상자 수를 별도 인원으로 다루고, 산재 신청 준비와 신청 완료를 구분하도록 추출 규칙을 검토했다.

- 최종 `scratch/accident-final-v2`의 empty/one/two/heading/nested 전체 페이지를 확인했다. long 10쪽은 이미 육안 확인한 v4 PDF와 픽셀 단위로 동일하다. nested 9쪽은 변경된 1·5·6·8·9쪽을 다시 확인했고 나머지 쪽은 v4와 픽셀 단위로 동일하다. 최대 길이 설명도 사진 두 컷과 함께 한쪽에 보존된다. PDF 텍스트의 끝 마커와 반복 문자 수로 누락 여부를 대조했다.
- 원본 HWPX SHA256 `04DE7CE17F6FA74B9F540F7330FAE5D3A372218F160F2437BBDCCE1FECB59588` 불변. 원본 헤더·격자를 유지한 정제 양식만 배포 대상으로 준비했다.
- 요청한 보안모듈은 기존 동일 DLL을 재사용하고 HKCU의 `FilePathCheckerModule` 등록을 보완했다. 레지스트리를 백업했으며 COM RegisterModule 및 이후 파일 열기/저장 모두 True, 보안 확인창 없이 완료했다.

## 반영 범위

SQL 파일과 앱 코드를 로컬에서 준비한다. 운영 SQL 실행, 프로덕션 빌드, 원격 푸시·배포는 수행하지 않는다.
