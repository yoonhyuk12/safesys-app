# 시공 캐비넷 예정공정표(공정표) 기능

작성일 2026-06-18

## 목적

프로젝트 상세 페이지 시공 캐비넷 P(계획) 섹션에 "공정표" 서류철을 추가하고, 사진(예정공정표)과 동일한 **공종 기반 완전판** 공정표를 작성·편집·Excel 출력할 수 있게 한다. 산출되는 공정률 곡선은 기존 작업일보·캐비넷 명판·프로젝트 목록 공정률과 **단일 출처로 연동**한다.

## 사용자 확정 사항 (2026-06-18)

- 모델 범위: **공종 기반 완전판** — 공종별 공사금액 → 가중치 자동, 旬(10일)별 일정 막대, 주간(旬)/월간 공정율·누계·S커브 자동 산출. 사진과 동일.
- 저장: `projects.construction_schedule` JSONB 컬럼 1개 추가 (마이그레이션은 사용자가 Supabase 콘솔에서 실행).
- 출력: **Excel 다운로드** (exceljs). 화면 편집·드래그는 기본 제공.
- 연동: 이 계획 곡선이 공정률의 **마스터** — 작업일보·캐비넷·목록이 같은 값을 표시.

## 핵심 아키텍처

```
projects.construction_schedule (JSONB)         ← 단일 출처(공종/금액/일정)
        │  computeSchedule() (순수 함수)
        ▼
旬별 공정율 / 누계 / 월간 / S커브 / 공종별 우측 공정률
        │  scheduleToAnchors() (旬 끝 날짜 → 누계%)
        ▼
getProgressAnchors(projectId)  ← 스케줄 있으면 스케줄에서 앵커 도출, 없으면 기존 수동행 폴백
        │  computeProgressRate(start,end,today,anchors)
        ▼
시공 캐비넷 명판(%) · 프로젝트 목록 카드 · 작업일보 공정률  ← 모두 동일 값
```

기존 `computeProgressRate`/`getProgressAnchors` API 시그니처는 유지한다. 연동은 `getProgressAnchors` 내부에서 스케줄 우선으로 앵커를 만들어 주면, 소비자(캐비넷/목록/작업일보)는 변경 없이 자동 반영된다.

## 데이터 모델 (work-schedule-types.ts)

```ts
interface WorkScheduleItem {
  id: string            // 안정적 식별자
  name: string          // 공사종류(공종)
  amount: number        // 공사금액(원)
  startIndex: number    // 시작 旬 인덱스 (period grid 기준, inclusive)
  endIndex: number      // 종료 旬 인덱스 (inclusive)
  dist?: Record<number, number> // 旬 인덱스 → 이 공종의 해당 旬 진행 비율(0~1). 없으면 기간 균등.
}
interface WorkSchedule {
  items: WorkScheduleItem[]
  contractNo?: string   // 공사관리번호 (표 상단)
  updatedAt?: string
}
```

### 旬(period) 그리드
착공~준공 기준, 월별 3분할(상순 1~10 / 중순 11~20 / 하순 21~말일). 각 period = { index, year, month, dayLabel(10/20/말일), endDate(YYYY-MM-DD, 준공으로 클램프) }.

### 계산 (순수 함수)
- `weight_i = amount_i / Σamount × 100` (가중치)
- 공종 i의 旬 p 자기진행비율 `f_{i,p}` = dist[p] 있으면 그 값, 없으면 균등 `1/(endIndex-startIndex+1)` (start≤p≤end). 그 외 0.
- 旬 기여(전체 대비%) `c_{i,p} = weight_i × f_{i,p}`
- 旬 공정율(열 합) `col_p = Σ_i c_{i,p}` (주간공정율)
- 旬 누계 `cum_p = Σ_{k≤p} col_k` (주간공정 누계)
- 월간 공정율 = 해당 월 旬 공정율 합, 월간 누계 = 월 단위 running.
- 공종별 우측 공정률 = `cum_{endIndex_i}` (그 공종 종료 시점 전체 누계 %). 사진의 우측 컬럼.
- S커브 점 = (period.endDate, cum_p) → 빨간 polyline.
- 검증: 각 공종 Σf≈1, Σweight≈100, 최종 cum≈100 아니면 화면에 경고 배지(강제 정규화는 안 함 — 사용자 입력 존중).

### 연동 앵커
`scheduleToAnchors(schedule, start, end)` = 각 period에 대해 `{ date: period.endDate, rate: cum_p }`. computeProgressRate가 착공(0)·준공(100)과 함께 보간 → 화면의 S커브와 동일.

## "일자별 수직 조정"

완전판에서 곡선은 공종/일정/분포에서 **파생**된다. 수직 조정은 (a) 旬 셀에 진행비율 직접 입력(값↑↓ → S커브 점 이동), (b) 공종 막대 시작/종료 드래그(일정 변경)로 제공한다. S커브 핸들 직접 드래그는 파생 구조상 v1 범위 외 — 셀 입력이 동일 효과. (사용자 확인 필요 시 후속.)

## 미해결/결정 사항

- 우측 "공정률" 컬럼 = 공종 종료 시점 누계%로 해석(사진의 공사준비 0.1% 등과 일치). 단순 가중치 표기 원하면 전환 쉬움.
- 旬(10일) 단위 채택 — 사진과 일치. 사용자는 "주별"이라 표현했으나 사진은 旬. 필요 시 주 단위 옵션 추가 가능.
- Excel S커브: exceljs 네이티브 차트 한계로, 화면 SVG→PNG 임베드 우선, 실패 시 월간누계 네이티브 라인차트 또는 숫자행만.
