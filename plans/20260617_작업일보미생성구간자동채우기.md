# 작업일보 미생성 구간 자동 채우기

작성일: 2026-06-17 · 대상 페이지: `/project/[id]/work-daily-report` (2단계 캘린더)

## 1. 목적 / 배경

2단계 캘린더 좌측 사이드바(범례 "등록됨 / 오늘 / *TBM 입력" 하단)에 **"작업일보 미생성 구간 자동 채우기"** 진입점을 추가한다.
최근 작업일보의 인원·장비 명단을 기준으로, **TBM이 제출된 미생성 날짜(어제까지)** 를 한 번에 일보로 생성한다. 각 날짜의 TBM 금일/명일 작업내용과 기상청 날씨도 함께 채운다.

기존 "TBM 전체 일보 생성(AI)"(1단계)이 *처음부터* 초안을 만드는 도구라면, 이 기능은 *이미 일보가 있는 상태에서* 그 이후 비어 있는 구간을 **기존 명단을 이어받아** 메우는 보완 도구다.

## 2. 확정된 동작 (사용자 결정사항)

| 항목 | 결정 |
|------|------|
| 대상 날짜 | **TBM이 제출된 미생성 날짜만** (TBM 없는 날은 건너뜀) |
| 구간 끝 | **어제까지** (오늘 제외 — 오늘은 작업 미완료·ASOS 관측자료 미취합) |
| 인원·장비 수량 | 최근 일보 명단을 **기준 어휘로 이월**, 금일투입은 그 날 TBM 수량으로 채우고 TBM에 없는 항목은 공란. **신규 항목은 추가** |
| 신규 항목 과거 반영 | 갭에서 추가된 신규 분류는 **모든 일보(과거 포함)에 빈 행으로 추가**. 항목 등장 이전 날짜는 수량 공란. → 누계 재계산을 **양방향(글로벌 로스터)** 으로 수정 |
| 공정률 전용 행 | 공정률만 입력된 앵커 행(작업내용 없음)은 **'실제 일보 아님'으로 판정**. 기준으로 안 쓰고, 미생성으로 보고 **UPDATE로 채움(공정률 보존)**. 재계산도 앵커 행은 건너뜀 |
| 확인 방식 | **요약 확인(인라인) 후 일괄 생성** |
| 전제조건 | 기준이 될 일보가 **하나도 없으면**(1단계 미실행) 먼저 "TBM 전체 일보 생성"을 하도록 안내 |

## 3. 재사용 자산 (신규 코드 최소화)

- `lib/work-daily-report/generate-from-tbm.ts`
  - `classifyTbmForGeneration` — TBM 수집 + 날짜순 AI 분류 + 날씨 일괄 조회. **여기에 옵션만 추가**해 재사용.
  - `saveGeneratedReports` — 일보 일괄 insert + 누계 재계산. **그대로 재사용.**
- `lib/work-daily-report/recalculate-cumulative.ts` — 저장 후 전 일보 전일까지/누계 재계산. **본 작업에서 양방향(글로벌 로스터)으로 수정**: 프로젝트 전체 분류 명단을 모든 일보에 채워, 신규 항목이 과거 일보에도 빈 행으로 반영되게 한다.
- `/api/weather/asos-range` — 과거 날짜 관측 날씨(범위 1회 조회).
- `/api/ai/supervisor-summary` (`type: 'work-daily-classify'`) — TBM 인원·장비 → 분류. `existingEquipment`/`existingPersonnel` 어휘를 받아 명명 일관성 유지.

## 4. 설계

### 4.1 데이터 흐름

```
[버튼 클릭]
  → 기준 일보 로드(최근 일보 1건)
      └ 없으면 → "1단계 먼저" 안내 (생성 중단)
  → 어제(endDate) 계산
  → classifyTbmForGeneration({ endDate=어제, seed 어휘=기준 일보 명단 })
      └ TBM 미생성 날짜(≤어제) 각각 AI 분류 + 날씨
  → 결과 days.length === 0 → "채울 구간 없음" 안내
  → [요약 표시] 기준 일보일 · 대상 N일(시작~끝) · 분류 실패 일수
  → [생성] 클릭 → saveGeneratedReports → recalc → loadReportDates() 갱신
```

### 4.3 핵심 로직 (의사코드)

```ts
// fill-missing-range.ts
async function prepareMissingRangeFill({ projectId, projectName, managingHq, managingBranch, latitude, longitude, today, onProgress }) {
  const baseline = await loadBaselineReport(projectId)       // 최근 일보 1건
  if (!baseline) return { needsStage1: true }

  const seedEquipmentVocab  = (baseline.equipment_rows ?? []).map(r => r.name).filter(Boolean)
  const seedPersonnelVocab  = (baseline.personnel_rows ?? []).map(r => r.category).filter(Boolean)
  const endDate = yesterdayStr(today)                        // 오늘 제외

  const result = await classifyTbmForGeneration({
    projectId, projectName, managingHq, managingBranch, latitude, longitude,
    endDate, seedEquipmentVocab, seedPersonnelVocab, onProgress,
  })
  return { needsStage1: false, baselineDate: baseline.report_date, baseline, result }
}
```

## 5. 엣지 케이스

- **기준 일보 없음**: `needsStage1` → "먼저 1단계에서 TBM 전체 일보 생성으로 초안을 만들어 주세요." + [1단계로 이동].
- **채울 구간 없음**(TBM 미생성 날짜 ≤어제 가 0): "채울 미생성 구간이 없습니다." 안내.
- **좌표 없음**: 날씨 없이 진행(기존 동작과 동일).
- **일부 날짜 AI 분류 실패**: `result.failedDates` 요약·결과에 표시하고 나머지는 생성.
- **이미 일보가 있는 날짜**: 항상 건너뜀(덮어쓰지 않음). 재실행 안전(idempotent — 남은 날짜만 처리).
- **기준 일보보다 앞선 구멍(과거 누락 TBM일)**: `skip-existing`만 적용되므로 ≤어제의 모든 미생성 TBM일이 대상. 누계 재계산이 날짜순으로 정합성 보장.
- **공정률 전용 앵커 행**(`ProgressRateModal`이 공정률만 저장한 행): `isRealWorkReport`(작업텍스트/금일투입 유무)로 판정. ① 기준 일보에서 제외(최근 *실제* 일보 사용) ② 미생성 대상에 포함하되 INSERT 대신 **UPDATE**로 채워 `progress_rate`/`progress_rate_manual` 보존 ③ 누계 재계산은 앵커 행을 건너뛰어 깨끗하게 유지. (1단계 "TBM 전체 일보 생성"은 기존대로 앵커 날짜를 채우지 않음 — `realReportDatesOnly` 미전달)

## 7. 검증 (성공 기준)

1. 기준 일보가 없는 프로젝트 → 카드가 "1단계 먼저" 안내를 보여주고 생성하지 않는다.
2. 기준 일보 + 그 이후 TBM 3일(어제까지) → 요약에 "대상 3일" 표시, [생성] 시 3건 일보 생성.
3. 생성된 일보의 인원·장비 분류명이 기준 일보 명단과 일관되고, TBM에 있던 신규 직종/장비가 추가된다.
4. 금일/명일작업이 해당일/다음 TBM일 작업내용으로 채워진다.
5. 날씨(날씨/최고·최저기온/강우량)가 ASOS 관측값으로 채워진다.
6. 오늘 날짜 일보는 생성되지 않는다(어제까지).
7. 저장 후 누계가 재계산되어 캘린더에 등록 표시(초록)가 갱신된다.
8. 갭에서 새로 등장한 분류가 **과거(기존) 일보에도 빈 행으로 추가**되고, 항목 등장 이전 날짜는 전일까지/금일/누계가 모두 공란이다.

## 8. 결정 노트 / 미해결

- 본 기능은 **TBM 있는 날짜만** 채운다(사용자 결정). 따라서 일요일/공휴일 판정 로직은 불필요. 추후 "TBM 없는 작업일도 이월로 채우기"를 원하면 공휴일 데이터 소스(특일정보 API/정적 목록) 연동을 별도 검토.
- **신규 항목 과거 반영(양방향)**: 사용자 결정으로 신규 분류는 과거 일보에도 빈 행으로 추가. `recalculate-cumulative.ts`를 글로벌 로스터 방식으로 수정해 구현하며, 이는 **1단계 생성 후 재계산에도 동일 적용**(시스템 전반에 전체 명단 공유)되는 부수효과가 있음 — 사용자 확인 완료.
- 확인 UI는 네이티브 `confirm()` 대신 **카드 내 인라인 요약 박스**로 구현(기존 `TBMClassificationPanel`의 인라인 패턴과 일관). 드래그 병합 검토는 제외(1단계 전용).
- 작성자/확인자 기본값은 최근 일보 값 우선, 없으면 프로젝트 소유자명.
- checklist.md / context-notes.md: 본 문서의 6·8절로 대체. 구현 착수 시 별도 파일로 분리 가능.
