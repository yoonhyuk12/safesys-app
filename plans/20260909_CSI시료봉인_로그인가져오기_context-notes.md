# 컨텍스트 노트 — CSI 시료봉인 로그인 가져오기

- **조사 분담(2026-09-09).** Advisor(Claude)가 Chrome 로그인 탭·curl·Node fetch로 프로토콜을 실측 확정. Codex(gpt-5.6-sol, read-only 샌드박스)는 curl 실행이 막혀 원문 확인은 못 했으나 설계 주의점을 제시 — 쿠키를 Set-Cookie 단위로 보관할 것, 302 단독으로 성공 판정하지 말 것, 세션만료가 200 로그인 HTML로 올 수 있음, 계정 잠금 대비 자동 재시도 금지, 비밀번호·전체 쿠키 비로그, Node 런타임 고정. 모두 계획에 반영.
- **로그인 흐름이 단순하다.** 평문 POST, 암호화·캡차·2차인증 없음. 성공은 302+Location, 실패는 200+alert 문구. 이전 CSI 노트의 "공개 화면은 UTF-8" 규칙이 여기도 적용된다(로그인 실패 본문·목록·상세 모두 UTF-8, `<meta charset=euc-kr>` 선언은 무시).
- **자격증명 정책.** 서버 저장·세션 보관 없음. 요청마다 로그인→조회→로그아웃. 모달 상태에만 두고 닫으면 버린다. API는 SafeSys Bearer 토큰 필수(공개 릴레이 방지).
- **시료봉인은 결과가 없다.** 목록의 시료상태 '품질검사 의뢰신청'은 의뢰 단계라 시험 결과·성적서번호가 없다. 프리필은 종목·일자·장소까지이고 결과는 성적서 발급 후 사용자가 채운다. 시험종목 카탈로그는 종별 전체 목록이라 실제 수행 종목으로 오해하지 말 것.
- **매핑 가정.** 대상 재료=시험종별, 공급공장=첫 시료 제조사, 항목=시료 1건당 1행(여러 시료면 종목명에 채취장소 병기). 사용자 피드백에 따라 조정 가능.
- **샘플 계정(총 40건, 기관 B00388)** 은 사용자가 조사용으로 제공. 저장소·로그·픽스처에 절대 기록하지 않는다.

- **잘못된 비밀번호 실측 문구.** "아이디 또는 비밀번호를 다시 확인하세요. 5회이상 로그인 실패 시 로그인이 제한됩니다." — CSI가 5회 실패 시 잠근다. 재시도 로직을 절대 넣지 말 것.

- **브라우저 화면 검증은 미완.** Advisor의 브라우저 자동화 규칙상 타사 비밀번호 입력을 대신할 수 없어 로그인→목록→가져오기 화면 흐름은 사용자가 직접 확인해야 한다. 프리필 값은 코드로 도출한 것이다.
- `docs/architecture.md`에 기존 `/api/csi/quality-reports`가 원래 누락돼 있었다 — 이번엔 새 두 줄만 추가.
- **자격증명 저장 결정(2026-09-09).** 사용자가 저장 위치를 직접 골랐다 — 브라우저 `localStorage`(그 기기에서만), 서버·DB 저장은 하지 않는다.
- 저장 값은 `safesys.csi.credentials` 키에 JSON을 UTF-8 base64로 감싸 넣는다. **난독화일 뿐 암호화가 아니다** — 기기를 공유하면 그대로 노출되므로 화면에도 "공유 기기에서는 저장하지 마세요"를 띄운다.
- 저장은 목록 조회가 성공한 뒤에만 한다(틀린 비밀번호를 기기에 남기지 않기 위해). 체크 해제·"저장된 정보 삭제"로 즉시 지운다.
