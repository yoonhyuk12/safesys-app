# 사고보고 검증 기록

## Coordinator 직접 확인

- 안전캐비넷 A(조치)의 `DocumentFolder`가 `/project/[id]/accident-report`로 연결되는 diff를 확인했다.
- 기존 `project_accidents`를 프로젝트별로 조회·저장하며, 대시보드도 같은 테이블을 조회한다. 별도 복사나 이중 등록이 없다.
- 변경 후 `npm run lint`와 `npx tsc --noEmit`이 종료 코드 0을 반환했다. 기존 저장소 린트 경고는 그대로 남는다.
- 최종 `npm run test:accident-report` 결과는 37건 중 36건 통과, 실패 0건, 기존 결함 TODO 1건이다. 같은 본부·다른 본부·본사·현장 역할별 타인 사고 관리 권한도 확인했다.
- 실제 SQL을 실행하는 PGlite 권한 테스트에서 현장 등록, 본인 수정·삭제, 프로젝트 격리, 작성자 위조 차단, 공유 철회, 기존 본부급 및 미등록 현장 권한을 확인했다.
- 기존 회원 삭제 트리거 결함은 재현 가능한 TODO 테스트로 남겼다. 이번 권한 정책 때문에 새로 발생한 문제가 아니며 `db-report.md`에 상세를 기록했다.

## 브라우저 검증

Playwright + 로컬 Edge headless로 `localhost:3000`에서 확인했다. Supabase 요청은 전부 가상 응답으로 대체해 운영 기록에 쓰지 않았다. 검증 코드는 gitignore된 `safesys-app/scratch/accident-report-smoke.cjs`다.

- 현장 시공사 계정의 사고 목록 조회 및 등록 진입.
- 프로젝트 자동 고정과 프로젝트 검색 제거.
- 저장 실패 안내 및 사용자가 입력한 장소·개요 보존.
- 재시도 저장 성공 후 상세 표시 및 프로젝트·작성자 ID 유지.
- 모바일 390px에서 문서 전체 가로 넘침 없음.
- 삭제 실패 메시지를 확인 모달 내부에서 표시.
- 삭제 성공 후 빈 목록 표시.
- 타인 작성 건의 수정·삭제 버튼 숨김.
- 조회 오류를 사고 없음으로 표시하지 않고 구별.
- 사고 목록 조회가 실패해도 프로젝트 접근 확인이 끝났다면 등록 진입점을 유지.

## 독립 리뷰

Orca의 UI 구현·DB 정책·독립 리뷰 작업이 모두 성공 상태로 종료됐다. 리뷰 결과 미해결 CRITICAL/HIGH/MEDIUM은 없으며, LOW 문서 설명과 시간대 테스트 대조 조건은 Coordinator가 마무리했다. 시간대 테스트를 재실행해 통과했고, 신규 화면의 배지 색은 디자인 시스템을 유지한다. 회수 가능한 작업자 리소스는 모두 해제했다.

## 운영 반영 상태

프로덕션 빌드·푸시·배포 및 원격 DB 변경은 하지 않았다. SafeSys 운영 프로젝트 `hbxthrnsaijfaxnfhsas`는 현재 연결된 Codex Supabase 계정에 권한이 없어 쓰기 적용할 수 없었다. Worker의 별도 읽기 전용 연결로 운영 정책 원문만 대조했다.

현장 작성 기능을 운영에서 사용하려면 `database/20260916-1032_사고보고_현장작성_권한.sql`을 적용한 뒤 앱 변경을 배포해야 한다. SQL 적용 전에는 시공사·감리단 사고 조회·저장이 기존 RLS에 의해 제한된다.
