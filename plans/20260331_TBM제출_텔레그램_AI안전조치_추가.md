# TBM 제출 시 텔레그램 AI 안전조치 확인사항 추가

## 목적
TBM 제출 시 발주청(한국농어촌공사)에게 발송하는 텔레그램 메시지에, AI가 생성한 **공사감독 관점 안전조치 확인사항 6가지**를 함께 포함하여 발송한다.

## 현재 구조

### 텔레그램 발송 흐름
```
TBM 제출 (TBMSubmissionModal.tsx)
  → DB 저장 (tbm_submissions)
  → 프로젝트의 client_telegram_id 조회
  → /api/telegram (direct 타입) 으로 메시지 발송
  → (교육사진 있으면) /api/telegram/photo 로 사진 발송
```

### 기존 텔레그램 메시지 내용
```
📋 TBM 일일안전교육 제출
🏗️ 현장: {프로젝트명}
📅 교육일자: {날짜}
⏰ 교육시간: {시작} ~ {종료}
📝 금일작업: {작업내용}
📖 교육내용: {교육내용}
👷 투입인원: {인원}
🚜 투입장비: {장비}
👤 작성자: {이름}
📞 연락처: {연락처}
📷 교육사진이 첨부되었습니다.
🔗 안전관리시스템 바로가기
```

### 기존 AI API 활용 패턴
- **API 엔드포인트**: `/api/ai/write-risk-analysis` (gpt-4o-mini 사용)
- **환경변수**: `OPENAI_API_KEY` (이미 설정됨)
- **동일 패턴**: TBM 제출 모달에서 이미 "AI 위험요인 분석" 기능 사용 중

## 수정 계획

### 1단계: 새 API 엔드포인트 생성

**파일**: `safesys-app/src/app/api/ai/tbm-safety-advice/route.ts`

> **별도 엔드포인트를 만드는 이유**: 기존 `/api/ai/write-risk-analysis`는 위험요인/대책을 구조화된 JSON으로 반환하지만, 이 API는 공사감독용 안전조치 텍스트를 반환하므로 프롬프트와 응답 형식이 다름.

- 기존 `/api/ai/write-risk-analysis/route.ts` 패턴을 따름
- OpenAI gpt-4o-mini 호출
- 입력: `todayWork`, `personnelInput`, `equipmentInput`
- **타임아웃**: 50초 (AbortController 사용) — 초과 시 AI 부분 생략하고 기존 메시지만 발송
- 프롬프트:
  ```
  오늘 TBM 작업내용: "{todayWork}"
  투입인원: "{personnelInput}"
  투입장비: "{equipmentInput}"

  위 내용에 대해서, 한국농어촌공사 공사감독으로써 안전조치 확인 해야할 사항 6가지를 적어줘.
  각 항목은 번호와 한 줄로 간결하게 작성해줘. HTML 태그 없이 플레인 텍스트로 작성해줘.
  ```
- 응답 형식: **플레인 텍스트** (HTML 태그 없이) — 클라이언트에서 텔레그램 HTML로 포맷
- 응답: `{ success: true, advice: "1. ...\n2. ...\n..." }`

### 2단계: TBM 제출 모달 수정

**파일**: `safesys-app/src/components/project/TBMSubmissionModal.tsx`

**수정 위치**: 텔레그램 알림 발송 블록 (라인 1087~1138)

**변경 내용**:
1. DB 저장 성공 후, 텔레그램 발송 전에 AI API 호출
2. **무작업 체크 시(`formData.noWorkCheck === true`) AI 호출 스킵** — 작업 내용 없으면 안전조치 생성 불필요
3. `/api/ai/tbm-safety-advice` 에 `todayWork`, `personnelInput`, `equipmentInput` 전달
4. AI 응답을 기존 텔레그램 메시지 하단에 추가:
   ```
   (기존 메시지 내용)

   ━━━━━━━━━━━━━━━━━━━━
   🤖 AI 안전조치 확인사항 (공사감독용)
   {AI 응답 6가지}
   ━━━━━━━━━━━━━━━━━━━━
   ```
5. AI API 실패/타임아웃 시에도 기존 메시지는 정상 발송 (AI 부분만 생략)

**UX 지연 최소화**:
- AI API 호출과 프로젝트 텔레그램 ID 조회를 **Promise.all로 병렬 실행**
- AI 타임아웃 50초 설정 — 늦어져도 발송만 되면 됨
- 테스트 결과 실제 응답 시간: 2~3초

## 주의사항

- AI API 호출 실패 시 텔레그램 발송 자체가 실패하면 안 됨 → try-catch로 분리
- **UX 지연**: AI 호출 + 텔레그램 발송이 모두 await 순차 실행이므로 체감 지연 발생 → AI조회와 텔레그램ID 조회를 Promise.all 병렬 처리
- **무작업 체크 시**: `formData.noWorkCheck === true`이면 AI 호출 스킵
- **AI 타임아웃**: 50초 (AbortController) — 초과 시 AI 부분 생략. 늦어져도 발송만 되면 OK
- **응답 형식**: 플레인 텍스트로 받아 클라이언트에서 HTML 포맷 → GPT 응답 형식 불일치 방지
- 기존 `OPENAI_API_KEY` 환경변수 그대로 사용 (추가 설정 불필요)
- 텔레그램 메시지 길이 제한 (4096자) 주의 → AI 응답을 간결하게 유도 (프롬프트에 "한 줄로" 명시)
