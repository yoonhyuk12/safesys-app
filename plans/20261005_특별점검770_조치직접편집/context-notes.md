# 컨텍스트

- 작업자는 직접 구현하고 조정자가 독립 검토한다. 커밋하지 않는다.
- normalize770Data는 누락 항목을 채우므로 삭제된 항목은 정규화 전 원본에서 확인한다.
- 최신 JSON을 읽어 updateItem으로 두 필드만 변경한다. 원본 최상위 확장 필드도 유지한다.
- 기존 read→update 패턴은 두 요청 사이의 동시 쓰기를 원자적으로 보호하지 않는다. 스키마/RPC 추가는 범위 밖이다.
- Supabase 공식 update 문서에서 update 후 select로 갱신 행 반환을 확인했다. https://supabase.com/docs/reference/javascript/update
- Supabase changelog를 확인했으며 이번 단순 JSON 갱신과 관련된 API 파괴적 변경은 찾지 못했다.
- GitHub 코드 검색을 수행했고 프로젝트 내 saveAfterPhoto/updateItem 패턴을 우선 재사용한다. 의존성 추가가 필요 없다.
- 이 작업에 없는 superpowers 스킬 대신 위임된 구체적 요구사항과 기존 검증 명령을 따른다. 소스 문자열 미러 테스트는 추가하지 않는다.

## 결과와 검증

- 인라인 버튼은 행 상세 이벤트를 차단한다. 자동 초점, 취소 시 초점 복귀, 저장 중 중복 방지(ref + disabled), 실패 시 초안 유지, 원본 항목 부재와 갱신 0건 감지를 구현했다.
- 추가 요청은 UTC 달력 연산으로 +7일을 계산하고 결과 편집 effect 및 폼 저장에서 빈 부적정 기한만 채운다. 값이 있는 기한은 점검일 변경 후에도 유지한다. 날짜 삭제는 기본값 복원을 뜻하며 UI에 안내한다.
- 신규 동작 테스트를 먼저 실행해 함수 부재 실패를 확인한 뒤 구현했다. 최종 npm run test:special-770은 39/39 통과했다.
- npm run lint 종료 0(기존 경고 존재), npx tsc --noEmit 종료 0. 로그는 TEMP/safesys-770-action-lint.txt와 TEMP/safesys-770-action-tests.txt에 저장했다.
- 조정자가 제공한 TEMP 기준 사본 네 개와 diff를 대조했다. 요청 외 동작 변경은 없다. 커밋·스테이징·빌드를 실행하지 않았다.
- 조정자가 실제 브라우저에서 편집 열기·자동 초점·취소 및 기본 기한(2026-10-04 → 2026-10-11), 수동 날짜 보존을 확인했다. 인증된 기존 조회를 사용하되 PATCH는 브라우저에서 모의 응답으로 대체했다. 실패 시 초안 유지, 성공 시 목록 반영, 요청 본문의 조치 내용·날짜 및 사진·지적 보존을 확인했다. 실제 DB 쓰기는 수행하지 않았다.
- 조정자가 린트·타입체크·관련 테스트 39개를 독립 실행했다. 날짜 입력 터치 높이를 44px로 보완했다.
- 대상 컴포넌트·상태·테스트가 작업 시작 전부터 미추적이고 폼에도 선행 변경이 있어, 다른 작업을 함께 포함하는 커밋을 만들지 않고 작업 트리에 유지했다.
- DB read→update 사이 동시 변경 보호는 기존 방식의 한계로 남는다. 부모 목록 새로고침은 컴포넌트를 다시 마운트하므로 성공 저장 뒤 포커스 복귀는 부모 갱신 방식에 영향을 받는다.
