# 비밀번호 찾기 — 이메일 발송 기반 재설정 플로우 전환

작성일 2026-08-02. 사용자 승인 완료(설계·데드 코드 삭제 모두 승인).

## 배경 및 문제

현재 `/login`의 비밀번호 찾기(`FindPasswordModal.tsx`)는 이메일+이름+전화번호를 `user_profiles`와 대조한 뒤 `/api/auth/update-password`(service role)로 비밀번호를 즉시 변경한다. 이메일 소유 확인이 없어, 공개되기 쉬운 개인정보 3가지만 알면 타인 계정의 비밀번호를 바꿀 수 있는 보안 취약점이다.

## 목표 플로우

1. 모달에서 **이메일만** 입력.
2. `supabase.auth.resetPasswordForEmail(email, { redirectTo: origin + '/reset-password' })` 호출.
3. "재설정 링크를 이메일로 발송했습니다" 안내(계정 존재 여부 비노출 — 이메일 열거 방지).
4. 메일 링크 → 기존 `/reset-password` 페이지에서 새 비밀번호 입력 → 로그인 페이지 이동.

`/reset-password` 페이지(`src/app/reset-password/page.tsx`)는 이미 구현되어 있고 현재 클라이언트 설정(implicit flow + `detectSessionInUrl`)과 호환되므로 수정 없이 재사용한다.

## 컨텍스트 노트

- 대안 검토 — 이름·전화번호 확인 후 발송하는 절충안은 표준 플로우 대비 마찰만 늘어 제외. 자체 OTP 구현은 Supabase 내장 기능 재발명이라 제외.
- `resetPasswordForEmail`은 미가입 이메일에도 성공을 반환하므로 계정 존재 여부 비노출이 자동 충족된다.
- Supabase는 동일 주소 재발송에 레이트 리밋(기본 60초)을 적용한다. 레이트 리밋 오류는 "잠시 후 다시 시도해주세요"류의 일반 메시지로 처리한다.
- 발송 인프라는 회원가입 인증 메일이 이미 운영 중이므로 재사용 가능하다고 판단(project_unverified_cleanup 메모리 참조).
