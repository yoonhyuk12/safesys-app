# 사고보고 출력 서식 작업 보고

제품 코드 변경은 동결했다. 사용자 최신 지시인 본문 1쪽 + 사진대지 1쪽을 구현했으며 추가 제품 수정은 없다.

## 변경

- 일반 본문 입력을 휴먼명조 동일 역할 서식으로 통일했다. 기본 14pt/장평100/자간0/줄간격130%를 먼저 적용한다.
- 줄간격130→120→110→100%, 장평95→90→85% 및 자간-2→-4→-5 순서로 적합하고, 부모 승인에 따라 마지막에 본문 전체를13→12pt로 균일 축소한다. 제목·항목명·연락처11pt·사진설명13pt·PUA 글꼴·사진2컷 구조는 보존한다.
- 공백 패딩을 제거하고 첫 문단 내어쓰기와 이어지는 문단 왼쪽 여백을 공통 정의로 생성한다. 선택한 크기/장평/자간을 접두어 폭과 높이 계산에도 적용한다.
- CRLF/CR/LF를 모두 처리하며 중간 빈 줄과 입력 공백을 보존한다. 본문이 하한에서도 넘치면 내용 삭제/요약/3쪽 출력 대신 줄여 달라는 오류를 반환한다.
- 보고요지 상단의 빈 장식 셀을 글줄로 과다 추정하던 계산을 바로잡고, 내용 행만 실제 높이에 맞췄다. 원본 표의 폭·주소·병합 및 상단 장식은 보존한다.
- 템플릿 정제 스크립트와 정제 HWPX를 함께 갱신했다. 원본 header 정의는 그대로 유지하고 출력 시 필요한 문단 모양 및 적합 서식만 추가/변경한다.

## 검증

- RED 확인. 기존 출력은 빈 줄을 삭제하고 CR을 그대로 두며 수동 이어쓰기에 공백을 삽입했다.
- 최신 HWPX 회귀47개 PASS, FAIL0. 글꼴/PUA/원본 격자/사진 비율/미디어 참조/개행·빈줄/자동·수동 여백/적합 하한/과다 장문 오류를 확인했다.
- 최종 사고보고 전체237개 중236 PASS, FAIL0, 기존TODO1. 최종 코드에서 전체 명령 exit0을 확인했다. 기존TODO는 계정삭제 시 SET NULL과 작성자변경 방지 트리거 충돌이며 이번 변경과 무관하다.
- `npx tsc --noEmit` exit0.
- `npm run lint` exit0. 기존 프로젝트 경고는 남아 있으며 변경 파일 관련 경고는 없다.
- 부모 synthetic 입력/생성 하니스를 읽어 실제 생성 성공을 확인했다. 부모 scratch 파일은 수정하지 않았다.
- 부모가 한글2022 Open/Save/Reopen/PDF 및 실제 브라우저 검증 수행. 실제 저장 보고서와 파주 표본 및 최신 synthetic 모두 실제2쪽 PASS. 저장 보고서의 공백/글머리 제외807자 동일, 파주13개 입력문장과 synthetic25개 입력줄 모두 페이지1, 사진2컷은 페이지2다.
- 부모 PDF 실측. synthetic 자동wrap/수동개행/빈줄 뒤 시작 x=142.56으로 동일. y=377.28/389.28/413.28로12pt 빈줄 보존. 테두리/페이지 영역 밖 텍스트 없음.

## 한계와 인계

한컴 조판 전의 적합 계산은 보수적인 폭 추정이다. 첫 내용 시작과 이어지는 줄은 접두어 글꼴 실폭 차이로 몇 픽셀 차이가 있을 수 있으나, 자동·수동 이어쓰기는 동일 좌표이며 부모가 현재 정렬을 승인했다. 임의의 초장문은 가독성 하한을 넘기지 않고 오류로 안내한다.

빌드·추가Worker·COM·라이브AI·브라우저·커밋·푸시는 Worker가 실행하지 않았다. API/AI/SQL/DB 데이터 및 원본 public/사고와 사용방법.md는 수정하지 않았다.

## 기본 작업의 최종 리뷰 보완

연락처 입력의 빈 줄60개가 높이에서 빠지는 문제를 RED로 재현한 뒤, 높이 제외를 보고요지 상단 장식2행에만 한정했다. 독립적인200자 사진설명2개 회귀를 복구해 사진행 축소·설명행 확대·끝 문구·총2쪽 구조를 검증했다. 이후 HWPX47개, 전체사고보고237개, tsc, lint를 모두 다시 실행했다. git diff --check도 통과했다.

raw 로그와 synthetic.hwpx는 ignored safesys-app/scratch/typography-worker/에 보관한다. 최종 결과는 위 요약이 정본이다.

## 고정 문단 줄바꿈 후속 수정

피해자 인적사항 머리는 기존 bullet 문단 모양을 재사용하고, 신고·사고자 조치 체크줄은 왼쪽 여백 1960·내어쓰기 0의 checks 문단 모양을 추가했다. 세 문단의 선행 공백만 제거하며 원문, PUA 체크 글자와 선택 상태, run의 charPrIDRef 및 fontRef는 유지한다. 새 문단 모양도 기존 FORMATS를 통해 실제 문단 서식과 폭·높이 적합 계산에 함께 반영된다. 본문 14→13→12pt 적합 단계와 사진 구조는 변경하지 않았다.

회귀는 기존 paraPr 21 때문에 RED인 것을 확인한 뒤 GREEN으로 전환했다. 후속 HWPX 테스트 48개 PASS, 타입체크 PASS, 린트 PASS(기존 저장소 경고), git diff --check PASS다. 위 전체 사고보고 236 PASS·기존 TODO 1 및 HWPX 47 PASS와 한글 실측은 기본 작업 결과이며, 이번 후속에서는 전체 사고보고 테스트 및 COM을 재실행하지 않았다. 부모에게 코드 준비 status를 전송했으며 후속 COM/PDF 시각 검증·최종 리뷰·커밋은 부모가 수행한다. 후속 테스트 로그는 safesys-app/scratch/typography-final-followup/에 있다.

부모 최종 확인도 완료했다. 최종 사고보고 전체 238개 중 237 PASS·FAIL 0·기존 TODO 1이다. 후속 코드의 브라우저 저장·다운로드와 한글2022 실제 2쪽, 본문 25줄·사진 2컷 보존, 체크줄 정렬 및 긴 사진 설명 2개를 검증했다. 자세한 결과는 verification.md에 기록했다. Worker 두 개 모두 성공 종료 후 회수했다.
