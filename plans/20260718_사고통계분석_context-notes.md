# 사고 통계 분석 컨텍스트 노트

- 사용자 확정 범위는 정기안전점검, 관리자점검, 본부불시점검 3종이다.
- 아차사고는 저장하거나 통계에 포함하지 않는다.
- 점검 수준은 단일 종합점수가 아니라 강도, 수행 완결성, 위험 신호로 나눈다.
- 지적 건수가 많다는 사실은 현장이 위험하거나 점검이 충실했다는 두 의미가 모두 가능하므로 종합점수로 단정하지 않는다.
- 모든 발주청 사용자는 자신의 조직 관할 사고와 분석을 조회한다.
- 본부급 이상 판정은 기존 `canSeeAllHq` 의미를 따르되, 본부 사용자의 쓰기 범위는 소속 본부로 제한한다.
- 본사 또는 `hq_division`이 없는 조직 관리자급은 전사 프로젝트를 관리한다.
- 기본 기간은 최근 12개월이고 사고 전 30일·90일 점검 이력을 비교한다.
- 근로자 등록 수와 TBM 입력 인원은 신뢰할 근로자-일 분모가 아니므로 1차 사고율 분모로 사용하지 않는다.
- 프로젝트-월을 관측 단위로 사용하고 100 프로젝트-월당 사고 건수를 보조로 표시한다.
- 사고 미등록 월은 관측 프로젝트-월에서 사고 0건으로 계산하되 신고 누락 가능성을 화면 주의문에 표시한다.
- 표본이 작은 경우 관계 수치를 확정적으로 해석하지 않고 `표본 부족` 상태를 표시한다.
- 오래된 `safesys-app/database/schema.sql`의 `incident_reports`는 `project_id`가 없고 역할 값이 현행 체계와 달라 재사용하지 않는다.
- 신규 테이블 이름은 충돌을 피하기 위해 `project_accidents`를 사용한다.
- 피해자 성명, 연락처, 주민등록번호 등 개인 식별정보는 분석 목적에 필요하지 않아 저장하지 않는다.
- 정기안전점검 기존 집계 함수는 준공 프로젝트를 제외하므로 사고 이력 분석 전용 조회를 만든다.
- 신규 DB 자식 테이블은 `ON DELETE CASCADE`, `merge_projects`, 프로젝트 삭제 연관 건수에 모두 반영한다.
- 차트 라이브러리는 추가하지 않고 기존 Tailwind UI 패턴을 따른다.
- 프로덕션 빌드는 사용자 동의 없이 실행하지 않는다.
- 관측 프로젝트-월은 공사기간과 겹치는 월에 실제 사고·3종 점검 기록 월을 합집합으로 더해, 공사기간 경계 밖의 실제 기록이 숨지 않게 한다.
- 동시 작업 중인 작업계획서 카드가 같은 `Dashboard.tsx`에 존재하므로 사고 카드 변경만 부분 스테이징하고 해당 변경은 보존한다.
- 기존 3000번 개발 서버는 HTTP 500이지만 별도 3001번 서버에서는 `/safe`와 `/safe/accident-analysis`가 정상 컴파일되고 HTTP 200으로 응답했다.
- 3001번 브라우저 세션은 감리 계정이어서 발주청 전용 분석 화면과 CRUD는 정적 검증까지만 완료했다.
- `database/20260718-0506_add_project_accidents.sql`은 작성했지만 원격 데이터베이스에는 아직 적용하지 않았다.
