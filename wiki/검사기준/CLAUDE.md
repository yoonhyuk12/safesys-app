# 검사 기준 위키 — 스키마(SCHEMA)

이 디렉토리는 **건설공사 공종단계별 검사 기준**에 대한 LLM 위키다. `llm-wiki.md` 패턴을 따른다. 이 문서는 위키를 유지하는 LLM에게 구조·규칙·워크플로를 알려주는 설정 파일이다. 사용자는 자료를 큐레이션하고 질문하며, LLM은 읽기·요약·교차참조·정리 등 뒷정리를 전담한다.

## 1. 레이어

- **Raw sources(원본)** — `safesys-app/public/`의 원본 PDF 등. 불변이다. LLM은 읽기만 하고 절대 수정하지 않는다.
- **The wiki(위키)** — 이 디렉토리의 마크다운 파일. LLM이 생성·갱신·교차참조를 전담한다. 사용자는 읽고, LLM이 쓴다.
- **The schema(스키마)** — 이 파일(`CLAUDE.md`). 위키 구조와 규칙을 정의한다. 사용자와 LLM이 함께 진화시킨다.

## 2. 디렉토리 구조

```
wiki/검사기준/
├── CLAUDE.md        # 이 스키마 파일
├── index.md         # 전체 페이지 카탈로그 (인제스트마다 갱신)
├── log.md           # append-only 작업 로그
├── overview.md      # 검사 기준 개요 + 적용요령
├── 자재부재검사기준.md  # 건설공사용 자재·부재 검사 기준 + 시험빈도
├── sources/         # 원본 자료별 요약 페이지
├── 개념/            # 횡단 개념 (검사방법·검사시기·책임검사지정)
└── 시설물/          # 시설물 유형별 검사 매트릭스 (공통·저수지·양배수장·방조제)
```

## 3. 핵심 데이터 모델 — 검사 매트릭스

검사 기준은 본질적으로 다차원 매트릭스다. 모든 시설물 페이지는 이 5개 축으로 정리한다.

| 축 | 의미 | 값 예시 |
|----|------|---------|
| **시설물** | 무엇을 짓는가 | 공통, 저수지, 양·배수장, 방조제(방수제) |
| **공종(분류)** | 어느 단계/부위인가 | 측량, 구조물, 시공단면, 기초처리, 암반정, 담수 … |
| **검사 대상** | 구체적으로 무엇을 보는가 | "철근 두께·규격·간격", "거푸집 존치기간" … |
| **검사방법** | 어떻게 보는가 | 검측 · 검사 · 시험 · 점검 · 검수 · 검토 → [[검사방법]] |
| **시기** | 언제 보는가 | 타설전 · 완료시 · 매립전 · 수시 · 시공전후 · 분기별 · 2회이상 … → [[검사시기]] |
| **책임** | 누가 하는가 | 감독원 · 지역본부 사업단 · 본사 주관부서 → [[책임검사지정]] |

## 4. 페이지 규칙(convention)

- **파일명** — 한글, 공백 없이. 시설물/개념 페이지는 핵심 명사 하나(예: `공통.md`, `검사방법.md`).
- **프론트매터** — 모든 페이지 상단에 YAML.
  ```yaml
  ---
  title: 페이지 제목
  type: 시설물 | 개념 | 개요 | 원본요약 | 자재
  source: 별표1_공종단계별검사기준   # 근거 원본 (sources/ 페이지명)
  tags: [검사기준, ...]
  updated: YYYY-MM-DD
  ---
  ```
- **첫 줄 주석** — 프론트매터 위에 `<!-- 한 줄 한국어 설명 -->`로 페이지 역할을 명시한다.
- **교차참조** — Obsidian 위키링크 `[[페이지명]]`을 쓴다(확장자 제외, 파일 basename 기준). 링크를 아끼지 말 것.
- **검사 매트릭스 표** — 시설물 페이지의 표 컬럼은 통일한다.
  `| 공종(분류) | No | 검사(검측) 대상 | 검사방법 | 시기 | 책임 |`
  - 책임 열은 약칭 사용 — `감독원` / `지역본부` / `본사`. 복수면 쉼표로.
- **불확실 셀** — 원본 판독이 불확실하면 텍스트 뒤에 `(?)`를 붙이고, 페이지 하단 "판독 주의" 절에 모은다. 추측으로 단정하지 않는다.
- **한국어 문장은 마침표로 끝낸다** — 콜론으로 문장을 끝내지 않는다(표·라벨 내 콜론은 허용).

## 5. 워크플로

### Ingest(인제스트)
1. 원본을 읽는다(이미지 PDF는 렌더링 후 판독). 핵심을 사용자와 논의한다.
2. `sources/`에 원본 요약 페이지를 쓰거나 갱신한다(출처·발행처·범위·판독 한계 기록).
3. 해당하는 시설물/개념 페이지를 갱신한다. 자료 하나가 여러 페이지를 건드릴 수 있다.
4. `index.md`를 갱신한다.
5. `log.md`에 인제스트 항목을 추가한다.

### Query(쿼리)
1. `index.md`를 먼저 읽어 관련 페이지를 찾는다.
2. 관련 페이지를 읽고 출처와 함께 답을 종합한다.
3. **좋은 답(비교표·분석·점검표 초안 등)은 새 위키 페이지로 다시 저장한다.** 탐색이 누적되도록.
4. `log.md`에 쿼리 항목을 추가한다.

### Lint(린트)
주기적으로 위키 건강검진을 한다. 점검 항목 — 페이지 간 모순, 최신 자료가 뒤집은 낡은 주장, 인바운드 링크 없는 고아 페이지, 별도 페이지가 필요한 개념, 누락된 교차참조, 웹/추가자료로 메울 데이터 공백. 결과는 `log.md`에 기록한다.

## 6. 로그 규칙

`log.md`는 append-only이며 각 항목은 일관된 접두로 시작한다 — `## [YYYY-MM-DD] ingest|query|lint | 제목`. 이러면 `grep "^## \[" log.md | tail -5`로 최근 이력을 뽑을 수 있다.

## 7. 용어·약칭

- **공감소(감독원)** — 현장 공사감독/감리. 책임 열 약칭 `감독원`.
- **지역본부 사업단** — 시공 주체. 약칭 `지역본부`.
- **본사 주관부서** — 본사 책임검사 부서. 약칭 `본사`.
- **공종** — 공사 종류/단계.
- **검측 / 검사 / 시험 / 점검 / 검수 / 검토** — 검사방법 구분. 정의는 [[검사방법]] 참조.

## 8. 출처·정확도 주의

현재 위키의 유일 원본은 `[별표 1] 공종단계별 검사기준.pdf`다. 이 PDF는 한글 폰트에 ToUnicode 매핑이 없어 텍스트 추출이 깨진다. 내용은 페이지를 이미지로 렌더링해 시각 판독한 것이라 작은 글씨 셀에 오독 가능성이 있다. 각 페이지의 "판독 주의" 절을 신뢰하고, 현장 적용 전에는 원본 PDF와 대조한다.
