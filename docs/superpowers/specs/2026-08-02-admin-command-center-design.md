# SafeSys 관리자 Command Center 디자인 명세

## 목표

기존 `/admin/users`와 `/admin/projects`의 데이터 조회·관리 기능을 유지하면서 관리자 영역을 신뢰감 있고 세련된 운영 콘솔로 개편한다. 데스크톱에서는 많은 정보를 빠르게 비교할 수 있는 정렬 테이블을 제공하고, 모바일에서는 접힌 목록을 먼저 보여준 뒤 선택한 항목의 상세와 관리 작업을 펼쳐 편하게 사용할 수 있게 한다.

## 범위

- 관리자 공통 레이아웃과 내비게이션의 Midnight Command 스타일 개편.
- 가입자 관리 화면의 통계, 검색·필터, 목록, 상태, 관리 작업 시각 개선.
- 프로젝트 현황 화면의 통계, 본부별 현황, 검색·필터, 목록, 상태, 관리 작업 시각 개선.
- 두 관리 테이블의 작업 열을 제외한 모든 데이터 열에 3단계 정렬 추가.
- 767px 이하 화면에서 테이블을 접기·펼치기 목록으로 전환.
- 로딩, 오류, 알림, 빈 결과, 모달 상태의 일관된 스타일 적용.

## 범위에서 제외하는 항목

- `/api/admin/*` 응답 구조와 인증·권한 정책 변경.
- 가입자 또는 프로젝트 데이터 모델 변경.
- 새로운 관리자 기능이나 통계 API 추가.
- 프로젝트 삭제·가입자 인증·수정·삭제 동작 변경.
- 신규 UI 패키지 설치.

## 데이터베이스와 SQL 영향

이번 개편은 화면 구성과 클라이언트 정렬 동작만 변경하므로 새 SQL 마이그레이션이 필요하지 않다.

- 가입자 인증 처리는 기존 `POST /api/admin/users/[id]/confirm`이 `supabaseAdmin.auth.admin.updateUserById(id, { email_confirm: true })`를 호출해 Supabase Auth의 이메일 인증 상태를 변경한다.
- 가입자 프로필 수정은 기존 서버 라우트가 service-role 클라이언트로 `public.user_profiles`를 갱신한다.
- 가입자 계정 삭제는 기존 Auth Admin API와 프로필 정리 로직을 유지한다.
- 프로젝트 조회와 삭제는 기존 관리자 조회 API 및 Storage 정리·DB cascade를 포함한 프로젝트 삭제 API를 유지한다.
- 관리자 API는 기존 Bearer 토큰, `ADMIN_EMAILS` 허용목록, OTP 인증 수단 검사로 보호한다.

관리자 권한을 DB 컬럼과 RLS 정책으로 이전하거나 관리자 작업 감사 로그를 새로 저장하는 요구가 추가되면 별도 데이터베이스 명세와 SQL 마이그레이션을 작성한다. 해당 변경은 이번 범위에 포함하지 않는다.

## 디자인 방향

선택한 시각 방향은 `A. Midnight Command`다.

- 짙은 네이비 내비게이션과 밝은 청회색 콘텐츠 배경을 사용한다.
- 흰색 데이터 카드에 블루·민트·앰버를 상태 포인트로 제한해 사용한다.
- 장시간 데이터를 읽어도 피로하지 않도록 본문과 테이블은 밝은 배경을 유지한다.
- 수치에는 tabular number 스타일을 적용하고 제목, 보조 설명, 데이터, 상태의 위계를 분명히 한다.
- 과한 글래스 효과나 그라디언트는 브랜드 마크와 제한된 강조 영역에만 사용한다.

## 공통 레이아웃

### 데스크톱과 태블릿

- 왼쪽에 SafeSys 브랜드, `가입자 관리`, `프로젝트 현황`, `메인으로`를 포함한 네이비 사이드바를 배치한다.
- 현재 메뉴는 블루 강조 배경과 선명한 텍스트로 표시한다.
- 콘텐츠 영역은 기존 `max-w-6xl`보다 넓혀 긴 관리자 테이블의 가독성을 높인다.
- 페이지 상단에는 영문 eyebrow, 한국어 제목, 설명, 관리자 상태, 새로고침 버튼을 배치한다.
- 통계 카드는 핵심 수치와 상태를 아이콘·색·짧은 보조 문구로 구분한다.

### 모바일

- 767px 이하에서는 사이드바 대신 네이비 상단 브랜드 바와 두 개의 탭 내비게이션을 사용한다.
- 터치 가능한 버튼과 컨트롤의 최소 높이는 44px로 한다.
- 통계 카드는 한 줄 가로 스크롤로 제공해 본문 세로 공간을 과도하게 차지하지 않는다.
- 검색은 한 줄 전체 너비로 배치하고, 그 아래에 정렬과 필터 컨트롤을 배치한다.

## 화면별 구성

### 가입자 관리

- 전체, 발주청, 감리단, 시공사, 미인증 통계를 카드로 보여준다.
- 이름·이메일·회사 검색, 역할 필터, 미인증 필터를 유지한다.
- 데스크톱 표는 이름, 이메일, 역할, 본부·지사, 회사, 직책, 가입일, 최근 로그인, 인증 상태, 작업 열로 구성한다.
- 기존 이메일 인증, 정보 수정, 계정 삭제 작업을 유지한다.
- 수정 모달도 Midnight Command의 표면, 입력, 포커스, 버튼 스타일에 맞춘다.

### 프로젝트 현황

- 전체, 활성, 비활성, 최근 30일 등록 통계를 카드로 보여준다.
- 본부별 등록 현황, 본부·지사 필터, 프로젝트명·등록자 검색, 활성 필터를 유지한다.
- 데스크톱 표는 프로젝트명, 본부, 지사, 등록자, 등록일, 상태, 관리 열로 구성한다.
- 기존 프로젝트 상세 새 창 열기와 삭제 작업을 유지한다.

## 정렬 설계

### 공통 상태와 순환

- 정렬 상태는 `정렬 없음`, `오름차순`, `내림차순` 세 가지다.
- 데이터 열 제목을 누를 때 `정렬 없음 → 오름차순 → 내림차순 → 정렬 없음` 순으로 순환한다.
- 다른 열을 누르면 해당 열의 오름차순 정렬로 즉시 전환한다.
- 정렬 없음으로 돌아오면 API가 내려준 최초 순서를 복원한다.
- 작업 열은 정렬 대상에서 제외한다.
- 검색, 필터 또는 정렬 조건이 바뀌면 현재 페이지를 첫 페이지로 되돌린다.

### 처리 순서

데이터 처리 순서는 다음과 같이 고정한다.

1. API 원본 목록을 보존한다.
2. 검색어와 필터 조건을 적용한다.
3. 필터링된 전체 결과를 현재 정렬 기준으로 안정 정렬한다.
4. 정렬된 결과를 페이지 크기에 따라 나눈다.
5. 현재 화면 크기에 따라 데스크톱 표 또는 모바일 목록으로 렌더링한다.

이 순서로 현재 페이지의 일부 행만 정렬되는 문제를 방지한다.

### 값 비교 규칙

- 한국어 문자열은 `ko-KR` locale 비교를 사용한다.
- 날짜는 화면 문자열이 아니라 타임스탬프 값으로 비교한다.
- boolean 상태는 인증·활성 여부의 실제 boolean 값으로 비교한다.
- `null`, 빈 문자열, 유효하지 않은 날짜는 오름차순과 내림차순 모두 마지막에 둔다.
- 동일한 값은 API 원본 순서를 유지하는 안정 정렬을 사용한다.

### 데스크톱 조작

- 각 정렬 가능 헤더 전체를 버튼으로 제공한다.
- 정렬하지 않은 열에는 중립 아이콘, 활성 열에는 위·아래 방향 아이콘을 표시한다.
- 현재 정렬 상태를 `aria-sort`와 화면 낭독기용 문구로 함께 제공한다.

### 모바일 조작

- 모바일에는 44px 이상의 `정렬 기준` 컨트롤과 `정렬 방향` 컨트롤을 제공한다.
- 모든 데이터 열을 정렬 기준에서 선택할 수 있다.
- 기본 순서 복원 동작을 명시적으로 선택할 수 있다.
- 데스크톱과 모바일은 동일한 정렬 상태와 결과를 사용한다.

## 모바일 목록과 상세 펼치기

- 최초 진입 시 모든 가입자·프로젝트 상세 영역은 닫힌 상태다.
- 접힌 가입자 행에는 이름, 이메일, 역할, 인증 상태를 표시한다.
- 접힌 프로젝트 행에는 프로젝트명, 본부·지사, 활성 상태를 표시한다.
- 행 전체를 하나의 큰 터치 대상으로 만들고 펼침 상태를 아이콘과 `aria-expanded`로 표시한다.
- 행을 누르면 상세 데이터와 수정·인증·열기·삭제 등 해당 작업 버튼을 펼친다.
- 한 번에 한 행만 열리며 다른 행을 열면 기존 행은 닫힌다.
- 열린 행을 다시 누르면 닫힌다.
- 검색, 필터, 정렬, 페이지 이동, 데이터 새로고침 시 열린 행을 닫는다.
- 상세 안의 작업 버튼을 눌렀을 때 행 토글 이벤트가 중복 실행되지 않도록 이벤트 경계를 분리한다.

## 상태와 오류 처리

- 최초 로딩과 새로고침은 레이아웃이 크게 흔들리지 않는 스켈레톤 또는 인라인 진행 상태로 표시한다.
- API 오류는 페이지 안의 접근 가능한 경고 카드로 표시하고 다시 시도 작업을 제공한다.
- 성공 알림은 민트 계열 알림으로 표시한다.
- 검색 결과가 없을 때는 현재 필터 조건을 해제할 수 있는 안내를 제공한다.
- 삭제와 같은 위험 작업은 레드 계열로 구분하고 기존 확인 절차를 유지한다.
- 처리 중에는 중복 요청을 막되 다른 읽기 작업의 상태를 불필요하게 막지 않는다.

## 컴포넌트와 코드 경계

- 공용 관리자 레이아웃은 인증 가드와 반응형 내비게이션만 담당한다.
- 정렬 타입, 3단계 전환, 값 비교, 안정 정렬은 재사용 가능한 공용 모듈로 분리한다.
- 정렬 가능한 데스크톱 헤더와 모바일 정렬 컨트롤은 공용 컴포넌트로 분리한다.
- 각 페이지는 자신의 필터 상태, 현재 페이지, 펼친 행 ID, 데이터별 열 정의를 소유한다.
- 가입자 수정 모달과 기존 서버 요청 함수는 현재 책임을 유지한다.
- API 라우트와 데이터 타입은 변경하지 않는다.

## 접근성과 반응형 기준

- 모든 아이콘 버튼은 접근 가능한 이름을 갖는다.
- 정렬 헤더는 키보드로 조작할 수 있어야 한다.
- 모바일 행은 `aria-expanded`와 상세 영역 연결 정보를 제공한다.
- 포커스 표시를 배경과 구별되는 블루 링으로 통일한다.
- 상태는 색만으로 구분하지 않고 텍스트와 아이콘을 함께 사용한다.
- 390px 너비에서 본문이 좌우로 넘치지 않아야 한다.
- 데스크톱 데이터 표는 필요한 최소 너비를 유지하고 콘텐츠 영역 안에서만 가로 스크롤할 수 있다.

## 테스트와 검증

### 자동 검증

- 정렬 없음·오름차순·내림차순 순환을 테스트한다.
- 다른 열 선택 시 오름차순으로 전환되는 동작을 테스트한다.
- 한국어 문자열, 날짜, boolean 상태, 빈 값의 비교 결과를 테스트한다.
- 동일 값의 원본 순서가 유지되는지 테스트한다.
- 필터 이후 정렬하고 정렬 이후 페이지를 나누는 순서를 테스트한다.
- TypeScript 타입 검사를 실행한다.
- ESLint를 실행한다.

### 수동 브라우저 검증

- `/admin/users`와 `/admin/projects`를 데스크톱 너비에서 확인한다.
- 각 데이터 열의 3단계 정렬과 기본 순서 복원을 확인한다.
- 390px 너비에서 접힌 목록, 한 행 펼치기, 다른 행으로 전환, 다시 닫기를 확인한다.
- 모바일 정렬과 데스크톱 정렬 결과가 동일한지 확인한다.
- 검색·필터·정렬·페이지 변경 후 펼친 행이 닫히는지 확인한다.
- 로딩, 오류, 빈 결과, 성공 알림, 수정 모달, 삭제 확인 상태를 확인한다.

프로덕션 빌드는 저장소 규칙에 따라 사용자 동의 없이 실행하지 않는다.

## 완료 기준

- Midnight Command 시각 체계가 두 관리자 페이지와 공통 레이아웃에 일관되게 적용된다.
- 작업 열을 제외한 모든 데이터 열이 지정한 3단계 방식으로 정렬된다.
- 정렬은 필터링된 전체 결과에 적용된 뒤 페이지 분할된다.
- 767px 이하에서 표 대신 접힌 목록이 먼저 표시되고 선택한 한 항목만 상세로 펼쳐진다.
- 390px 모바일 화면에서 검색·필터·정렬·상세 확인·관리 작업을 가로 스크롤 없이 수행할 수 있다.
- 기존 관리자 인증과 가입자·프로젝트 관리 기능이 유지된다.
- 정렬 자동 테스트, ESLint, TypeScript 검사가 통과한다.
