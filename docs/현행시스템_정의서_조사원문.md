# SafeSys 현행 시스템 코드 조사 원문

> 조사 기준일 2026-09-03. 저장소에서 확인한 사실만 기록했다. 환경 변수는 이름만 기록하고 값은 기록하지 않았다.

## 1. 소프트웨어 구성

### 패키지와 런타임

- 앱 패키지는 `safesys-app`, 버전은 `0.1.0`이다. 핵심 선언 버전은 Next.js `^15.5.0`, React/React DOM `19.1.2`, TypeScript `^5`, `@supabase/supabase-js` `^2.53.0`, `@supabase/auth-ui-react` `^0.4.7`, `@supabase/auth-ui-shared` `^0.1.8`, Supabase CLI `^2.31.8`이다. 근거: `safesys-app/package.json:2-4`, `safesys-app/package.json:12-14`, `safesys-app/package.json:29-32`, `safesys-app/package.json:51`, `safesys-app/package.json:54`.
- `package-lock.json`의 실제 설치 버전은 Next.js `15.5.12`, React `19.1.2`, React DOM `19.1.2`다. 근거: `safesys-app/package-lock.json`의 `packages.node_modules/next`, `packages.node_modules/react`, `packages.node_modules/react-dom` 항목.
- `package.json`에 `engines`가 없고 저장소에서 `.nvmrc`, `.node-version`도 발견되지 않았다. Node.js 최소/권장 버전은 코드에서 확인 불가 — 확인 필요: Vercel 프로젝트의 Node.js Runtime 설정과 개발 표준 Node 버전.
- App Router API 중 명시적 런타임 선언은 `nodejs` 2건이며 Edge 런타임 선언은 발견되지 않았다. 근거: `safesys-app/src/app/api/weather/warnings/route.ts:18`, `safesys-app/src/app/api/hwp/safety-inspection/route.ts:8`.
- `middleware.ts`/`middleware.js`는 발견되지 않았다. 인증은 클라이언트 컨텍스트와 각 API의 개별 검증 코드에 분산돼 있다. 근거: `safesys-app/src/contexts/AuthContext.tsx:84`, `safesys-app/src/providers/SupabaseProvider.tsx:22-35`.

### API 라우트

- `safesys-app/src/app/api/**/route.ts`는 총 74개다. 최상위 그룹별로 `admin` 10, `ai` 18, `weather` 5, `g2b` 7, `projects` 7, `tbm-telegram` 3, `tbm-view` 2, `chat` 2, `telegram` 2, 나머지 단일 라우트 18개(`app-alert`, `board`, `bulk-sign`, `csi`, `find-id`, `geocoding`, `hwp`, `living-weather-index`, `manager-inspections`, `map-tile`, `quality-summary`, `risk-db` 2, `tbm-today`, `test-apparent-temp`, `weather-crawl`, `weather-region-code`)다. 근거: `safesys-app/src/app/api/` 하위 `route.ts` 전수 파일 목록.
- 기능은 관리자/OTP/AI 사용량, AI 생성·분류·OCR·TTS, 프로젝트 CRUD·병합, 서명, 기상, 나라장터·CSI, 지도/주소, Telegram·알림앱, TBM 조회·발송으로 나뉜다. 근거: 위 API 디렉터리명과 각 `route.ts`.

### PWA, 빌드, 배포 파일

- 별도 `next-pwa`/Serwist 의존성은 없다. 자체 `public/sw.js`를 프로덕션에서 등록하고 업데이트 감지 UI를 둔다. 근거: `safesys-app/src/components/common/ServiceWorkerRegistration.tsx:8-24`, `safesys-app/src/components/common/UpdateNotifier.tsx:9-20`, `safesys-app/public/sw.js:1-6`.
- 웹 앱 매니페스트는 이름/short name `AI안전관리`, `display: standalone`, 세로 우선, SVG 아이콘 48~512px로 구성된다. 근거: `safesys-app/public/manifest.json:2-46`, `safesys-app/src/app/layout.tsx:23`.
- Next 설정은 빌드 중 ESLint·TypeScript 오류 무시, 전 경로 no-cache 헤더, `output: 'standalone'`이다. 근거: `safesys-app/next.config.ts:4-10`, `safesys-app/next.config.ts:15-34`.
- Vercel 설정은 `npm install --legacy-peer-deps`, `next build`만 지정한다. 함수 memory/maxDuration 및 region 설정은 없다. 근거: `safesys-app/vercel.json:2-3`.
- `safesys-app/.vercel/project.json`이 존재하며 프로젝트명은 `safesys-app`이다. Dockerfile/docker-compose는 발견되지 않았다. `safesys-app/netlify.toml`도 있어 Netlify Next.js 플러그인 기반 병행 배포 설정이 있다. 근거: `safesys-app/.vercel/project.json:1`, `safesys-app/netlify.toml:1-11`.

## 2. 배포 환경·인프라

- `main` 푸시가 Vercel 운영 자동 배포를 유발한다고 문서화돼 있다. 로컬 `.env.local`이 아니라 Vercel Production 환경 변수를 사용한다. 근거: `docs/environment.md:31-36`, `docs/environment.md:72-89`.
- Supabase 프로젝트 접속은 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, 서버 관리 작업은 `SUPABASE_SERVICE_ROLE_KEY`를 쓴다. 실제 URL/ref/키 값은 기록하지 않았다. 근거: `safesys-app/src/lib/supabase.ts:11-12`, `safesys-app/src/lib/supabase-admin.ts:8-9`.
- 서버 사양·비용·GPU는 코드에서 확인 불가 — 확인 필요: Vercel 요금제, 함수 CPU/메모리/리전/동시성, Supabase 요금제·리전, GPU 사용 계약. `vercel.json`에는 리소스 힌트가 없다. 근거: `safesys-app/vercel.json:1-4`.
- CCTV는 프로젝트의 RTSP URL을 보관하고 실시간 스트리밍 데이터 제공 및 영상정보 수집·제3자 제공 동의를 받는다. 다만 앱이 실제 영상을 저장·재생하는 구현은 grep에서 확인되지 않고, 외부 `aicctvalert` Edge Function에 알림을 보낸다. 근거: `safesys-app/src/lib/projects.ts:37`, `safesys-app/src/components/auth/TermsAndConditions.tsx:403`, `safesys-app/src/components/worker-consent/ConsentForms.tsx:111-158`, `safesys-app/src/lib/app-alert.ts:1-59`.
- 확인된 Storage 버킷은 `worker-id-cards`, `quality-test-photos`, `work-plans`, `safety-inspection-photos`, `inspection-photos`다. 상수로 사용하는 자재 검사사진 버킷도 존재한다. 근거: `database/20260211-0942_fix_worker_qr_registration_rls.sql:75-93`, `database/20260702-1657_add_quality_test_records_photo.sql:5-27`, `database/20260711-1009_add_work_plans.sql:63-88`, `safesys-app/src/components/project/SafetyInspectionForm.tsx:1298-1300`, `safesys-app/src/app/project/[id]/manager-inspection/page.tsx:1186-1199`, `safesys-app/src/components/project/material/MaterialInspectionPhotoField.tsx:79-116`.

## 3. 본인인증·인증 방식

- 일반 로그인은 Supabase Auth의 email/password 방식(`signInWithPassword`), 가입은 `signUp`이다. OAuth, magic-link OTP, phone Auth용 `signInWith*` 호출은 발견되지 않았다. 근거: `safesys-app/src/lib/auth.ts:71-75`, `safesys-app/src/lib/auth.ts:109-114`, `safesys-app/src/components/auth/PasswordChangeModal.tsx:77`.
- 세션은 `@supabase/supabase-js` 브라우저 클라이언트에서 `persistSession`, `autoRefreshToken`, `detectSessionInUrl`을 활성화하고 `getSession`/`onAuthStateChange`로 관리한다. `@supabase/ssr` 의존성과 서버 쿠키 클라이언트는 없다. 근거: `safesys-app/src/lib/supabase.ts:16-23`, `safesys-app/src/providers/SupabaseProvider.tsx:22-35`.
- 역할은 발주청·감리단·시공사이며 조직은 본부→지사다. 발주청 본부급/관리자는 전사 조회, 감리단·시공사는 소속 지사 조회 패턴이다. 근거: `docs/auth.md:5-21`, `safesys-app/src/lib/supabase.ts:69-72`.
- 관리자 로그인은 자체 이메일 OTP 발송·검증 API와 관리자 세션을 별도로 둔다. 근거: `safesys-app/src/app/api/admin/otp/send/route.ts:23-24`, `safesys-app/src/app/api/admin/otp/verify/route.ts:8-9`, `safesys-app/src/lib/admin-mailer.ts:11-14`.
- PASS/NICE/KCB 휴대폰 본인확인 연동은 발견되지 않았다. 전화번호는 가입 프로필 필드 및 아이디 찾기 입력으로 사용된다. 코드에서 확인 불가 — 확인 필요: 운영상 별도 본인확인 절차 또는 외부 계약 유무. 근거: `safesys-app/src/components/auth/SignUpForm.tsx:147-218`, `safesys-app/src/components/auth/FindIdModal.tsx:61-75`.
- 전자서명은 `react-signature-canvas`로 그린 뒤 `toDataURL()` base64 데이터 URL로 만들며 여러 문서 테이블의 TEXT/JSONB에 저장한다. 작업자 신분증·교육사진·일부 서명 URL은 Storage를 사용한다. 근거: `safesys-app/src/components/project/DailyInspectionSignatureModal.tsx:5-56`, `database/20260709-0634_add_tbm_worker_signatures.sql:15`, `database/20260612-0324_add_ptw_permits_table.sql:17`, `safesys-app/src/app/worker-register/[token]/page.tsx:330-368`.
