# 굴착 작업계획서 표준 양식 분석 브리프 (Codex 워커용)

## 목표

42쪽짜리 굴착 작업계획서 표준 양식 PDF를 분석해, SafeSys 작업계획서 마법사에 5번째 서식(굴착, planType `excavation`)으로 추가하기 위한 **구조화 분석 보고서**를 작성한다. 이 단계에서는 **코드를 수정하지 않는다** — 분석과 보고서 작성만 한다.

## 입력

- 표준 양식 PDF: `C:\Users\Sweet HOME\Downloads\[2021-교육혁신실-835] 굴착 작업계획서 샘플(예시).pdf` (42쪽, 텍스트 레이어 있을 가능성 높음 — HWP 변환본)
- 참고: 같은 폴더에 동명 `.hwp` 원본과 `굴착작업+작업계획서.pdf`, `1. 굴착기 작업계획서 표준서식고용노동부.hwp`도 있으나, 분석 대상은 위 PDF 하나로 한정한다.

## 방법

1. 텍스트 추출: 가용한 도구를 사용한다 (예: `npx -y pdf-parse`, `pdfjs-dist` Node 스크립트, Python `pdfminer.six`/`pypdf` 등). 페이지 단위로 추출해서 페이지 번호를 유지한다.
2. 텍스트 레이어가 없거나 표 구조가 불명확한 페이지는 그 사실을 보고서에 명시한다 (이미지 변환까지는 불필요).
3. 임시 스크립트는 `safesys-app/scratch/` 안에만 만든다.

## 기존 SafeSys 구조 (분류 기준으로 사용)

분석 전에 아래 두 파일을 읽고 기존 4종 서식(하역운반·건설기계·전기·중량물)의 패턴을 파악하라.

- `safesys-app/src/lib/work-plan/types.ts` — `CommonWorkPlanFields`, 서식별 FormData, `MapDrawingData`(작업계획도 지도 드로잉), 서명 역할
- `safesys-app/src/lib/work-plan/constants.ts` — 표지 고정 문구(`WORK_PLAN_COVERS`), 체크리스트, 사전조사 항목(`CONSTRUCTION_SURVEY_ITEMS.excavation` 주목), 안전계수 등

핵심 컨셉: 마법사는 프로젝트 DB에서 현장명·주소·업체·감독관·공사기간·좌표를 자동 인입하고, 법정 고정 문구는 상수로 하드코딩하며, 작업계획도는 지도 드로잉 에디터로 그린다. 사용자는 현장 고유 정보만 입력한다.

## 산출물

`safesys-app/scratch/excavation-plan-analysis.md` 하나로 작성한다. 구성은 다음과 같다.

### 1. 페이지별 목차 (42쪽 전체)

각 페이지에 무엇이 있는지 한 줄씩. 예: "p.3 공사 개요표(발주처·공사명·기간·굴착깊이…)".

### 2. 섹션별 상세 구조

문서를 논리 섹션으로 나누고, 섹션마다 다음을 기록한다.

- 표가 있으면 행·열 헤더를 그대로 옮긴 표 구조
- 서식 입력 칸(빈칸·밑줄·체크박스) 전체 목록
- 샘플(예시)로 채워져 있는 값은 "예시값"으로 표시

### 3. 필드 분류표 (가장 중요)

모든 입력 요소를 다음 4종으로 분류한 표를 만든다.

| 분류 | 의미 |
|------|------|
| A 자동 인입 | 프로젝트 DB에서 채울 수 있음 (현장명·주소·업체명·감독관·공사기간·좌표 등) |
| B 고정 기본값 | 법정 문구·안전수칙·체크리스트·표준 절차 등 보일러플레이트 — 상수로 하드코딩 가능 |
| C 사용자 입력 | 현장 고유 정보라 반드시 입력받아야 함 (굴착 깊이·연장·토질·공법·장비·흙막이 방식 등) |
| D 첨부·드로잉 | 위치도·작업계획도·단면도·사진·서명 등 |

C(사용자 입력)는 최소화하는 방향으로 판단하되, 안전상 현장마다 달라야 하는 값을 B로 뭉개지 않는다.

### 4. B 분류 보일러플레이트 원문 발췌

나중에 `constants.ts`로 옮길 수 있도록, 고정 문구(법정 안내문·안전수칙·체크리스트 항목·표준 작업절차 등)를 **원문 그대로**(띄어쓰기·기호 포함) 발췌한다. 발췌마다 출처 페이지를 표기한다.

### 5. 기존 구조 매핑 및 간소화 제안

- `CommonWorkPlanFields` 중 재사용 가능한 필드
- 작업계획도류가 `MapDrawingEditor`로 대체 가능한지 (몇 장이 필요한지)
- 기존 서명 역할(`WorkPlanSignatureRole`)과 결재란 매핑
- 42쪽 → 사용자 실입력 항목 몇 개로 압축 가능한지 요약 (숫자로)
- 판단이 애매한 항목은 "코디네이터 판단 필요"로 별도 목록화

## 제약

- 소스 코드(`src/`) 수정 금지. 보고서와 임시 스크립트만 생성.
- 보고서는 한국어로 작성.
- 원문 발췌는 요약·의역하지 말 것 (상수화에 그대로 쓸 원문이다).
