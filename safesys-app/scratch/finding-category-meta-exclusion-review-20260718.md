## 3. HIGH — SQL/TS 불일치 (blocker)

로컬 패리티 시뮬레이션 (SQL 1200 로직 vs 현재 TS `isExcludedFindingText`).

| 문장 | SQL | TS | 원인 |
|------|-----|-----|------|
| 공사중지 | NULL | F19_OTHER | TS에 `공사\s*중지` 없음 (일시 중지만 있음) |
| 공사 중지 | NULL | F19_OTHER | 동일 |
| 중지 기간 중 현장 폐쇄 | NULL | F19_OTHER | TS에 `중지\s*기간` 없음 |

### 근본 원인 매핑

| 규칙 | SQL (정본 권장) | TS (현재) |
|------|-----------------|-----------|
| 준비중 | `공사[[:space:]]*준비중`, `준비중으로` 만 | **`/준비중/` 전역** → 과잉제외 |
| 공사 중지 | `공사[[:space:]]*중지` | **없음** → 과소제외 |
| 중지 기간/상태 | `중지[[:space:]]*기간`, `중지된[[:space:]]*상태` | **없음** → 과소제외 |
| 복합 공사…없/해당 | (작업없음·해당 없음으로 대부분 커버) | 추가 `/공사\s*(중지로\|…\|준공).{0,40}(없\|해당)/` — `해당` 단독 가지가 SQL보다 넓을 수 있음 |
| compact | `작업없음`, `현장작업없음` | `작업없음`, `관련작업없음` (현장작업없음 누락 — 정규식으로 대부분 보완) |
| 지적사항 별도 없음 | 명시 패턴 (DEFECT 무관 early NULL) | **없음**. 단독 문장 시 SQL NULL / TS 잔류 가능 |

### 영향
- 마이그레이션 적용 후 **DB 저장코드 = SQL**, 앱은 `resolveFindingCode`가 저장코드를 우선 → 대부분 DB 따름.
- 저장코드 NULL·미적용 구간·재분류 전 fallback은 **TS** → bare 준비중 과잉제외로 통계 누락, 공사 중지는 F19로 잔류.
- 사고분석 UI와 DB 리포트가 어긋날 수 있음.

## 4. 정확한 수정 권고 (TS를 SQL에 맞출 것 — 권장)

`finding-classification.ts`의 `isExcludedFindingText` 메타 블록을 SQL 1200과 동형으로 교체.

**삭제**
- `/준비중/i` (bare)
- (선택) 중복·넓은 `/공사\s*(중지로|미착공|준비중|완료|준공).{0,40}(없|해당)/i` — SQL에 없으면 제거해 동형 유지. 10변형은 `작업 없음`·`해당…없`·`공사 준비중`으로 이미 커버.

**추가 (DEFECT 가드 블록 안)**
```ts
/공사\s*준비중/i
/준비중으로/i
/공사\s*중지/i
/중지\s*기간/i
/중지된\s*상태/i
```
기존 유지: `미착공`, `일시\s*중지`, `양생\s*중`, `시공\s*예정`, `준비단계`, `건축공사\s*완료`, `기존\s*수로\s*면처리\s*작업`, `작업\s*없음`, `관련\s*작업\s*없음`(작업 없음과 중복이면 생략 가능).

**early NULL 블록 (SQL 2번째 IF와 동형)**
```ts
/지적사항\s*별도\s*없음/i  // 또는 /지적\s*사항\s*별도\s*없음/
// 해당사항: SQL은 해당사항 없음 / 해당 사항 없음 / 해당 없 명시.
// 현재 TS /해당(\s*사항)?\s*없/ 는 의미상 동등에 가깝지만 SQL과 1:1로 맞추려면 분리 권장.
```

**EXCLUSION_COMPACT**
```ts
// SQL과 맞춤
'작업없음', '현장작업없음'
// '관련작업없음'은 정규식 작업 없음으로 커버되므로 유지해도 무방
```

**회귀 골든 (수정 후 필수)**
```
공사 중지 → NULL
공사중지 → NULL
중지 기간 중 현장 폐쇄 → NULL
중지된 상태 → NULL
설비 설치 준비중 → F19 (제외 아님)
자재 반입 준비중 → F11
비상발전기 준비중 → F13
안전시설 준비중 미설치 → F02
공사 준비중 → NULL
준비중으로 현장 휴무 → NULL
작업 없음 구간 난간 미설치 → F02
10변형 → NULL
상하작업 동시진행 → F20
동시 진행… → F19
이동형cctv 설치 → F19
```

SQL 쪽을 TS bare 준비중에 맞추는 것은 **비권장** (자재/전기 실질 지적 과잉 NULL).

## 7. 운영 절차 차단 (코드 외)

1. **미적용 DB**: 1200(또는 최신 1120 함수) 콘솔 적용 + 재백필 전, 앱이 category 컬럼 SELECT 하면 스키마/수치 불일치.
2. **TS 미수정 채 배포**: DB는 공사 중지를 NULL, 클라이언트 fallback/로컬 분류는 F19 — 이중 기준.
3. **수용 실측**: 적용 후 F19 잔여가 CCTV만인지, 10변형이 NULL인지 SELECT 검증 (1200 파일 하단 쿼리).

## 8. 결론

- 10변형·DEFECT 반례·F20·CCTV 핵심은 의도대로 동작한다.
- **blocker**: TS `준비중` 과잉제외 + `공사 중지/중지 기간/중지된 상태` 과소제외로 SQL과 7건 불일치.
- **수정**: TS를 SQL 1200 패턴에 정렬 (위 섹션 4). SQL을 TS에 맞추지 말 것.
- 수정·회귀 골든 통과 후 SQL 적용 → 재백필 → 앱 배포 순서 유지.
