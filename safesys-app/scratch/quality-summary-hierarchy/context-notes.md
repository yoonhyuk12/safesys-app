# 컨텍스트 노트

- FK는 `ON DELETE SET NULL` — 총괄표 삭제가 법정 서식인 실시대장 기록을 지우면 안 됨. docs/database.md의 CASCADE 규칙은 projects FK에 대한 것이라 무관.
- 기존 레코드 backfill 안 함. 어떤 총괄표에 속하는지 시스템이 추정할 수 없음 → "총괄표 미지정" 그룹으로 노출하고 수정 화면에서 사용자가 지정.
- `serial_no`는 프로젝트 전역 유지. 별지 42호 실시대장은 누적 문서이고 엑셀 출력도 전체 기록 기준.
- 수동 "자동집계" 버튼: 하위 기록이 있으면 하위 범위, 없으면 프로젝트 전체로 폴백 — 레거시 총괄표(연결 기록 0건) 워크플로를 깨지 않기 위함.
- 총괄표 열 때 하위 기록 0건이면 저장된 ④·⑤를 건드리지 않음 (레거시 보호).
- Supabase MCP가 docs/database.md엔 읽기 전용이라 적혀 있으나 apply_migration 도구가 존재 — 시도 후 실패하면 사용자에게 SQL 전달. (성공 시 docs 갱신 필요)
- 마이그레이션 먼저 적용해도 안전 — nullable 컬럼 추가는 배포 중인 기존 코드에 영향 없음. 코드 배포(main 푸시)는 마이그레이션 이후에만.
